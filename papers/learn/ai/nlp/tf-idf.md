TF-IDF는 한 문서에 자주 나오고 다른 문서에는 드문 단어에 큰 가중치를 주는 값입니다. 키워드 검색의 기본 점수이고, 지금도 RAG의 검색 층에서 만납니다.

에이전트를 만들 때 이런 곳에서 이 생각이 나옵니다.

- **BM25**: Elasticsearch와 OpenSearch 같은 검색 엔진의 기본 점수입니다. TF-IDF를 손본 것이라, 원리를 알면 점수가 왜 그렇게 나오는지 읽힙니다.
- **hybrid search**: 이 키워드 점수와 임베딩 점수를 합쳐 쓰는 구성이 RAG에서 흔합니다. → [고급 RAG](../rag/advanced-rag.md)
- **정확한 용어 찾기**: 제품명, 에러 코드, 사람 이름처럼 임베딩이 뭉개기 쉬운 드문 단어는 키워드 검색이 잘 찾습니다.

## 왜 필요한가

키워드 검색은 질문의 단어가 문서에 얼마나 나오는지로 순위를 매깁니다. [단어 주머니](./bag-of-words.md)의 횟수를 그대로 점수로 쓰면 흔한 말이 순위를 좌우합니다. 예를 들어 문서 1,000개 모두에 나오는 `서비스`와 20개에만 나오는 `환불`이 있고, 질문이 "서비스 환불"이라 합시다. 문서 A는 `서비스` 10번과 `환불` 1번, 문서 B는 `서비스` 3번과 `환불` 3번입니다. 횟수를 더하면 A가 11, B가 6이라 A가 앞서지만, 질문의 핵심은 `환불`이고 환불을 더 많이 말하는 쪽은 B입니다(장난감 수치입니다).

[불용어](./text-preprocessing.md) 목록으로 `서비스`를 지울 수도 있지만, 어떤 말이 흔한지는 코퍼스(검색할 문서 전체)마다 다르고 목록은 사람이 매번 정해야 합니다. TF-IDF는 이것을 계산으로 처리합니다. 문서 안의 횟수(tf)에, 그 단어가 몇 개 문서에 나오는지로 만든 가중치(idf)를 곱합니다. 위 예에서 `서비스`는 모든 문서에 있어 idf가 0이고, `환불`은 \(\ln(1000/20) \approx 3.91\)입니다. tf를 횟수 그대로 쓰면 점수는 A가 \(10 \times 0 + 1 \times 3.91 = 3.91\), B가 \(3 \times 0 + 3 \times 3.91 = 11.74\)로 순서가 뒤집혀 B가 앞섭니다. 식과 계산은 아래에 있습니다.

## 계산

[단어 주머니](./bag-of-words.md)의 횟수에 "이 단어가 몇 개 문서에 나오는가"를 반영합니다. 문서 세 개짜리 코퍼스(문서 모음)로 계산합니다.

```text
d1: 날씨 좋다      d2: 날씨 나쁘다      d3: 날씨 날씨 좋다
```

문서 수 \(N = 3\)이고, 단어가 들어 있는 문서 수(df)는 `날씨` 3, `좋다` 2, `나쁘다` 1입니다. tf는 그 문서 안의 횟수를 단어 수로 나눈 값입니다.

\[
\mathrm{tfidf} = \mathrm{tf} \times \ln \frac{N}{\mathrm{df}}
\]

뒤에 곱하는 \(\ln(N/\mathrm{df})\)가 idf입니다. 단어가 많은 문서에 나올수록 작아지고, 모든 문서에 나오면 0입니다. d1과 d2의 값을 구해 봅니다.

```text
단어      df   ln(N/df)   d1의 tf-idf       d2의 tf-idf
날씨      3    0          0                 0
좋다      2    0.405      0.5 x 0.405 = 0.203   -
나쁘다    1    1.099      -                 0.5 x 1.099 = 0.549
```

d1의 `좋다`는 두 단어 중 하나라 tf가 0.5이고, 3개 문서 중 2개에 있어 idf가 \(\ln(3/2) = 0.405\)입니다. 곱하면 0.203입니다. idf에 로그를 씌우는 이유는 차이를 누르기 위해서입니다. \(N/\mathrm{df}\)를 그대로 쓰면 문서 1,000개 중 1개에 나온 단어가 1,000을 받아서 점수를 혼자 가져갑니다. 로그를 쓰면 같은 단어가 약 6.9입니다.

모든 문서에 있는 `날씨`는 0이 되어 사라집니다. 한 문서에만 있는 `나쁘다`가 가장 크게 남습니다.

## 검색 점수로 쓰기

질문의 단어마다 문서의 TF-IDF를 구해 더하면 그 문서의 점수가 됩니다. 위 코퍼스에서 질문이 `좋다`이면 d1이 0.203, d2가 0, d3이 0.135입니다. d3에도 `좋다`가 한 번 있지만 문서에 단어가 셋이라 tf가 1/3로 낮아져서 d1 뒤에 놓입니다. 질문이 `좋다 나쁘다`이면 d1이 0.203, d2가 0.549, d3이 0.135라 d2가 1등입니다. 질문과 문서를 모두 TF-IDF 벡터로 만들어 [코사인 유사도](./cosine-similarity.md)로 견주는 방식도 있습니다. 실제 검색 엔진의 BM25는 여기에 문서 길이 보정을 더한 점수입니다.

## 기억할 것 세 가지

### 값이 크다고 중요한 단어는 아닙니다

TF-IDF는 드물면 큽니다. 오타가 문서 하나에만 있어도 idf가 가장 큽니다. 어느 단어가 레이블을 가르는지는 TF-IDF가 아니라, 그 위에서 가중치를 학습하는 모델이 정합니다.

### 문서가 늘면 값이 바뀝니다

\(N\)과 df는 코퍼스에서 정해집니다. 새 문서를 넣으면 기존 문서의 idf도 달라집니다. 학습 때의 \(N\)과 df를 저장해 두고 추론 때 같은 값을 써야 합니다. RAG에서 문서를 계속 추가하는 인덱스라면 재계산 시점을 정해 둬야 합니다.

### 도구마다 식이 다릅니다

위의 식은 교재 정의입니다. scikit-learn은 기본값으로 \(\ln\frac{1+N}{1+\mathrm{df}} + 1\)을 쓰고, tf는 원래 횟수이며, 결과 벡터의 길이를 1로 맞추는 정규화도 합니다. 같은 이름의 방법이어도 숫자가 다르고, 이 식에서는 모든 문서에 있는 단어도 0이 되지 않습니다. 손 계산과 도구 결과가 안 맞으면 이쪽을 먼저 봅니다.

한국어에서는 `TfidfVectorizer`의 기본 token 규칙이 글자 두 개 이상만 단어로 센다는 점도 조심합니다. 한 글자 token(`좋`, `는`)은 칸이 되지 못합니다. 직접 [토큰화](./tokenization.md)한 결과를 넣을 때는 규칙을 따로 지정합니다.

<summary>더 깊이: BM25와 변형, 직접 구현</summary>

- BM25는 TF-IDF에 두 가지를 더합니다. 같은 단어가 여러 번 나와도 점수가 무한정 오르지 않게 포화시키고, 긴 문서가 유리하지 않도록 문서 길이로 보정합니다.
- 로그의 밑은 모든 idf를 같은 배수로 바꿀 뿐입니다. 진짜 차이는 스무딩과 정규화에서 납니다.
- 손으로 계산한 값은 이 코드로 확인할 수 있습니다.

```python
import math

docs = {"d1": ["날씨", "좋다"], "d2": ["날씨", "나쁘다"], "d3": ["날씨", "날씨", "좋다"]}
N = len(docs)
vocab = ["날씨", "좋다", "나쁘다"]
idf = {v: math.log(N / sum(v in d for d in docs.values())) for v in vocab}
for k, d in docs.items():
    print(k, [round(d.count(v) / len(d) * idf[v], 3) for v in vocab])
```

```text
d1 [0.0, 0.203, 0.0]
d2 [0.0, 0.0, 0.549]
d3 [0.0, 0.135, 0.0]
```
