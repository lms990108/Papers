[단어 주머니](./bag-of-words.md)는 한 문장 안의 횟수입니다. 문서가 여러 개면, 모든 문서에 나오는 단어는 문서를 가르지 못합니다. `날씨`만 모은 글에서 `날씨`의 횟수는 크고, 긍정과 부정의 차이는 `좋다`와 `나쁘다`에 있습니다. 한 문서 안에서의 횟수는 키우고, 많은 문서에 나오는 단어는 깎는 가중치가 **TF-IDF**(term frequency–inverse document frequency)입니다.

:::tip[한눈에 보기]
TF-IDF는 단어 빈도(tf)에 역문서 빈도(idf)를 곱한 가중치입니다. 한 문서에 자주 나오고 다른 문서에는 드문 단어가 큽니다.

- tf는 한 문서 안의 횟수(또는 비율)이고, idf는 그 단어가 들어 있는 문서가 적을수록 커집니다.
- 모든 문서에 있는 단어는 idf가 작거나 0입니다. [불용어](./stopword.md) 목록을 사람이 정하는 대신 숫자로 깎는 셈입니다.
- 로그의 밑은 값을 일정한 배수로 바꿀 뿐입니다. 진짜 차이는 스무딩과 정규화 같은 변형에서 나옵니다. 책의 식과 scikit-learn의 식이 다릅니다.
- 결과는 [단어 주머니](./bag-of-words.md)처럼 단어 순서가 없는 목록입니다.

선수 지식은 [단어 주머니](./bag-of-words.md), [불용어](./stopword.md)입니다. 다음으로 보면 좋은 글은 목록 둘의 방향을 재는 [코사인 유사도](./cosine-similarity.md)입니다.
:::

## 정의

문서가 세 개 있습니다.

- d1: 날씨 좋다
- d2: 날씨 나쁘다
- d3: 날씨 날씨 좋다

한 문서 안 횟수를 그 문서의 단어 수로 나눈 값을 **단어 빈도**(term frequency, tf)라고 합니다. d1에서 `날씨`와 `좋다`는 각각 \(1/2 = 0.5\)입니다. d3에서 `날씨`는 \(2/3\)입니다.

**문서 빈도**(document frequency, df)는 그 단어가 들어 있는 문서 수입니다. `날씨`는 3, `좋다`는 2, `나쁘다`는 1입니다. 문서가 \(N = 3\)개일 때 **역문서 빈도**(inverse document frequency, idf)는 \(\log(N / \mathrm{df})\)입니다. 이 로그는 자연로그입니다.

\[
\mathrm{tfidf} = \mathrm{tf} \times \log \frac{N}{\mathrm{df}}
\]

기호를 풀어 읽으면 이렇습니다. \(\mathrm{tf}\)는 이 문서에서 이 단어의 횟수를 문서의 단어 수로 나눈 값입니다. \(N\)은 문서의 총 수이고 \(\mathrm{df}\)는 이 단어가 들어 있는 문서 수입니다. \(N/\mathrm{df}\)는 문서 몇 개당 하나꼴로 이 단어가 나오는가를 뜻하고, 드문 단어일수록 큽니다. 로그를 씌워 그 증가를 완만하게 합니다. 한 문서의 단어 하나의 가중치는 “이 문서에서 얼마나 자주” 곱하기 “전체에서 얼마나 드물게”입니다.

`날씨`는 \(\log(3/3) = 0\)이라, 횟수가 있어도 가중치가 0입니다. `좋다`의 역문서 빈도는 \(\log(3/2) \approx 0.405\)라 d1에서는 \(0.5 \times 0.405 \approx 0.203\)입니다. `나쁘다`는 \(\log(3) \approx 1.099\)라 d2에서는 \(0.5 \times 1.099 \approx 0.549\)입니다. 드물게 나온 나쁘다가 한 문서 안의 점수를 더 크게 움직입니다.

칸 순서를 오늘, 날씨, 좋다, 나쁘다로 두면 d1의 목록은 \([0,\ 0,\ 0.203,\ 0]\)입니다. 날씨 횟수는 0.5였는데 역문서 빈도가 0이라 칸이 0이 됩니다. d2는 \([0,\ 0,\ 0,\ 0.549]\)입니다. [단어 주머니](./bag-of-words.md)의 불만 점수는 날씨에 0.2를 곱했지만, 이 목록에서는 날씨 칸이 이미 0이라 그 0.2가 합에 들어가지 않습니다.

## 문서 예제

d3은 단어가 셋이고 `날씨`가 둘, `좋다`가 하나입니다. `날씨`의 tf는 \(2/3\)이지만 idf가 0이라 tf-idf도 0입니다. `좋다`의 tf는 \(1/3\)이고 idf는 d1과 같은 \(\log(3/2) \approx 0.405\)라, tf-idf는 \(0.135\)입니다. 칸 순서를 오늘, 날씨, 좋다, 나쁘다로 두면 d3은 \([0,\ 0,\ 0.135,\ 0]\)입니다.

d1은 \([0,\ 0,\ 0.203,\ 0]\)이라 0이 아닌 칸이 좋다뿐입니다. 두 목록의 [코사인](./cosine-similarity.md)은 1입니다. 횟수로 보면 d1은 \([0,\ 1,\ 1,\ 0]\), d3은 \([0,\ 2,\ 1,\ 0]\)이라 날씨 칸이 코사인을 1보다 작게 만듭니다. idf가 그 칸을 0으로 지운 뒤에야 두 문서가 같은 방향이 됩니다.

d2의 나쁘다 0.549는 d1의 좋다 0.203보다 큽니다. 문서 세 개 중 하나에만 나온 단어라서입니다. 로지스틱 회귀에 이 목록을 넣으면, 날씨 가중치가 얼마든 d1의 점수에는 날씨가 더해지지 않습니다. 횟수 목록이었다면 날씨는 1이라 그 가중치가 그대로 더해집니다.

## 파이썬으로 확인

위 정의를 그대로 옮깁니다. 칸은 날씨, 좋다, 나쁘다 셋입니다. `오늘`은 어느 문서에도 없어서 df가 0이고 \(N/\mathrm{df}\)를 계산할 수 없으므로 뺐습니다. 마지막 줄은 d1과 d3의 코사인입니다.

```python
import math

docs = {"d1": ["날씨", "좋다"], "d2": ["날씨", "나쁘다"], "d3": ["날씨", "날씨", "좋다"]}
N = len(docs)
vocab = ["날씨", "좋다", "나쁘다"]
df = {v: sum(v in d for d in docs.values()) for v in vocab}
idf = {v: math.log(N / df[v]) for v in vocab}          # 자연로그

def tfidf(toks):
    return [toks.count(v) / len(toks) * idf[v] for v in vocab]   # tf = 횟수 / 단어 수

print(df, {v: round(idf[v], 3) for v in vocab})
for k, d in docs.items():
    print(k, [round(x, 3) for x in tfidf(d)])

def cos(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))
print(round(cos(tfidf(docs["d1"]), tfidf(docs["d3"])), 3))
```

```text
{'날씨': 3, '좋다': 2, '나쁘다': 1} {'날씨': 0.0, '좋다': 0.405, '나쁘다': 1.099}
d1 [0.0, 0.203, 0.0]
d2 [0.0, 0.0, 0.549]
d3 [0.0, 0.135, 0.0]
1.0
```

0.203, 0.549, 0.135와 코사인 1이 본문 계산과 같습니다.

## 로그의 밑과 스무딩

TF-IDF에는 하나의 식이 없습니다. 책과 도구마다 조금씩 다릅니다. 가장 흔한 차이는 두 가지입니다. 하나는 로그의 밑입니다. 자연로그 대신 상용로그(밑 10)나 밑 2를 쓸 수 있습니다. 밑을 바꾸면 모든 idf가 같은 배수로 바뀝니다. 예를 들어 \(\log_{10}(3) = \ln(3) / \ln(10)\)이라 값이 \(1/\ln 10 \approx 0.434\)배가 됩니다. 단어끼리의 크기 비율은 그대로이고, 가중치 전체의 규모만 바뀝니다. 가중치를 학습하는 모델에서는 이 규모 차이를 흡수합니다.

다른 하나는 **스무딩**(smoothing)입니다. 식 \(\log(N/\mathrm{df})\)는 \(\mathrm{df} = 0\)이면 계산이 안 되고, \(\mathrm{df} = N\)이면 0이 되어 그 단어가 아예 사라집니다. 이를 다루는 변형이 있습니다. 분모에 1을 더한 \(\log(N/(1 + \mathrm{df}))\)를 쓰는 교재가 있는데, \(\mathrm{df} = N\)이면 \(\log(N/(N+1))\)이 음수가 됩니다. scikit-learn의 `TfidfTransformer`와 `TfidfVectorizer`는 기본 설정에서 다음 식을 씁니다.

\[
\mathrm{idf}(t) = \ln \frac{1 + N}{1 + \mathrm{df}(t)} + 1
\]

분자와 분모에 1을 더해 마치 모든 단어를 담은 문서가 하나 더 있는 것처럼 하고, 끝의 \(+1\)로 \(\mathrm{df} = N\)인 단어도 idf가 1이 되게 합니다. 스무딩을 끄면 \(\ln(N/\mathrm{df}) + 1\)입니다. 두 식 모두 자연로그입니다. 또 이 도구의 tf는 비율이 아니라 원래 횟수이고, 문서마다 결과 목록의 길이(L2 노름)가 1이 되게 나누는 정규화를 기본으로 합니다.

세 문서에서 이 식들을 각각 계산해 비교해 봅시다. 칸은 날씨(df 3), 좋다(df 2), 나쁘다(df 1)이고 \(N = 3\)입니다. 아래 코드는 위 설명 그대로 직접 구현한 것입니다. scikit-learn을 쓰지 않고 표준 라이브러리만 썼습니다.

```python
import math

N = 3
df = {"날씨": 3, "좋다": 2, "나쁘다": 1}
variants = {
    "ln(N/df)": lambda d: math.log(N / d),
    "log10(N/df)": lambda d: math.log10(N / d),
    "log2(N/df)": lambda d: math.log2(N / d),
    "ln(N/(1+df))": lambda d: math.log(N / (1 + d)),
    "sk smooth": lambda d: math.log((1 + N) / (1 + d)) + 1,
    "sk no-smooth": lambda d: math.log(N / d) + 1,
}
for name, f in variants.items():
    print(f"{name:13}", [round(f(df[v]), 3) for v in df])

idf = {v: variants["sk smooth"](df[v]) for v in df}      # 스무딩 idf
for k, d in {"d1": ["날씨", "좋다"], "d2": ["날씨", "나쁘다"], "d3": ["날씨", "날씨", "좋다"]}.items():
    x = [d.count(v) * idf[v] for v in df]                # tf는 원래 횟수
    n = math.sqrt(sum(c * c for c in x))
    print(k, [round(c / n, 3) for c in x])               # L2 정규화
```

```text
ln(N/df)      [0.0, 0.405, 1.099]
log10(N/df)   [0.0, 0.176, 0.477]
log2(N/df)    [0.0, 0.585, 1.585]
ln(N/(1+df))  [-0.288, 0.0, 0.405]
sk smooth     [1.0, 1.288, 1.693]
sk no-smooth  [1.0, 1.405, 2.099]
d1 [0.613, 0.79, 0.0]
d2 [0.509, 0.0, 0.861]
d3 [0.841, 0.541, 0.0]
```

밑이 다른 첫 세 줄은 비율이 같습니다. 나쁘다와 좋다의 idf 비는 자연로그로 \(1.099 / 0.405 \approx 2.71\)이고 밑 2로도 \(1.585 / 0.585 \approx 2.71\)입니다. 넷째 줄은 날씨가 \(-0.288\)로 음수고, 좋다가 정확히 0입니다. 스무딩한 다섯째 줄은 날씨도 1이라 사라지지 않고, 비율은 \(1.693 / 1.288 \approx 1.31\)로 크게 줄어 드문 단어의 가중치가 덜 부풀려집니다. 끝의 \(+1\)이 로그의 배수 관계를 깨기 때문입니다.

그 결과가 마지막 세 줄입니다. 이 방식에서 d1과 d3의 목록은 날씨 칸이 0으로 지워지지 않아서 \([0.613,\ 0.79,\ 0]\)과 \([0.841,\ 0.541,\ 0]\)입니다. 코사인은 \(0.613 \times 0.841 + 0.79 \times 0.541 \approx 0.94\)입니다. 정의대로 계산한 앞의 코사인 1과 다릅니다. 같은 이름의 방법이어도 식이 다르면 숫자가 다릅니다.

한국어에는 도구를 쓸 때 주의할 점이 하나 있습니다. `TfidfVectorizer`의 기본 토큰 규칙은 글자(문자와 숫자)가 두 개 이상 이어진 토큰만 단어로 셉니다. 한 글자 토큰, 예를 들어 [어간 추출](./stemming.md)로 남은 `좋`이나 조사 `는`은 이 기본 설정에서 칸이 되지 못합니다. 한국어에서 직접 [토큰화](./tokenization.md)한 결과를 넣으려면 토큰 규칙을 따로 지정해야 합니다.

## 헷갈리기 쉬운 점

**idf가 0이라고 쓸모없는 단어는 아닙니다.** 이 코퍼스에서 문서를 가르는 데 쓸모가 없다는 뜻입니다. `날씨`는 문서 세 개가 모두 날씨 이야기라 0이 됐을 뿐입니다. 다른 코퍼스에서는 같은 단어가 중요할 수 있습니다. idf는 문서 묶음의 성질이지 단어의 성질이 아닙니다.

**TF-IDF 값이 크다고 레이블을 가르는 단어는 아닙니다.** TF-IDF는 레이블을 보지 않습니다. 드물기만 하면 큽니다. 철자가 틀린 단어가 문서 하나에만 나오면 idf가 가장 커집니다. 레이블을 가르는 값은 가중치를 학습하는 모델이 만듭니다. TF-IDF는 입력 칸의 크기를 미리 손보는 일입니다.

**로그의 밑만 바꾸면 결과는 사실상 같습니다.** 밑만 바꾸면 모든 값이 같은 배수라서 단어끼리의 순서와 비율은 그대로입니다. 달라지는 것은 스무딩, 정규화, tf의 정의를 바꿀 때입니다. 도구 결과와 손 계산이 안 맞으면 이쪽을 먼저 봅니다.

**새 문서가 들어오면 idf도 바뀝니다.** \(N\)과 df가 코퍼스에서 정해지므로 문서가 늘면 idf도 바뀝니다. 학습 때의 \(N\), df를 저장해 두고 추론 때 같은 값을 써야 합니다.

## 연습 문제

1. 문서 4개짜리 코퍼스에서 `영화`가 문서 하나에만 있고, 그 문서는 단어 5개 중 `영화`가 2번입니다. 자연로그 \(\log(N/\mathrm{df})\) 식으로 이 문서의 `영화` tf-idf를 구해 보세요. \(\ln 4 \approx 1.386\)입니다.
2. 위 코퍼스(\(N = 4\))에서 scikit-learn 기본 식 \(\ln((1+N)/(1+\mathrm{df})) + 1\)로 \(\mathrm{df} = 4\)인 단어와 \(\mathrm{df} = 1\)인 단어의 idf를 구해 보세요.
3. 위 본문에서 `나쁘다`와 `좋다`의 idf 비가 자연로그와 밑 2에서 같은데, 스무딩한 scikit-learn 식에서는 왜 다른가요?

<details>
<summary>정답</summary>

1. \(\mathrm{tf} = 2/5 = 0.4\)이고 \(\mathrm{idf} = \ln(4/1) = \ln 4 \approx 1.386\)입니다. \(\mathrm{tfidf} = 0.4 \times 1.386 \approx 0.555\)입니다.
2. \(\mathrm{df} = 4\)이면 \(\ln(5/5) + 1 = 1\)입니다. \(\mathrm{df} = 1\)이면 \(\ln(5/2) + 1 \approx 0.916 + 1 = 1.916\)입니다. 모든 문서에 있는 단어도 idf가 0이 되지 않습니다.
3. 밑이 다른 로그끼리는 \(\log_2 x = \ln x / \ln 2\)처럼 상수 배라서 두 idf의 비가 같습니다. scikit-learn 식은 로그에 \(+1\)을 더하는데, 더하는 상수는 배수 관계를 깨기 때문에 비가 \(2.71\)에서 \(1.31\)로 바뀝니다.

</details>

## 정리

TF-IDF는 한 문서에서의 빈도에 코퍼스 전체에서의 희소성을 곱해서, 흔한 단어를 깎고 문서를 가르는 단어를 살립니다. 로그의 밑은 값 전체를 같은 배수로 바꿀 뿐이고, 스무딩과 정규화는 값을 실제로 바꿉니다. 책의 정의와 scikit-learn의 기본값은 식이 달라서 같은 문서도 숫자가 다릅니다. 만들어진 목록 둘이 얼마나 같은 방향인지는 [코사인 유사도](./cosine-similarity.md)로 잽니다. 순서를 조금 남기는 쪽은 [엔그램](./ngram.md)입니다.
