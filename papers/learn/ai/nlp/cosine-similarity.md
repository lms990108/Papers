리뷰 둘의 횟수 목록이 비슷하면, 레이블도 비슷할 가능성이 큽니다. 목록의 길이만 다르고 방향이 같으면, 칸마다의 차이 합은 커도 내용은 같습니다. “날씨 좋다”가 한 번인 목록과 같은 문장을 두 번 이어 횟수가 두 배인 목록은 방향이 같습니다. 그 방향을 재는 값이 **코사인 유사도**(cosine similarity)입니다.

:::tip[한눈에 보기]
코사인 유사도는 두 수 목록이 이루는 각의 코사인입니다. 곱의 합을 두 길이의 곱으로 나눈 값이라, 목록의 길이는 지우고 방향만 남깁니다.

- 같은 방향이면 1, 직각이면 0, 반대 방향이면 -1입니다.
- 횟수 목록처럼 칸이 0 이상이면 값은 0과 1 사이입니다.
- 길이로 나누기 때문에, 문장을 두 번 이어 붙여도 값이 변하지 않습니다.
- 곱만 쓰면 긴 목록이 이기고, 칸마다의 거리만 쓰면 방향이 같은 쌍도 멀게 나옵니다.

선수 지식은 [단어 주머니](./bag-of-words.md), [TF-IDF](./tf-idf.md)입니다. 다음으로 보면 좋은 글은 [엔그램](./ngram.md), [임베딩](./embedding.md), [워드투벡터](./word2vec.md)입니다.
:::

## 유클리드 거리의 한계

[단어 주머니](./bag-of-words.md)의 순서 오늘, 날씨, 좋다, 나쁘다를 씁니다. “날씨 좋다”는 \(a = [0,\ 1,\ 1,\ 0]\)입니다. 같은 문장을 두 번 이어 횟수가 두 배인 목록은 \(c = [0,\ 2,\ 2,\ 0]\)입니다. “날씨 나쁘다”는 \(b = [0,\ 1,\ 0,\ 1]\)입니다.

칸마다의 차이로 거리를 재 봅시다. \(a - c = [0,\ -1,\ -1,\ 0]\)이고 제곱의 합은 2라서 거리는 \(\sqrt{2}\)입니다. \(a - b = [0,\ 0,\ 1,\ -1]\)도 제곱의 합이 2라 거리가 \(\sqrt{2}\)입니다. 내용이 같은 쌍과 좋다와 나쁘다가 갈린 쌍이 같은 거리입니다. 거리는 길이의 차이에 끌려가서, 두 배로 늘린 같은 문장을 다른 문장만큼 멀다고 봅니다. 길이를 지우고 방향만 봐야 합니다.

## 정의

두 목록 \(x\), \(y\)의 칸을 \(x_i\), \(y_i\)라고 합시다. 칸마다 곱해 더한 값이 곱의 합입니다. 목록 자신과의 곱의 합에 제곱근을 씌운 값이 길이입니다.

\[
x \cdot y = \sum_i x_i y_i, \qquad \|x\| = \sqrt{x \cdot x}
\]

코사인 유사도는 곱의 합을 두 길이의 곱으로 나눈 것입니다.

\[
\cos(x, y) = \frac{x \cdot y}{\|x\| \, \|y\|}
\]

말로 읽으면, 두 목록을 각각 길이 1로 줄인 뒤 곱해 더한 값입니다. 길이 1짜리 두 화살표가 이루는 각이 \(\theta\)이면 이 값은 \(\cos\theta\)입니다. 각이 0이면 1이고, 직각이면 0이고, 반대 방향이면 -1입니다. 이름이 코사인인 이유가 이것입니다.

## 계산 예

\(a\)와 \(c\)부터 해 봅시다. 곱은 칸마다 \(0 \times 0,\ 1 \times 2,\ 1 \times 2,\ 0 \times 0\)이고 합은 \(4\)입니다. \(\|a\| = \sqrt{0+1+1+0} = \sqrt{2}\)이고 \(\|c\| = \sqrt{0+4+4+0} = \sqrt{8} = 2\sqrt{2}\)라, 두 길이의 곱은 \(\sqrt{2} \times 2\sqrt{2} = 4\)입니다. 코사인은 \(4 / 4 = 1\)입니다. 칸마다의 차이는 1씩인데 방향은 같습니다.

내용이 다르면 1보다 작아집니다. \(a\)와 \(b\)의 곱의 합은 \(0+1+0+0 = 1\)이고, 길이는 둘 다 \(\sqrt{2}\)입니다.

\[
\cos(a, b) = \frac{a \cdot b}{\|a\| \|b\|} = \frac{1}{\sqrt{2} \times \sqrt{2}} = \frac{1}{2} = 0.5
\]

같은 목록끼리는 1입니다. 곱이 0인 목록끼리는 0입니다. 방향이 반대면 -1까지 내려갑니다. 횟수 목록은 칸이 0 이상이라 이 예에서는 음수가 나오지 않습니다. 코사인이 0.5면 사이각은 \(60^\circ\)입니다.

## 다른 예제

[TF-IDF](./tf-idf.md)의 문서 셋을 횟수 목록으로 씁시다. d1은 “날씨 좋다”라 \([0,\ 1,\ 1,\ 0]\), d2는 “날씨 나쁘다”라 \([0,\ 1,\ 0,\ 1]\), d3은 “날씨 날씨 좋다”라 \([0,\ 2,\ 1,\ 0]\)입니다. 새 리뷰 q가 “날씨 좋다 좋다”라서 \([0,\ 1,\ 2,\ 0]\)이라고 합시다. q와 가장 가까운 문서는 무엇일까요?

| 문서 | q와의 곱의 합 | 길이의 곱 | 코사인 |
| --- | --- | --- | --- |
| d1 | \(1 + 2 = 3\) | \(\sqrt{5} \times \sqrt{2}\) | 0.949 |
| d2 | \(1\) | \(\sqrt{5} \times \sqrt{2}\) | 0.316 |
| d3 | \(2 + 2 = 4\) | \(\sqrt{5} \times \sqrt{5} = 5\) | 0.8 |

d1이 가장 가깝습니다. q는 좋다가 두 번이라 d3처럼 날씨가 두 번인 문서보다, 날씨와 좋다가 한 번씩인 d1이 비율 면에서 더 닮았습니다. 곱의 합만 보면 d3의 4가 가장 큽니다. d3의 길이가 길기 때문입니다.

## 파이썬으로 확인

```python
import math

def dot(x, y): return sum(p * q for p, q in zip(x, y))
def norm(x): return math.sqrt(dot(x, x))
def cos(x, y): return dot(x, y) / (norm(x) * norm(y))
def dist(x, y): return math.sqrt(sum((p - q) ** 2 for p, q in zip(x, y)))

# 칸 순서: 오늘, 날씨, 좋다, 나쁘다
a = [0, 1, 1, 0]   # 날씨 좋다
b = [0, 1, 0, 1]   # 날씨 나쁘다
c = [0, 2, 2, 0]   # 날씨 좋다 날씨 좋다
print("cos(a,c) =", round(cos(a, c), 3), " 거리 =", round(dist(a, c), 3))
print("cos(a,b) =", round(cos(a, b), 3), " 거리 =", round(dist(a, b), 3))
print("사이각(도) =", round(math.degrees(math.acos(cos(a, b))), 1))

d1, d2, d3 = [0, 1, 1, 0], [0, 1, 0, 1], [0, 2, 1, 0]
q = [0, 1, 2, 0]   # 날씨 좋다 좋다
for name, d in [("d1", d1), ("d2", d2), ("d3", d3)]:
    print(name, round(cos(q, d), 3))
```

```text
cos(a,c) = 1.0  거리 = 1.414
cos(a,b) = 0.5  거리 = 1.414
사이각(도) = 60.0
d1 0.949
d2 0.316
d3 0.8
```

거리는 두 쌍이 같은 1.414이고 코사인은 1과 0.5로 갈립니다.

## 쓰이는 곳

문서가 많으면 새 리뷰와 코사인이 가장 큰 학습 리뷰의 레이블을 그대로 쓰기도 합니다. 이 방법은 가중치를 학습하지 않습니다. TF-IDF로 칸을 바꾼 뒤 같은 식을 쓰면, 모든 문서에 있는 단어가 유사도를 덜 끌어갑니다. d1과 d3을 TF-IDF 목록으로 바꾸면 \([0,\ 0,\ 0.203,\ 0]\)과 \([0,\ 0,\ 0.135,\ 0]\)이라 코사인이 1입니다. 횟수 목록에서는 0.949였습니다. 날씨 칸이 지워지자 두 문서가 같은 방향이 됩니다. d1과 d2는 횟수 목록에서 0.5였다가 TF-IDF 목록에서 0이 됩니다. 둘이 공유하던 칸이 날씨뿐이었기 때문입니다.

임베딩 목록 사이의 가깝기도 이 식으로 잽니다. [워드투벡터](./word2vec.md)는 같이 나온 단어의 두 목록의 곱이 커지도록 목록을 움직이고, 학습이 끝난 목록을 서로 비교할 때는 코사인을 많이 씁니다. 곱을 키우는 학습과 길이를 지운 비교는 다른 일입니다.

## 내적과 길이

같은 방향인 \(a = [0,\ 1,\ 1,\ 0]\)과 \(c = [0,\ 2,\ 2,\ 0]\)의 곱은 4입니다. \(a\)와 \(a\)의 곱은 2입니다. 곱만 비교하면 두 배짜리 문장이 원문보다 자기 자신에 더 가깝습니다. 길이로 나누면 둘 다 1이라, 그 끌림이 사라집니다.

겹치는 칸이 없으면 곱이 0입니다. 오늘만 있는 \([1,\ 0,\ 0,\ 0]\)과 날씨만 있는 \([0,\ 1,\ 0,\ 0]\)의 코사인은 0입니다. 0.5는 그 0과, 같은 문장의 1 사이에 있습니다. “날씨 좋다”와 “날씨 나쁘다”는 날씨 칸 하나만 공유해서 1의 절반입니다.

코사인이 1이어도 레이블이 같다는 보장은 없습니다. 횟수가 같은 두 문장에 사람이 긍정과 부정을 다르게 붙일 수 있습니다. 그때는 가장 가까운 리뷰의 레이블을 베끼는 방법이 그 쌍에서 틀립니다. 빈칸을 학습하는 [로지스틱 회귀](../machine-learning/logistic-regression.md)는 그 두 레이블을 손실로 보고 가중치를 밉니다.

## 정규화와 코사인

두 목록을 먼저 길이 1로 줄이면 분모가 1이라, 곱의 합이 그대로 코사인입니다. \([1,\ 1]\)과 \([1,\ 0]\)을 봅시다. 길이 1로 줄이면 \([0.707,\ 0.707]\)과 \([1,\ 0]\)이고 곱은 0.707입니다. 원래 목록으로 코사인을 계산해도 \(1 / (\sqrt{2} \times 1) = 0.707\)입니다. 그래서 목록을 미리 길이 1로 정규화해 두고 곱만 계산하는 방식이 많습니다. 비교할 쌍이 많을 때 나눗셈과 제곱근을 매번 하지 않아도 됩니다.

[워드투벡터](./word2vec.md)의 예에서 날씨를 \([1,\ 0]\), 좋다를 \([0.8,\ 0.6]\)으로 두었습니다. 좋다의 길이는 \(\sqrt{0.64 + 0.36} = 1\)이라 곱 0.8이 곧 코사인입니다. 좋다 목록을 세 배로 키워 \([2.4,\ 1.8]\)로 만들면 곱은 2.4가 되지만 코사인은 0.8로 그대로입니다.

```python
import math
def dot(x, y): return sum(p * q for p, q in zip(x, y))
def norm(x): return math.sqrt(dot(x, x))
def cos(x, y): return dot(x, y) / (norm(x) * norm(y))

날씨 = [1, 0]
for 이름, v in [("좋다", [0.8, 0.6]), ("좋다x3", [2.4, 1.8]), ("자동차", [0, 1]), ("반대", [-1, 0])]:
    print(이름, "곱", round(dot(날씨, v), 2), "코사인", round(cos(날씨, v), 2))
```

```text
좋다 곱 0.8 코사인 0.8
좋다x3 곱 2.4 코사인 0.8
자동차 곱 0 코사인 0.0
반대 곱 -1 코사인 -1.0
```

## 헷갈리기 쉬운 점

**코사인이 크다고 뜻이 같은 것은 아닙니다.** 같은 칸을 쓴 정도만 잽니다. 단어 주머니에서 “날씨 좋다”와 “날씨 나쁘다”는 날씨 칸을 공유해서 0.5이고, 뜻이 반대라는 사실은 목록에 없습니다. 좋다와 나쁘다가 다른 칸인 한 둘 사이의 곱은 0입니다.

**코사인은 음수가 될 수 있습니다.** 이 페이지의 예에서는 음수가 나오지 않았지만, 식은 -1까지 갈 수 있습니다. 횟수나 TF-IDF 목록은 칸이 0 이상이라 곱의 합이 음수가 될 수 없을 뿐입니다. 학습된 임베딩 목록은 칸에 음수가 들어가므로 코사인도 음수가 됩니다.

**코사인은 확률이 아닙니다.** 0과 1 사이의 값을 확률로 읽기 쉽지만, 0.5는 사이각이 \(60^\circ\)라는 뜻입니다. 합이 1이 되도록 맞춘 값이 아닙니다.

**영벡터는 코사인이 정의되지 않습니다.** 길이가 0이기 때문입니다. 단어가 하나도 없는 문서를 횟수 목록으로 만들면 \([0,\ 0,\ 0,\ 0]\)이고, 나눗셈에서 0으로 나누게 됩니다. 비교하기 전에 이런 문서를 걸러 내거나, 유사도를 0으로 두는 규칙을 정해야 합니다. [임베딩](./embedding.md)의 예 표에서 나쁘다의 행이 \([0,\ 0]\)인 것도 곱이 보이게 둔 값이라서 그렇고, 이 행으로는 코사인을 계산할 수 없습니다.

**코사인이 1이어도 같은 문서는 아닙니다.** 방향만 같습니다. “날씨 좋다”와 같은 문장을 두 번 이은 문서는 코사인이 1이어도 길이가 다릅니다.

## 변형

**코사인 거리**는 \(1 - \cos(x, y)\)로 둡니다. 같은 방향이면 0이고, 직각이면 1이고, 반대면 2입니다. 거리를 쓰는 도구에 넣을 때 유사도를 거리로 뒤집은 것입니다. 이 값은 엄밀한 의미의 거리 공리(삼각부등식)를 모두 만족하지는 않으므로, 순서를 매기는 용도로 쓰는 편이 안전합니다.

길이를 지우기 싫을 때는 곱의 합을 그대로 씁니다. 단어 목록의 길이가 빈도나 중요도를 나타낼 때가 그 경우입니다. 어느 쪽을 쓸지는 길이에 뜻이 있는지로 정합니다. 문서 길이가 단순히 글이 길어서 생긴 차이라면 코사인이 맞고, 길이가 신호라면 곱의 합이 맞습니다.

## 연습 문제

1. \(x = [1,\ 2,\ 0,\ 0]\)과 \(y = [2,\ 1,\ 0,\ 0]\)의 코사인을 구해 보세요.
2. “날씨 날씨 나쁘다” \([0,\ 2,\ 0,\ 1]\)과 가장 가까운 문서를 d1, d2, d3 중에서 골라 보세요. 횟수 목록 기준입니다.
3. \(a = [0,\ 1,\ 1,\ 0]\)을 세 번 이은 목록 \(3a\)와 \(b = [0,\ 1,\ 0,\ 1]\)의 코사인은 \(a\)와 \(b\)의 코사인과 같은가요?

<details>
<summary>정답</summary>

1. 곱의 합은 \(2 + 2 = 4\)이고 두 길이는 모두 \(\sqrt{5}\)입니다. \(4 / 5 = 0.8\)입니다.
2. d1은 곱이 2, 길이의 곱이 \(\sqrt{10}\)이라 0.632입니다. d2는 곱이 \(2 + 1 = 3\)이라 \(3/\sqrt{10} = 0.949\)입니다. d3은 곱이 4, 길이의 곱이 5라 0.8입니다. 답은 d2입니다.
3. 같습니다. \(3a = [0,\ 3,\ 3,\ 0]\)과 \(b\)의 곱은 3이고, \(\|3a\| = 3\sqrt{2}\)이므로 \(3 / (3\sqrt{2} \times \sqrt{2}) = 0.5\)입니다. 목록을 몇 배로 키워도 코사인은 변하지 않습니다.

</details>

## 정리

코사인 유사도는 곱의 합을 두 길이로 나눈, 방향의 닮음입니다. 같은 문장을 두 번 이은 목록과는 1이고, 같은 칸을 절반만 공유하면 0.5이며, 겹치는 칸이 없으면 0입니다. 칸마다의 거리와 곱의 합은 길이에 끌려서 이 일에 맞지 않습니다. TF-IDF로 칸을 바꾸면 모든 문서에 있는 단어가 빠지고, 임베딩에서는 목록 사이의 가깝기를 잴 때 씁니다. 횟수를 세어 다음 단어를 정하는 방법은 [엔그램](./ngram.md)에서 이어집니다.
