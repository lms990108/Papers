두 문장이 얼마나 닮았는지 숫자 하나로 말하고 싶습니다. 문장을 수 목록으로 바꾸면 그 목록을 화살표로 그릴 수 있습니다. 그러면 “닮았다”를 “같은 방향을 가리킨다”로 바꿔 말할 수 있고, 방향의 닮음을 재는 값이 **코사인 유사도**(cosine similarity)입니다.

그림에 나오는 기호를 먼저 읽어 둡니다.

- \(a\)와 \(b\)는 수 목록 둘을 원점에서 뻗은 화살표로 그린 것입니다. 끝의 동그라미를 끌면 목록이 바뀝니다.
- 길이는 화살표의 길이이고, 사이각은 두 화살표가 벌어진 각입니다.
- 내적 \(a \cdot b\)는 두 목록의 칸마다 곱해 더한 값입니다.
- 거리 \(|a - b|\)는 두 화살표 끝 사이의 직선 거리입니다.
- 코사인은 내적을 두 길이의 곱으로 나눈 값입니다. 같은 방향이면 1입니다.

<CosineExplorer />

:::tip[한눈에 보기]
코사인 유사도는 두 수 목록이 이루는 각의 코사인입니다. 곱의 합을 두 길이의 곱으로 나눈 값이라, 길이는 지우고 방향만 남깁니다.

- 같은 방향이면 1, 직각이면 0, 반대 방향이면 -1입니다.
- 횟수 목록처럼 칸이 0 이상이면 값은 0과 1 사이입니다.
- 길이로 나누기 때문에 문장을 두 번 이어 붙여도 값이 변하지 않습니다.
- 곱만 쓰면 긴 목록이 이기고, 칸마다의 거리만 쓰면 방향이 같은 쌍도 멀게 나옵니다.

선수 지식은 [단어 주머니](./bag-of-words.md), [TF-IDF](./tf-idf.md)입니다. 다음으로 보면 좋은 글은 [엔그램](./ngram.md), [임베딩](./embedding.md), [워드투벡터](./word2vec.md)입니다.
:::

## 1. 거리로 재면 왜 안 되나

[단어 주머니](./bag-of-words.md)의 칸 순서는 오늘, 날씨, 좋다, 나쁘다입니다. “날씨 좋다”는 \(a = [0,\ 1,\ 1,\ 0]\)입니다. 같은 문장을 두 번 이으면 \([0,\ 2,\ 2,\ 0]\)이 됩니다. 내용은 같고 목록의 길이만 두 배입니다. “날씨 나쁘다”는 \(b = [0,\ 1,\ 0,\ 1]\)로, 내용이 다릅니다.

이어 붙인 횟수를 바꿔 가며 거리와 코사인을 비교해 보세요.

<LengthVsDirection />

횟수가 2일 때 두 거리가 모두 \(\sqrt{2}\)입니다. 내용이 같은 쌍과 좋다·나쁘다가 갈린 쌍이 같은 거리입니다. 거리는 길이의 차이에 끌려갑니다. 길이는 지우고 방향만 봐야 합니다.

## 2. 정의

두 목록 \(x\), \(y\)의 칸을 \(x_i\), \(y_i\)라고 합시다. 칸마다 곱해 더한 값이 **내적**(dot product)입니다. 자기 자신과의 내적에 제곱근을 씌운 값이 길이입니다.

\[
x \cdot y = \sum_i x_i y_i, \qquad \|x\| = \sqrt{x \cdot x}
\]

코사인 유사도는 내적을 두 길이의 곱으로 나눈 값입니다.

\[
\cos(x, y) = \frac{x \cdot y}{\|x\| \, \|y\|}
\]

말로 읽으면, 두 목록을 각각 길이 1로 줄인 뒤 곱해서 더한 값입니다. 길이 1짜리 두 화살표 사이의 각이 \(\theta\)이면 이 값은 \(\cos\theta\)입니다. 이름이 코사인인 이유입니다.

| 두 화살표의 방향 | 사이각 | 코사인 |
| --- | --- | --- |
| 같음 | \(0^\circ\) | 1 |
| 직각 | \(90^\circ\) | 0 |
| 반대 | \(180^\circ\) | -1 |

맨 위 그림에서 “길이 1로 줄여 보기”를 켜면, 줄인 두 화살표의 내적이 코사인과 같은 값인 것을 직접 볼 수 있습니다.

## 3. 계산해 보기

\(a = [0,\ 1,\ 1,\ 0]\)과 \(c = [0,\ 2,\ 2,\ 0]\)부터 계산해 봅시다. 내적은 \(0 \times 0 + 1 \times 2 + 1 \times 2 + 0 \times 0 = 4\)입니다. 길이는 \(\|a\| = \sqrt{2}\), \(\|c\| = 2\sqrt{2}\)라서 곱이 4입니다. 코사인은 \(4 / 4 = 1\)입니다. 칸마다의 차이는 1씩인데 방향은 같습니다.

내용이 다르면 1보다 작아집니다. \(a\)와 \(b\)의 내적은 1이고 길이는 둘 다 \(\sqrt{2}\)입니다.

\[
\cos(a, b) = \frac{1}{\sqrt{2} \times \sqrt{2}} = \frac{1}{2} = 0.5
\]

코사인이 0.5이면 사이각은 \(60^\circ\)입니다.

이제 새 리뷰 q와 가장 닮은 문서를 찾아 봅시다. d1은 “날씨 좋다”, d2는 “날씨 나쁘다”, d3은 “날씨 날씨 좋다”입니다. q의 횟수를 바꿔 보세요.

<BagCosineTable />

기본값인 q = “날씨 좋다 좋다”(\([0,\ 1,\ 2,\ 0]\))에서 내적은 d3을 고르고 코사인은 d1을 고릅니다. d3은 길이가 길어서 내적이 큽니다. q는 날씨와 좋다의 비율이 d1과 더 닮았습니다.

## 4. 정규화와 코사인

두 목록을 먼저 길이 1로 줄이면(**정규화**) 분모가 1이라서 내적이 그대로 코사인입니다. \([1,\ 1]\)과 \([1,\ 0]\)을 봅시다. 길이 1로 줄이면 \([0.707,\ 0.707]\)과 \([1,\ 0]\)이고 내적은 0.707입니다. 원래 목록으로 계산해도 \(1 / (\sqrt{2} \times 1) = 0.707\)로 같습니다.

그래서 목록을 미리 길이 1로 정규화해 두고 내적만 계산하는 방식이 많습니다. 비교할 쌍이 많을 때 나눗셈과 제곱근을 매번 하지 않아도 됩니다.

[워드투벡터](./word2vec.md)의 예에서 날씨는 \([1,\ 0]\), 좋다는 \([0.8,\ 0.6]\)입니다. 좋다의 길이는 1이라 내적 0.8이 곧 코사인입니다. 좋다를 세 배로 키워 \([2.4,\ 1.8]\)로 만들면 내적은 2.4가 되지만 코사인은 0.8로 그대로입니다.

## 5. 쓰이는 곳

문서가 많을 때 새 리뷰와 코사인이 가장 큰 학습 리뷰의 레이블을 그대로 쓰기도 합니다. 이 방법은 가중치를 학습하지 않습니다.

TF-IDF로 칸을 바꾼 뒤 같은 식을 쓰면, 모든 문서에 있는 단어가 유사도를 덜 끌어갑니다. d1과 d3을 TF-IDF 목록으로 바꾸면([TF-IDF](./tf-idf.md)의 계산) \([0,\ 0,\ 0.203,\ 0]\)과 \([0,\ 0,\ 0.135,\ 0]\)이라 코사인이 1입니다. 횟수 목록에서는 0.949였습니다. 날씨 칸이 지워지자 두 문서가 같은 방향이 됩니다. d1과 d2는 0.5에서 0이 됩니다. 둘이 공유하던 칸이 날씨뿐이었기 때문입니다.

임베딩 목록 사이의 가깝기도 이 식으로 잽니다. [워드투벡터](./word2vec.md)는 같이 나온 단어의 두 목록의 곱이 커지도록 목록을 움직이고, 학습이 끝난 목록을 서로 비교할 때는 코사인을 많이 씁니다. 곱을 키우는 학습과 길이를 지운 비교는 다른 일입니다. RAG의 [검색](../rag/retrieval.md)도 이 값으로 질문과 가까운 청크를 고릅니다.

## 6. 헷갈리기 쉬운 점

**코사인이 크다고 뜻이 같은 것은 아닙니다.** 같은 칸을 쓴 정도만 잽니다. “날씨 좋다”와 “날씨 나쁘다”는 날씨 칸을 공유해서 0.5이고, 뜻이 반대라는 사실은 목록에 없습니다.

**코사인이 1이어도 레이블이 같다는 보장은 없습니다.** 횟수가 같은 두 문장에 사람이 긍정과 부정을 다르게 붙일 수 있습니다. 그때는 가장 가까운 리뷰의 레이블을 베끼는 방법이 그 쌍에서 틀립니다. 가중치를 학습하는 [로지스틱 회귀](../machine-learning/logistic-regression.md)는 그 두 레이블을 정답으로 삼아 오차를 계산하고 가중치를 고칩니다.

**코사인은 음수가 될 수 있습니다.** 횟수나 TF-IDF 목록은 칸이 0 이상이라 음수가 나오지 않을 뿐입니다. 학습된 임베딩 목록은 칸에 음수가 들어가므로 코사인도 -1까지 내려갑니다.

**코사인은 확률이 아닙니다.** 0.5는 사이각이 \(60^\circ\)라는 뜻입니다. 합이 1이 되도록 맞춘 값이 아닙니다.

**길이가 0인 목록은 코사인이 정의되지 않습니다.** 0으로 나누게 됩니다. 단어가 하나도 없는 문서가 그렇습니다. 비교하기 전에 걸러 내거나 유사도를 0으로 두는 규칙을 정해야 합니다. 맨 위 그림에서 한 화살표를 원점으로 끌어 보면 확인할 수 있습니다.

**코사인이 1이어도 같은 문서는 아닙니다.** 방향만 같습니다. “날씨 좋다”와 같은 문장을 두 번 이은 문서는 길이가 다릅니다.

## 7. 변형

**코사인 거리**는 \(1 - \cos(x, y)\)입니다. 같은 방향이면 0, 직각이면 1, 반대면 2입니다. 거리를 쓰는 도구에 유사도를 넣을 때 뒤집은 값입니다. 거리가 지켜야 할 규칙 하나인 삼각부등식(다른 점을 거쳐 가는 길이 직접 가는 길보다 짧지 않다는 것)을 모두 만족하지는 않아서, 순서를 매기는 용도로 쓰는 편이 안전합니다.

길이를 지우기 싫을 때는 내적을 그대로 씁니다. 길이가 빈도나 중요도를 뜻할 때가 그렇습니다. 문서 길이가 글이 길어서 생긴 차이라면 코사인이 맞고, 길이가 신호라면 내적이 맞습니다.

<details>
<summary>파이썬으로 확인</summary>

```python
import math

def dot(x, y): return sum(p * q for p, q in zip(x, y))
def norm(x): return math.sqrt(dot(x, x))
def cos(x, y): return dot(x, y) / (norm(x) * norm(y))
def dist(x, y): return math.sqrt(sum((p - q) ** 2 for p, q in zip(x, y)))

# 칸 순서: 오늘, 날씨, 좋다, 나쁘다
a = [0, 1, 1, 0]   # 날씨 좋다
b = [0, 1, 0, 1]   # 날씨 나쁘다
c = [0, 2, 2, 0]   # 날씨 좋다 날씨 좋다
print("cos(a,c) =", round(cos(a, c), 3), " 거리 =", round(dist(a, c), 3))
print("cos(a,b) =", round(cos(a, b), 3), " 거리 =", round(dist(a, b), 3))
print("사이각(도) =", round(math.degrees(math.acos(cos(a, b))), 1))

d1, d2, d3 = [0, 1, 1, 0], [0, 1, 0, 1], [0, 2, 1, 0]
q = [0, 1, 2, 0]   # 날씨 좋다 좋다
for name, d in [("d1", d1), ("d2", d2), ("d3", d3)]:
    print(name, round(cos(q, d), 3))
```

```text
cos(a,c) = 1.0  거리 = 1.414
cos(a,b) = 0.5  거리 = 1.414
사이각(도) = 60.0
d1 0.949
d2 0.316
d3 0.8
```

```python
날씨 = [1, 0]
for 이름, v in [("좋다", [0.8, 0.6]), ("좋다x3", [2.4, 1.8]), ("자동차", [0, 1]), ("반대", [-1, 0])]:
    print(이름, "곱", round(dot(날씨, v), 2), "코사인", round(cos(날씨, v), 2))
```

```text
좋다 곱 0.8 코사인 0.8
좋다x3 곱 2.4 코사인 0.8
자동차 곱 0 코사인 0.0
반대 곱 -1 코사인 -1.0
```

</details>

## 연습 문제

1. \(x = [1,\ 2,\ 0,\ 0]\)과 \(y = [2,\ 1,\ 0,\ 0]\)의 코사인을 구해 보세요.
2. “날씨 날씨 나쁘다” \([0,\ 2,\ 0,\ 1]\)과 가장 가까운 문서를 d1, d2, d3 중에서 골라 보세요. 횟수 목록 기준입니다. (위 표에서 직접 확인할 수 있습니다.)
3. \(a = [0,\ 1,\ 1,\ 0]\)을 세 번 이은 목록 \(3a\)와 \(b = [0,\ 1,\ 0,\ 1]\)의 코사인은 \(a\)와 \(b\)의 코사인과 같은가요?

<details>
<summary>정답</summary>

1. 내적은 \(2 + 2 = 4\)이고 두 길이는 모두 \(\sqrt{5}\)입니다. \(4 / 5 = 0.8\)입니다.
2. d1은 내적이 2, 길이의 곱이 \(\sqrt{10}\)이라 0.632입니다. d2는 내적이 \(2 + 1 = 3\)이라 \(3/\sqrt{10} = 0.949\)입니다. d3은 내적이 4, 길이의 곱이 5라 0.8입니다. 답은 d2입니다.
3. 같습니다. \(3a = [0,\ 3,\ 3,\ 0]\)과 \(b\)의 내적은 3이고, \(\|3a\| = 3\sqrt{2}\)이므로 \(3 / (3\sqrt{2} \times \sqrt{2}) = 0.5\)입니다. 목록을 몇 배로 키워도 코사인은 변하지 않습니다.

</details>

## 정리

코사인 유사도는 내적을 두 길이로 나눈, 방향의 닮음입니다. 같은 문장을 두 번 이은 목록과는 1이고, 같은 칸을 절반만 공유하면 0.5이며, 겹치는 칸이 없으면 0입니다. 칸마다의 거리와 내적은 길이에 끌려서 이 일에 맞지 않습니다. TF-IDF로 칸을 바꾸면 모든 문서에 있는 단어가 빠지고, 임베딩에서는 목록 사이의 가깝기를 잴 때 씁니다. 횟수를 세어 다음 단어를 정하는 방법은 [엔그램](./ngram.md)에서 이어집니다.
