개체명 인식(named entity recognition, NER)은 글에서 사람, 장소, 기관, 날짜처럼 이름이 가리키는 구간을 찾아 종류를 붙이는 일입니다.

에이전트가 글에서 필요한 값을 뽑는 곳마다 이 일이 들어 있습니다.

- **개인정보 마스킹**: prompt를 외부 API로 보내기 전에 이름, 주소, 전화번호를 찾아 가립니다.
- **슬롯 채우기**: 예약 에이전트가 사용자 말에서 날짜, 장소, 사람 이름을 뽑습니다.
- **RAG 메타데이터와 그래프**: 청크에서 개체를 뽑아 필터 조건이나 지식 그래프의 노드로 씁니다. → [그래프 RAG](../rag/graph-rag.md), [지식 그래프](../rag/knowledge-graph.md)
- **평가**: 위 추출이 잘 되는지 잴 때 이 페이지의 개체 단위 F1을 씁니다.

요즘은 전용 모델을 학습하기보다 LLM에 JSON 같은 구조화된 출력으로 뽑게 하는 일이 많습니다. 어느 쪽이든 평가 방식과 실패 패턴은 같습니다.

## 표지 달기: BIO

고전적인 방식은 token마다 표지를 하나씩 붙이는 분류입니다. 이름의 시작은 B, 이름의 속은 I, 이름이 아닌 칸은 O이고, 종류는 B와 I 뒤에 붙입니다. 장소는 LOC, 사람은 PER, 기관은 ORG입니다.

| token | 표지 |
| --- | --- |
| 서울 | B-LOC |
| 특별시 | I-LOC |
| 날씨 | O |
| 좋다 | O |

"서울 특별시"가 장소 하나입니다. O 바로 뒤에 I가 오는 것처럼 시작이 없는 속은 규칙에 어긋난 표지 열입니다. 표지를 눌러 바꿔 보면서 어떤 이름이 뽑히는지, 어느 열이 어긋나는지 확인하세요.

## 개체 단위로 채점하기

개체명 인식은 대부분의 token이 O라서 token 정확도로 재면 후하게 나옵니다. 그래서 이름 하나를 단위로 세고, 종류와 경계가 모두 정답과 같을 때만 맞은 것으로 칩니다.

정답에 이름이 5개 있고, 모델이 4개를 냈고, 그중 3개가 맞았다고 합시다.

```text
정밀도 = 맞은 수 / 모델이 낸 수 = 3 / 4 = 0.75
재현율 = 맞은 수 / 정답 수       = 3 / 5 = 0.6
F1     = 2 x 0.75 x 0.6 / (0.75 + 0.6) = 0.9 / 1.35 = 0.667
```

정밀도는 모델이 이름이라고 한 것 중 실제로 맞은 비율이고, 재현율은 실제 이름 중 모델이 찾은 비율입니다. F1은 둘의 조화평균입니다.

## 기억할 것 세 가지

### token 정확도가 높아도 개체를 못 찾을 수 있습니다

token 16개 중 이름 token이 7개이고 나머지 9개가 O인 데이터가 있다고 합시다. 모델이 전부 O로 내면 token 정확도는 \(9/16 \approx 0.56\)이지만 개체 F1은 0입니다. 글이 길수록 O의 비중이 커져서 이 격차는 더 벌어집니다.

### 경계가 조금 틀려도 부분 점수가 없습니다

정답이 "서울 특별시"인데 모델이 "서울"만 내면, 모델이 낸 것은 틀렸고(FP 1) 정답은 놓친 것(FN 1)이 됩니다. 한 번 틀렸는데 두 번 틀린 것으로 셉니다. 경계가 겹치기만 하면 맞다고 세는 느슨한 평가도 있어서, 점수를 비교할 때는 어느 기준인지 확인합니다.

### LLM 추출은 원문에 없는 값을 낼 수 있습니다

LLM에 개체를 뽑으라고 하면 원문에 없는 이름을 만들어 내거나, 표기를 바꿔서 내기도 합니다. 뽑은 값이 원문에 실제로 있는지 문자열로 확인하고, 위치(시작과 끝)를 같이 받아서 원문과 맞춰 봅니다. 개인정보 마스킹에서는 놓친 이름(재현율)이 더 치명적이어서, 정밀도보다 재현율을 먼저 봅니다.

<summary>더 깊이: 모델 구조, 어긋난 열 걸러내기, 마이크로 F1과 매크로 F1</summary>

- 전용 모델은 [트랜스포머](./transformer.md)나 [순환 신경망](./rnn.md)으로 token마다 벡터를 만들고, 표지별 점수를 낸 뒤 [소프트맥스](../machine-learning/softmax.md)를 씁니다. [버트](./bert.md)를 fine-tuning하면 마지막 층의 token별 벡터를 그대로 분류에 씁니다. token이 단어 조각으로 쪼개지면 첫 조각의 표지만 정답으로 두는 방식이 흔합니다.
- 자리마다 가장 높은 표지를 고르면 O 바로 뒤의 I처럼 어긋난 열이 나올 수 있습니다. 어긋난 열에 비용을 더해 가장 비용이 낮은 열을 고르는 방법이 [비터비](../machine-learning/viterbi.md)와 같은 종류입니다. 서울이 O(점수 3), 특별시가 I-LOC(점수 5)이면 점수 합 8이 최고이지만 어긋난 열입니다. 비용을 더하면 맞는 열 B-LOC, I-LOC(점수 합 7)이 이깁니다.
- BIO 외에 끝을 E, 한 token짜리를 S로 따로 표시하는 BIOES도 씁니다.
- 품사 태깅(part-of-speech tagging)도 같은 모양입니다. token마다 명사, 동사 같은 표지를 붙입니다.
- 개체 전체를 한꺼번에 세어 구한 F1이 마이크로 F1이고, 종류별 F1을 평균한 것이 매크로 F1입니다. 개체 수가 적은 종류도 같은 비중으로 반영되는 점이 다릅니다. 흔한 종류는 잘 맞고 희귀한 종류만 약하면, 매크로 F1이 마이크로 F1보다 낮게 나옵니다.

</details>
