임베딩은 token이나 문장을 수 목록(벡터)으로 바꾼 것입니다. 신경망은 글자를 계산할 수 없어서 글을 먼저 수로 바꿉니다.

에이전트를 만들 때 세 군데에서 만납니다.

- **RAG 검색**: 문서를 자른 조각(청크)과 질문을 같은 임베딩 모델에 넣어 벡터로 만들고, 가까운 청크를 찾습니다. → [검색](../rag/retrieval.md), [벡터 인덱스](../rag/vector-index.md)
- **그 밖의 의미 비교**: 비슷한 질문을 묶는 시맨틱 캐시, 중복 문서 제거, 분류, 라우팅에도 같은 벡터를 씁니다.
- **LLM 입력층**: prompt의 token은 가장 먼저 임베딩 표에서 벡터로 바뀝니다. 모델 안에서 일어나는 일이라 API로는 보이지 않습니다.

## token 임베딩: 표에서 행 읽기

LLM 안쪽의 임베딩은 표입니다. token 번호가 행 번호이고, 한 행이 그 token의 벡터입니다. 이 표의 수는 학습으로 정해지는 파라미터입니다.

| 번호 | token | 벡터 |
| --- | --- | --- |
| 0 | 오늘 | 1, 0 |
| 1 | 날씨 | 0, 1 |
| 2 | 좋다 | 1, 1 |
| 3 | 나쁘다 | 0, 0 |

"오늘 날씨"는 번호 0, 1이고, 모델에 들어가는 것은 번호가 아니라 0번 행과 1번 행입니다. 표에는 순서 정보가 없어서, 몇 번째 자리인지를 나타내는 벡터를 따로 더해 줍니다. 아래 그림에서 단어를 눌러 번호가 행으로 바뀌고 자리 정보가 더해지는 과정을 보세요.

표의 크기는 사전 크기 곱하기 벡터 길이입니다. 사전이 128,000개이고 길이가 4,096이면 표만 5억 개 넘는 수입니다. 사전이 10,000개이고 길이가 100이면 100만 개입니다. 이 표를 만들 때 token을 어디서 자를지는 [tokenization](./tokenization.md)이 정합니다.

## 문장 임베딩: RAG에서 쓰는 쪽

임베딩 모델은 글 한 덩어리를 받아 벡터 하나를 돌려줍니다. 모델 안에서는 token 벡터들이 [어텐션](./attention.md)(token마다 다른 token을 얼마나 읽을지 정해 정보를 섞는 계산)을 거치며 섞이고, 그 결과가 하나의 벡터로 요약됩니다. 그래서 같은 단어라도 문장에 따라 벡터가 달라집니다.

RAG의 흐름은 두 단계입니다.

1. 문서를 청크로 자르고, 청크마다 벡터를 만들어 저장합니다.
2. 질문이 오면 질문 벡터를 만들어, 저장된 벡터 중 가장 가까운 것을 가져옵니다. 가까움은 [코사인 유사도](./cosine-similarity.md)로 잴 때가 많습니다.

## 기억할 것 네 가지

### 임베딩 이전의 표현에는 뜻이 없었습니다

번호 \(k\)인 항목을 \(k\)번 칸만 1이고 나머지는 0인 벡터로 바꾸는 원-핫(one-hot) 방식이 있습니다. 서로 다른 두 원-핫의 거리는 사전이 얼마나 크든 항상 \(\sqrt{2}\)라서, `좋다`와 `나쁘다`의 거리와 `좋다`와 `훌륭하다`의 거리가 같습니다. 키워드 검색이 유의어를 놓치는 이유이고, 임베딩은 비슷한 말이 가까워지게 학습한 것입니다. 원-핫은 분류와 다음 token 학습의 정답 레이블로는 지금도 쓰입니다. → [소프트맥스](../machine-learning/softmax.md)

### 저장할 때와 검색할 때 같은 모델을 씁니다

모델마다 벡터 공간이 다릅니다. 같은 문장도 모델 A와 B가 내는 벡터는 서로 관계가 없습니다. 벡터 길이가 같아서 계산이 돌아가더라도 결과는 의미가 없습니다. 임베딩 모델을 바꾸면 저장된 청크를 전부 다시 임베딩해야 합니다.

### 벡터 길이와 입력 길이는 비용입니다

벡터가 길수록 저장 공간과 검색 시간이 늘어납니다. 일부 API는 벡터 길이를 줄여 받는 옵션을 줍니다. 모델마다 입력 token 한도도 있어서, 청크가 한도를 넘으면 뒷부분이 잘리거나 오류가 납니다. 청크 크기는 이 한도 안에서 정합니다. → [청킹](../rag/chunking.md)

### 가깝다는 것은 관련이 있다는 뜻이지 정답이라는 뜻이 아닙니다

벡터는 같이 쓰이는 말의 비슷함을 담습니다. 질문과 가까운 청크가 답을 담고 있다는 보장은 없습니다. "환불 가능합니다"와 "환불 불가합니다"는 주제가 같아서 가까운 벡터가 됩니다. 검색한 청크가 답의 근거가 되는지는 따로 확인해야 합니다. → [근거 확인](../rag/grounding.md)

<summary>더 깊이: 표와 원-핫, 자리 정보, 학습</summary>

- 원-핫 벡터에 표를 곱하면 그 행이 나옵니다. 번호 0의 원-핫은 \([1,\ 0,\ 0,\ 0]\)이고, 위 표(4행 2열)에 곱하면 \([1,\ 0]\)입니다. 사전이 5만이면 원-핫은 5만 칸이고 거의 다 0이라, 구현에서는 원-핫을 만들지 않고 번호로 행을 바로 읽습니다.
- 표에서 읽은 행은 문맥을 모릅니다. "은행"은 어느 문장에서든 같은 행입니다. 문맥에 따라 달라지는 벡터는 어텐션을 지난 뒤에 나옵니다.
- 순서는 표에 없어서 자리마다 따로 만든 벡터를 더합니다. 오늘이 첫 자리이고 자리 벡터가 \([0.1,\ 0]\)이면 입력은 \([1,\ 0] + [0.1,\ 0] = [1.1,\ 0]\)입니다.
- 학습 중에는 읽힌 행만 기울기를 받습니다. 한 문장이 건드리는 행은 그 문장의 token 수만큼입니다.
- 출력 쪽에서 단어별 점수를 만들 때 같은 표를 다시 쓰는 구조(weight tying)도 있습니다. 파라미터가 한 벌로 줄어듭니다. 점수는 [소프트맥스](../machine-learning/softmax.md)로 비율이 됩니다.
- 표를 처음부터 학습하지 않고 [워드투벡터](./word2vec.md)처럼 미리 학습한 것을 초기값으로 쓰기도 합니다. 위 예의 나쁘다 행 \([0,\ 0]\)처럼 영 벡터는 코사인을 계산할 수 없는데, 실제 표에는 보통 없습니다.

</details>
