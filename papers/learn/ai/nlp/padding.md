패딩은 길이가 다른 문장을 한 묶음(batch)으로 만들려고 짧은 문장 뒤에 붙이는 빈 칸입니다. 빈 칸이 계산에 섞이지 않게 마스크(mask)로 표시해야 합니다.

호스팅 API만 쓰면 안 보이지만, 아래 작업에서는 직접 만납니다.

- **로컬 모델 batch 추론**: Hugging Face `tokenizer(texts, padding=True)`로 여러 prompt를 한 번에 넣을 때 `attention_mask`가 같이 나옵니다.
- **임베딩 대량 생성**: RAG 인덱싱에서 청크 수천 개를 batch로 임베딩할 때 패딩 낭비가 시간을 좌우합니다. → [임베딩](./embedding.md)
- **fine-tuning**: 학습 데이터를 batch로 묶을 때 패딩 위치에는 오차를 계산하지 않아야 합니다.

## 묶고 가리기

"날씨 좋다"는 token이 둘이고 "오늘 날씨 정말 좋다"는 넷입니다. 짧은 쪽에 빈 칸 0을 둘 붙여 넷으로 맞춥니다. 어느 칸이 진짜 token인지는 마스크로 기억합니다. 진짜는 1, 빈 칸은 0입니다.

```text
날씨 좋다 0 0        mask 1 1 0 0
오늘 날씨 정말 좋다   mask 1 1 1 1
```

최대 길이와 붙이는 위치를 바꿔 보세요. 최대 길이보다 긴 문장은 뒤가 잘립니다.

<PadBatch />

마스크를 빼먹으면 두 곳에서 문제가 생깁니다. 오차 평균에 빈 칸이 들어가면 학습 신호가 흐려집니다. 날씨와 좋다의 오차가 각각 0.3이고 빈 칸의 오차를 1이라고 하면, 빈 칸을 넣은 평균은 \((0.3 + 0.3 + 1 + 1)/4 = 0.65\)이고 뺀 평균은 \((0.3 + 0.3)/2 = 0.3\)입니다. 어텐션에서는 빈 칸이 비율을 가져가서 진짜 token이 받을 몫이 줄어듭니다. → [어텐션](./attention.md)

## 기억할 것 세 가지

### 빈 칸은 반드시 가립니다

마스크를 오차에 곱하고 어텐션 점수에 적용해야 문장 하나만 넣었을 때와 같은 결과가 나옵니다. 라이브러리가 `attention_mask`를 받으면 대부분 알아서 처리합니다. 문제는 마스크 없이 input_ids만 모델에 넘기는 경우입니다. 오류 없이 돌아가지만 결과가 미세하게 달라서 알아채기 어렵습니다.

### 생성할 때는 왼쪽에 붙입니다

decoder-only LLM은 마지막 칸의 출력으로 다음 token을 만듭니다. 오른쪽에 붙이면 짧은 문장의 마지막 칸이 빈 칸이라, 진짜 문장이 아니라 빈 칸에서 이어 쓰게 됩니다. 왼쪽에 붙이면 모든 문장의 마지막 칸이 진짜 token입니다. 학습에서는 오른쪽 패딩도 마스크만 있으면 괜찮습니다. pad token이 따로 없는 모델이 많아서 eos token을 pad로 재사용하는 일이 흔한데, 그때도 마스크가 있어야 구분됩니다.

### 길이가 비슷한 문장끼리 묶습니다

batch의 가로는 가장 긴 문장에 맞춥니다. 길이가 2, 4, 3, 7인 네 문장을 한 묶음으로 만들면 칸이 28개이고 진짜 token은 16개라서 빈 칸이 12개(42.9%)입니다. 비슷한 것끼리 (2, 3)과 (4, 7)로 나누면 칸이 20개, 빈 칸이 4개(20%)로 줄어듭니다. 빈 칸도 계산 시간과 메모리를 씁니다. 청크 길이가 들쭉날쭉한 RAG 인덱싱에서는 길이로 정렬해서 묶으면 빨라집니다.

<summary>더 깊이: 어텐션 마스크 수치, 임베딩 번호, RNN과의 관계</summary>

- 마스크를 써서 빈 칸을 뺀 평균 오차는 마스크 \(m_i\)와 자리별 오차 \(\ell_i\)로 쓰면 아래와 같습니다. 마스크가 1인 자리의 오차만 더해 그 개수로 나눕니다.

\[
\bar{\ell} = \frac{\sum_i m_i \ell_i}{\sum_i m_i}
\]

- 어텐션 점수가 \(2,\ 1,\ 0,\ 0\)이고 뒤 두 칸이 빈 칸이라고 합시다. 가리지 않으면 소프트맥스 비율이 \(0.610,\ 0.225,\ 0.083,\ 0.083\)이라 빈 칸이 약 0.165를 가져갑니다. 빈 칸의 점수를 아주 작은 수(\(-\infty\) 또는 큰 음수)로 바꾸면 비율이 \(0.731,\ 0.269,\ 0,\ 0\)이 됩니다. 이 처리는 미래 token을 가리는 causal mask와 같은 종류입니다.
- 빈 칸에 쓰는 번호는 사전의 어떤 단어와도 겹치면 안 됩니다. 0번이 이미 단어에 쓰이면 빈 칸 전용 번호를 따로 만듭니다. 그 번호의 임베딩 행은 오차와 어텐션에서 빠지므로 기울기를 받지 않고, 많은 라이브러리가 영 벡터로 고정하는 옵션을 줍니다.
- [순환 신경망](./rnn.md)은 빈 칸을 지날 때마다 상태가 한 번씩 더 갱신됩니다. 마지막 칸의 상태를 쓰면 진짜 마지막 token의 상태와 달라서, 길이를 따로 기억해 두었다가 진짜 마지막 칸의 상태를 꺼냅니다.
- 한 batch의 최대 길이를 사람이 정해 두면 그보다 긴 문장은 잘립니다. 가장 긴 문장에 맞추면 잘리지 않고 빈 칸만 늘어납니다.

</details>
