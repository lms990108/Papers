단어 주머니는 문장을 단어별 출현 횟수의 벡터로 바꾸고 순서는 버리는 표현입니다. LLM 이전의 기본 텍스트 표현이고, 지금은 키워드 검색의 바탕으로 만납니다.

에이전트를 만들 때 이런 곳에서 이 생각이 나옵니다.

- **키워드 검색**: RAG의 키워드 검색(BM25 같은 sparse retrieval)은 단어가 문서에 몇 번 나왔는지로 점수를 냅니다. → [TF-IDF](./tf-idf.md)
- **hybrid search**: 이 키워드 점수와 임베딩(뜻이 비슷한 글이 가까운 벡터가 되게 바꾼 것) 점수를 합쳐 검색합니다. 둘이 서로 다른 것을 놓치기 때문입니다. → [고급 RAG](../rag/advanced-rag.md)
- **가벼운 baseline**: 분류나 라우팅에서 LLM을 부르기 전에, 횟수 벡터와 로지스틱 회귀로 먼저 해 볼 수 있습니다.

## 왜 필요한가

글은 문장마다 길이가 다릅니다. 반면 분류기와 [코사인 유사도](./cosine-similarity.md) 같은 계산은 길이가 정해진 벡터를 받습니다. 그래서 글을 "항상 같은 길이의 수 목록"으로 바꾸는 방법이 필요합니다.

가장 단순한 방법은 단어마다 번호를 매기고 번호 열을 그대로 넣는 것입니다. 사전이 오늘 0, 날씨 1, 좋다 2, 나쁘다 3이면 "날씨 좋다"는 \([1,\ 2]\), "날씨 나쁘다 날씨"는 \([1,\ 3,\ 1]\)입니다. 문제가 둘입니다. 길이가 달라서 같은 분류기에 넣을 수 없습니다. 또 번호는 이름표일 뿐인데, 계산은 3이 2의 1.5배라는 크기로 읽어 버립니다.

단어 주머니는 단어마다 칸을 하나씩 주고 그 단어가 나온 횟수를 적습니다. 벡터 길이는 문장 길이와 상관없이 사전 크기로 고정되고, 번호의 크기가 뜻을 갖는 일도 없습니다. 대가는 순서입니다. 앞에서 본 [텍스트 전처리](./text-preprocessing.md)는 이 칸 수를 줄이는 단계였습니다. 횟수를 셀 단위는 [tokenization](./tokenization.md)이 정한 token입니다.

## 계산

벡터의 칸이 될 단어 목록(사전)을 오늘, 날씨, 좋다, 나쁘다 순으로 둡니다. 문장을 [tokenization](./tokenization.md)한 뒤 token마다 해당 칸에 1을 더합니다. 아래 표의 각 줄이 문장 하나의 벡터입니다.

```text
문장                  오늘 날씨 좋다 나쁘다
날씨 좋다               0    1    1    0
좋다 날씨               0    1    1    0
날씨 나쁘다 날씨        0    2    0    1
```

순서가 다른 첫째와 둘째 문장이 같은 벡터입니다. 문장 길이가 달라도 벡터 길이는 사전 크기로 같습니다. 사전에 없는 단어는 칸이 없어서 버려집니다.

문장 벡터를 \(x\)라 하고 칸별 가중치를 \(w\)라 합시다. 둘을 칸마다 곱해 더하면 한 줄짜리 분류기의 점수가 됩니다.

\[
s = w \cdot x
\]

가중치는 학습 글에서 레이블을 가장 잘 맞히도록 정해집니다([로지스틱 회귀](../machine-learning/logistic-regression.md)). 점수가 클수록 불만이라고 하고, 설명용으로 \(w = [0,\ 0,\ -1,\ +1]\)(오늘, 날씨, 좋다, 나쁘다 순)이라 합시다. 위 표의 두 문장 점수는 이렇습니다.

```text
날씨 좋다           0×0 + 1×0 + 1×(-1) + 0×1 = -1
날씨 나쁘다 날씨    0×0 + 2×0 + 0×(-1) + 1×1 =  1
```

`날씨`의 가중치는 0이라 몇 번 나와도 점수가 변하지 않고, `나쁘다`가 있는 문장만 불만 쪽으로 갑니다. 사전이 5만 단어이면 벡터는 5만 칸이지만 한 문장에서 0이 아닌 칸은 몇 개뿐이라, 실제로는 0이 아닌 칸만 저장합니다(희소 벡터). 키워드 검색이 sparse retrieval로 불리는 이유입니다.

## 기억할 것 세 가지

### 순서와 부정을 읽지 못합니다

"dog bites man"과 "man bites dog"은 뜻이 반대인데 같은 벡터입니다. 부정도 약합니다. "나쁘지 않다"에는 `나쁘다` 칸이 1로 들어가서, 불만 쪽 가중치를 가진 칸이 그대로 점수를 올립니다. 순서와 문맥은 [어텐션](./attention.md) 쪽이 읽습니다.

### 횟수가 크다고 중요한 단어는 아닙니다

조사와 `날씨`처럼 어디에나 있는 말이 가장 큰 횟수를 가집니다. 이것을 깎는 방법이 [불용어](./text-preprocessing.md) 제거와 [TF-IDF](./tf-idf.md)입니다.

### 같은 뜻도 다른 칸이 됩니다

`좋다`와 `훌륭하다`는 칸이 달라서 서로 닮았다는 정보가 없습니다. 그래서 키워드 검색이 놓치는 유의어를 임베딩 검색이 찾습니다. → [임베딩](./embedding.md)

- 이진: 있는지 없는지만 적습니다. 같은 단어가 여러 번 나와도 1입니다.
