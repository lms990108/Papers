LLM은 앞만 보는 [트랜스포머](./transformer.md) 블록을 크게 쌓고, 방대한 글의 모든 자리에서 다음 token을 맞히도록 학습한 모델입니다. 에이전트에서 판단과 생성을 맡는 부분이고, 만나는 곳이 가장 많습니다.

- **API 호출**: messages, `max_tokens`, `temperature`를 넘기고 token으로 요금을 냅니다. → [다음 token](./next-token.md)
- **context window**: 입력과 출력이 함께 쓰는 token 한도입니다. 에이전트 루프에서 가장 먼저 부딪힙니다.
- **지연 시간과 비용**: 입력 token은 한꺼번에, 출력 token은 하나씩 처리합니다. → [Prefill, decode](./prefill-decode.md)
- **모델 선택**: 사전 학습만 마친 base 모델을 후속 학습으로 chat, reasoning 모델로 만듭니다. → [Post-training](./post-training.md)
- **지식 한계**: 학습한 시점까지의 글만 압니다. 그 뒤의 정보는 prompt나 RAG로 넣습니다. → [RAG](../rag/index.md)

## 계산

글이 "오늘 날씨 좋다"이면 맞힐 자리가 둘입니다. 오늘 자리는 날씨를, 날씨 자리는 좋다를 맞힙니다. 모델이 정답에 준 비율이 각각 0.5와 0.711이라고 합시다. 자리마다 오차 \(-\log p\)를 구해 평균을 냅니다.

\[
\frac{-\log 0.5 + (-\log 0.711)}{2} = \frac{0.693 + 0.341}{2} \approx 0.517
\]

LLM의 사전 학습은 이 평균을 줄이는 일 하나입니다. 이 평균에 지수를 씌우면 퍼플렉서티이고, 이 예에서는 약 1.677입니다. 1에 가까울수록 정답 칸의 비율이 높습니다. 모델이 커져도 오차의 식은 같습니다. 블록 수와 벡터 길이는 비율을 만드는 쪽에 들어갑니다.

## 기억할 것 세 가지

### context window에는 입력과 출력이 함께 들어갑니다

API는 대화를 기억하지 않습니다. 매 요청에 지금까지의 messages를 전부 다시 보냅니다. 에이전트 루프에서는 도구 결과까지 쌓입니다.

단계마다 도구 결과가 2,000 token씩 쌓인다면 \(k\)번째 요청의 입력은 \(2{,}000 \times k\) token입니다. 10번 요청에 보낸 입력의 합은 \(2{,}000 \times (1 + 2 + \dots + 10) = 110{,}000\) token입니다. 마지막 요청의 입력은 2만 token인데 총 입력은 그 5.5배입니다. context 길이는 단계 수에 비례해 늘지만 보낸 입력의 총합은 단계 수의 제곱에 가깝게 늡니다. 그래서 이전 내용을 요약하고, 오래된 도구 결과를 지우고, 같은 앞부분을 캐시하는 설계가 필요해집니다. → [Prefill, decode](./prefill-decode.md)

### 사실이 아니라 그럴듯한 다음 token을 고릅니다

모델은 학습한 글에서 다음에 올 만한 token의 비율을 만듭니다. 그 token이 사실인지 확인하는 단계는 없습니다. 틀린 내용도 비율이 높으면 자신 있게 나옵니다. 그래서 근거가 필요한 답은 RAG나 도구로 확인할 문서를 prompt에 넣고, 출처를 인용하게 하는 방식을 씁니다.

temperature를 0으로 낮춰도 사실만 말하게 되는 것은 아닙니다. 가장 비율이 높은 token을 고를 뿐이고, 같은 입력에 완전히 같은 출력이 나온다는 보장도 없습니다.

### 지식은 학습 시점에 멈춰 있습니다

모델이 아는 내용은 학습 데이터의 마지막 날짜까지입니다. 최신 정보, 회사 내부 문서, 사용자 개인 정보는 모델 안에 없습니다. 이런 것은 prompt나 RAG, 도구 호출로 넣어야 합니다. 모델을 다시 학습해서 넣는 것은 비용이 크고 갱신이 느려서 보통 마지막 수단입니다.

<summary>더 깊이: 퍼플렉서티와 인과 마스크</summary>

- 퍼플렉서티는 평균 오차의 지수입니다. 정답 비율이 매 자리 \(1/4\)이면 4이고, 네 단어를 균등하게 고르는 것과 같습니다. 모델 평가에서 쓰지만 에이전트의 작업 성공률과는 별개의 지표입니다.
- 양쪽을 다 보는 블록으로 다음 token을 맞히면 정답이 입력에 이미 있어 오차가 0이 됩니다. 그래서 미래 칸을 점수에서 빼는 인과 마스크를 걸고, 그렇게 쌓은 블록 더미가 decoder-only입니다. 앞뒤를 보고 가린 칸을 맞히는 쪽이 [버트](./bert.md)입니다.
- 블록 한 층의 내부 계산은 [Decoder block](./block.md)에서, 이 모델이 다음 단어 비율을 만드는 원리는 [언어 모델](./language-model.md)에서 봅니다.
