셀프 어텐션은 query, key, value가 모두 같은 token 열에서 나오는 [어텐션](./attention.md)입니다. 한 문장 안의 token들이 서로를 읽습니다.

에이전트를 만들 때는 이 계산의 변형이 어떤 모델을 쓰느냐로 나타납니다.

- **생성용 LLM**: 뒤를 가린(causal) 셀프 어텐션만 쌓습니다. → [LLM](./llm.md)
- **임베딩 모델, reranker**(검색된 청크를 질문과 함께 읽고 순위를 다시 매기는 모델): 앞뒤를 모두 보는 셀프 어텐션이 많습니다. → [버트](./bert.md)
- **prompt caching**: 앞을 읽기만 하는 성질 덕분에 앞부분의 계산을 재사용합니다. → [프리필과 디코드](./prefill-decode.md)

## 왜 필요한가

[어텐션](./attention.md)은 한 열이 다른 열을 읽는 계산입니다. 번역에서는 출력 쪽이 입력 쪽을 읽습니다. 그런데 문장 하나를 이해하는 데도 같은 계산이 필요합니다. [워드투벡터](./word2vec.md)에서 본 것처럼 단어마다 벡터가 하나뿐이면 "은행"은 어느 문장에서든 같은 벡터입니다. 강 옆의 은행인지 대출을 받는 은행인지는 같은 문장의 옆 token을 봐야 정해집니다. 문장 안의 token이 서로를 읽어 자기 벡터를 문맥에 맞게 고쳐야 합니다.

이 일을 [순환 신경망](./rnn.md)으로 하면 정보가 자리를 하나씩 지나서 전해집니다. 두 token이 50칸 떨어져 있으면 상태를 50번 갱신하는 동안 정보가 살아남아야 하고, 계산도 앞자리부터 순서대로 해야 합니다. 셀프 어텐션은 문장 안의 모든 token이 같은 문장의 모든 token을 직접 읽습니다. 떨어진 거리와 상관없이 한 층에서 닿고, 모든 자리를 동시에 계산합니다. 이름의 self는 질문하는 쪽(query)과 답하는 쪽(key, value)이 같은 token 열이라는 뜻입니다.

## 계산

token이 \(n\)개이면 점수 표는 \(n \times n\)이고, 행 하나가 한 token이 문장 전체에 나눠 주는 읽기 비율이어서 각 행은 합이 1입니다(열의 합이 아닙니다). 오늘, 날씨, 좋다 세 token의 점수가 아래와 같다고 합시다. 행이 query, 열이 key입니다.

```text
점수           오늘    날씨    좋다
오늘 (query)   1.414   0       1.414
날씨           0       0.707   0.707
좋다           1.414   0.707   2.121
```

소프트맥스를 하면 왼쪽 표가 됩니다. 뒤 token을 가리면 오른쪽 표가 됩니다. 가린 칸은 점수에서 빼고 남은 칸으로 소프트맥스를 합니다.

```text
가리지 않음                    뒤를 가림 (causal)
오늘   0.446  0.108  0.446     1.000  -      -
날씨   0.198  0.401  0.401     0.330  0.670  -
좋다   0.284  0.140  0.576     0.284  0.140  0.576
```

오늘은 자기만 읽을 수 있어 비율이 1입니다. 마지막 token 좋다는 앞을 다 읽을 수 있어서 가려도 같은 행이 나옵니다.

가리지 않은 표의 날씨 행은 오늘 0.198, 날씨 0.401, 좋다 0.401입니다. 날씨의 새 벡터는 세 token의 value를 이 비율로 섞은 것이라, 날씨 혼자였던 벡터에 이웃의 정보가 들어갑니다. 이것이 문맥을 반영한 벡터입니다. 출력은 입력과 같은 수의 벡터로, token마다 하나씩 나옵니다.

아래 그림에서 self, cross, causal 세 경우를 눌러 비교해 보세요. cross는 query가 한 열에서, key와 value가 다른 열에서 오는 경우입니다(번역에서 출력 쪽이 입력 쪽을 읽을 때). 계산은 같고 query와 key, value가 어디서 오는지, 어느 칸을 가리는지만 다릅니다.

## 기억할 것 세 가지

### 생성 모델은 뒤를 가린 셀프 어텐션입니다

앞의 오른쪽 표처럼 각 token은 자기와 앞만 읽습니다. 그래서 prompt의 앞부분 token은 뒤에 무엇이 오든 계산 결과가 바뀌지 않습니다. 이 성질 덕분에 앞부분의 key와 value를 저장해 두고 재사용할 수 있습니다. 앞부분이 같은 요청이 반복되는 에이전트 루프에서 prompt caching이 효과를 내는 구조입니다.

### 임베딩 모델과 생성 모델은 보는 방향이 다릅니다

검색용 임베딩 모델과 reranker는 문장을 읽고 표현으로 바꾸는 일이라 앞뒤를 모두 보는 구조가 많습니다. 생성 모델은 한 방향입니다. RAG는 둘을 함께 쓰는데 입력 길이 한도가 모델마다 다릅니다. 임베딩 모델의 최대 입력 token 수는 LLM의 context window보다 훨씬 짧은 경우가 많아, 청크 크기를 정할 때 확인해야 합니다.

### 순서는 위치 정보로 따로 넣습니다

셀프 어텐션 자체는 token 순서를 모릅니다. 위치 정보를 더해 순서를 알려 주고, 그 방식에 따라 모델이 안정적으로 다루는 최대 길이가 정해집니다. context window 한도의 한 원인이기도 합니다.

<summary>더 깊이: 크로스 어텐션, 순서 불변성, 경로 길이</summary>

- 크로스 어텐션은 query는 한쪽 열에서, key와 value는 다른 열에서 옵니다. 점수 표가 \(m \times n\)이 됩니다. 번역, 글로 이미지를 만드는 확산 모델, 일부 멀티모달 모델이 씁니다. 텍스트만 다루는 에이전트에서는 직접 만날 일이 드뭅니다.
- 순서를 섞어 넣으면 각 token의 출력은 같고 놓이는 줄만 따라 바뀝니다. 입력의 행을 섞는 순열 행렬을 \(P\)라 하면 점수 표는 \(P S P^\top\)이 되고, 출력은 \(P Y\)가 됩니다.
- 두 token 사이에 정보가 닿기까지 거치는 단계(경로 길이)는 순환 신경망이 \(O(n)\), 셀프 어텐션이 \(O(1)\)입니다. 대신 층당 점수 표가 \(n^2\)이라 길이가 길수록 비용이 커집니다. 2017년 트랜스포머 논문(Vaswani 외)의 비교표입니다.

</details>
