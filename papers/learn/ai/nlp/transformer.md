트랜스포머는 [어텐션](./attention.md)과 token마다 따로 계산하는 층을, 더하기와 정규화로 감싼 블록을 여러 개 쌓은 구조입니다. 지금 쓰는 LLM과 임베딩 모델은 거의 이 구조입니다.

에이전트를 만들 때는 구조 자체보다 구조가 정하는 숫자를 만납니다.

- **모델 크기와 GPU 메모리**: 블록 수와 벡터 길이로 파라미터 수가 정해지고, 그 수가 가중치 메모리입니다.
- **context window와 KV cache**: 길이에 따라 어텐션 비용과 KV cache 메모리가 늘어납니다. → [프리필과 디코드](./prefill-decode.md)
- **모델 종류**: 생성용 LLM, 임베딩 모델, 번역 모델이 같은 블록으로 다르게 조립됩니다.

## 왜 필요한가

2017년 이전의 번역 모델은 [순환 신경망](./rnn.md)이나 [장단기 메모리](./lstm.md) 위에 [어텐션](./attention.md)을 붙인 형태였습니다. 순환 구조는 자리를 순서대로 계산해야 해서, 1,000 token짜리 학습 문장 하나에 1,000단계가 직렬로 필요했습니다. 2017년 Vaswani 등의 논문 "Attention Is All You Need"는 순환 구조를 빼고 [셀프 어텐션](./self-attention.md)만으로 번역 모델을 만들었습니다. 셀프 어텐션은 한 층에서 모든 자리를 동시에 계산하므로 GPU를 충분히 쓸 수 있고, 그래서 더 큰 모델을 더 큰 글로 학습할 수 있었습니다.

다만 셀프 어텐션만 쌓아서는 모델이 되지 않습니다. 어텐션은 value를 비율대로 섞는 계산이라, token 하나하나의 정보를 따로 가공하는 단계가 빠져 있습니다. 또 층을 깊게 쌓으면 학습 신호가 앞쪽 층까지 닿지 못하는 일이 생깁니다. → [기울기 소실](../deep-learning/gradient-vanishing.md) 트랜스포머는 섞는 단계(어텐션) 뒤에 가공하는 단계(FFN)를 두고, 더하기와 정규화로 감싸서 깊게 쌓을 수 있게 만든 구조입니다.

학습과 입력 읽기는 병렬이지만, 답을 생성할 때는 token을 하나 만들어야 다음 token의 입력이 생겨서 한 개씩 순서대로 만듭니다. → [프리필과 디코드](./prefill-decode.md)

## 블록 하나

트랜스포머는 같은 모양의 블록을 여러 개 쌓은 것입니다. 블록 하나는 token 벡터가 줄지어 있는 표를 받아서 같은 크기의 표를 돌려줍니다. 안에서 하는 일은 두 가지입니다.

- **어텐션**: token끼리 정보를 주고받습니다. 한 token의 벡터에 다른 token들의 정보가 섞여 들어옵니다. 블록 안에서 token 사이를 섞는 곳은 여기뿐입니다.
- **FFN**(feed-forward network): 섞어서 받은 정보를 token마다 따로 가공합니다. token 벡터 하나를 작은 신경망(보통 두 층)에 넣는 것이라 token 사이는 섞이지 않습니다.

회의에 빗대면 어텐션은 모두 모여 서로 이야기를 듣는 시간이고, FFN은 자리로 돌아가 들은 내용을 각자 정리하는 시간입니다. 블록은 이 두 시간을 차례로 지납니다.

다만 두 단계를 그냥 이어 붙이면 문제가 둘 생깁니다. 단계의 결과로 벡터를 통째로 갈아 끼우면 원래 정보가 흐려지고, 층이 깊을수록 학습 신호가 앞쪽 층까지 닿지 못합니다([기울기 소실](../deep-learning/gradient-vanishing.md)). 또 단계를 지날 때마다 값의 크기가 제멋대로 변할 수 있습니다. 그래서 각 단계에 장치를 둘 붙입니다. 아래에서는 앞 문서의 어텐션 계산에 나온 "오늘" token 벡터 \([1,\ 0]\)으로 따라갑니다. 길이 2는 칸이 보이게 줄인 것이고 실제 모델은 수천 칸입니다.

### 장치 1: 더하기 (잔차 연결, residual)

단계의 결과로 입력을 바꾸지 않고, 입력에 결과를 더합니다. 단계가 내놓는 것은 새 벡터가 아니라 "원래 벡터에 이만큼 보태라"는 수정분입니다.

앞 문서에서 어텐션이 \([0.670,\ 0.330]\)을 돌려줬습니다. 입력에 더하면 이렇습니다.

\[
[1,\ 0] + [0.670,\ 0.330] = [1.670,\ 0.330]
\]

원래 \([1,\ 0]\)이 그대로 들어 있고 그 위에 어텐션이 읽어 온 정보가 더해진 모양입니다. 이렇게 하면 입력에서 출력까지 더하기만 거치는 길이 남아서, 층을 수십 개 쌓아도 학습 신호가 앞쪽 층까지 전달됩니다.

### 장치 2: 층 정규화 (layer normalization)

더하기만 계속하면 값이 점점 커집니다. 층 정규화는 벡터 하나 안에서 값의 크기를 맞춰 주는 장치입니다. 먼저 평균을 빼서 중심을 0으로 옮기고, 값이 퍼진 정도(표준편차)로 나눠서 퍼진 정도를 1로 맞춥니다.

\([1.670,\ 0.330]\)에 적용하면 이렇습니다.

1. 평균: \((1.670 + 0.330) / 2 = 1\)
2. 평균을 뺍니다: \([0.670,\ -0.670]\)
3. 퍼진 정도(표준편차): 두 칸 모두 평균에서 0.670 떨어져 있으니 0.670입니다.
4. 퍼진 정도로 나눕니다: \([1,\ -1]\)

처음 값이 얼마나 크든 정규화를 거치면 이 규모로 돌아옵니다. 값은 바뀌지만 어느 칸이 더 큰지는 그대로입니다.

### FFN은 안에서 무슨 일을 하나요

FFN(feed-forward network)은 섞어서 받은 token 벡터 하나를 그 자리에서 가공하는 작은 신경망입니다. 벡터를 넓혔다가 다시 줄이는 두 층으로 되어 있고 세 동작을 합니다.

1. **넓히기**: 곱셈으로 벡터를 더 긴 벡터로 만듭니다. 실제 모델은 보통 4배 정도로 넓힙니다.
2. **음수 자르기**: 넓힌 값에서 음수를 0으로 바꿉니다(ReLU). 이 단계가 있어서 단순한 곱셈을 이어 붙인 것과 다른 계산이 됩니다.
3. **줄이기**: 곱셈으로 원래 길이로 되돌립니다. 입력과 출력의 길이가 같아야 블록을 쌓을 수 있기 때문입니다.

장치 2에서 정규화한 \([1,\ -1]\)이 FFN에 들어온다고 하고 따라가 봅니다. 가중치는 학습으로 정해지는 값인데, 여기서는 계산이 보이게 고른 값입니다.

| 동작 | 계산 | 결과 |
|---|---|---|
| 넓히기 | 칸 4개가 입력 두 칸에 곱하는 가중치가 \((1,\ 1)\), \((1,\ -1)\), \((-1,\ 1)\), \((-1,\ -1)\)입니다. 첫 칸은 \(1 \times 1 + 1 \times (-1) = 0\) | \([0,\ 2,\ -2,\ 0]\) |
| 음수 자르기 | \(-2\)가 0이 됩니다 | \([0,\ 2,\ 0,\ 0]\) |
| 줄이기 | 살아남은 2에 가중치 \((0,\ 1.5)\)를 곱합니다 | \([0,\ 3]\) |

어텐션은 벡터를 비율대로 섞는 계산이라, 섞은 결과를 이 token에 맞게 가공하는 일은 FFN이 맡습니다. 모든 token이 같은 가중치를 쓰지만 계산은 token마다 따로 하고 다른 token의 벡터는 보지 않습니다. 모델 파라미터의 큰 부분(보통 3분의 2 정도)이 이 두 층의 가중치입니다.

### 한 바퀴 돌려 보기

블록은 어텐션과 FFN 각각에 이 두 장치를 한 번씩 붙입니다. 같은 "오늘" 벡터가 블록을 한 번 지나는 과정입니다.

| 단계 | 하는 일 | 값 |
|---|---|---|
| 0. 입력 | 오늘 token 벡터 | \([1,\ 0]\) |
| 1. 어텐션 | 다른 token에서 정보를 가져옵니다 | \([0.670,\ 0.330]\) |
| 2. 더하기 | 입력 + 어텐션 결과 | \([1.670,\ 0.330]\) |
| 3. 정규화 | 크기를 맞춥니다 | \([1,\ -1]\) |
| 4. FFN | 넓히기, 음수 자르기, 줄이기를 지납니다(위 계산) | \([0,\ 3]\) |
| 5. 더하기 | 3번의 벡터 + FFN 결과 | \([1,\ 2]\) |
| 6. 정규화 | 평균 1.5, 표준편차 0.5로 맞춥니다 | \([-1,\ 1]\) |

2·3번이 어텐션에 붙은 장치이고 5·6번이 FFN에 붙은 장치입니다. 식 하나로 쓰면 \(y = \mathrm{LN}(x + \mathrm{Sublayer}(x))\)이고, Sublayer 자리에 어텐션과 FFN이 한 번씩 들어가 두 번 적용됩니다(LN은 층 정규화입니다).

결과 \([-1,\ 1]\)은 입력과 길이가 같습니다. 블록의 입력과 출력은 둘 다 (token 수 × 벡터 길이) 크기의 표여서 몇 개든 이어 쌓을 수 있습니다. 마지막 블록의 출력에서 생성용 LLM은 [다음 token](./next-token.md)의 점수를 만들고, 임베딩 모델은 벡터 하나로 요약합니다.

아래 그림은 위 표를 자동으로 재생합니다. 주황 길은 원래 값이 그대로 내려가는 길이고, 파랑 길은 복사본이 어텐션(또는 FFN)을 지나 수정분을 만드는 길입니다. 두 길이 만나는 +에서 더해집니다. 멈추고 싶으면 일시정지를 누르세요.

## 기억할 것 세 가지

### 모델 크기는 블록 수와 벡터 길이로 정해집니다

파라미터는 학습으로 정해지는 수입니다. 벡터 길이를 \(d\)라 하면 블록 하나에 약 \(12d^2\)개가 들어 있고(계산은 아래 '더 깊이'), 블록을 쌓은 수만큼 곱해집니다. \(d = 4096\), 블록 32개이면 \(12 \times 4096^2 \times 32\)로 약 64억 개입니다. 나머지는 token 표 등이 채워 7B급 모델이 됩니다.

가중치 메모리는 파라미터 수에 파라미터 하나가 차지하는 바이트 수를 곱한 값입니다. 70억 개를 bfloat16(2바이트)으로 두면 약 14GB이고, 4비트 양자화(수 하나를 4비트로 줄여 저장)를 하면 약 3.5GB입니다. 서빙에는 여기에 KV cache와 계산용 메모리가 더 필요합니다.

### 문장 길이는 파라미터가 아니라 비용에 들어갑니다

입력이 길어져도 파라미터는 늘지 않습니다. 늘어나는 것은 어텐션 계산과 KV cache 메모리입니다. 같은 모델이어도 context를 길게 쓰면 느려지고 비싸집니다.

### 구조는 세 가지가 있습니다

encoder-only는 앞뒤를 모두 보고 읽는 구조로, 임베딩 모델과 reranker, 분류기가 여기에 속합니다. → [버트](./bert.md)

decoder-only는 앞만 보고 이어 쓰는 구조입니다. GPT 계열이나 Llama 계열 같은 지금의 LLM이 대부분 이쪽입니다. → [LLM](./llm.md)

encoder-decoder는 입력을 읽는 쪽과 출력을 만드는 쪽이 나뉩니다. 번역 모델이 대표적입니다.

<summary>더 깊이: 위치 인코딩, 파라미터 세기, 정규화 위치</summary>

- 위치 인코딩은 자리 번호마다 정해진 벡터를 token 벡터에 더합니다. 2017년 논문은 사인과 코사인으로 만들었고, 요즘 LLM은 query와 key를 위치에 따라 돌리는 방식(RoPE) 등을 많이 씁니다. 방식에 따라 안정적으로 다루는 최대 길이가 달라집니다.
- 파라미터 \(12d^2\)은 어텐션의 \(W_Q, W_K, W_V, W_O\)가 \(4d^2\), FFN이 가운데 칸 수를 \(4d\)로 두었을 때 \(2 \times d \times 4d = 8d^2\)여서 나옵니다. 바이어스와 정규화 파라미터, token 표(임베딩)는 뺀 값입니다.
- 2017년 블록은 더한 뒤에 정규화했고, 지금 LLM은 어텐션과 FFN 앞에서 먼저 정규화하는 구성이 흔합니다.
- 일부 큰 모델은 FFN을 여러 전문가(expert)로 나누고 token마다 몇 개만 쓰는 구조(MoE)입니다. 파라미터 수는 크지만 token당 계산은 그보다 적습니다.

</details>
