트랜스포머는 [어텐션](./attention.md)과 token마다 따로 계산하는 층을, 더하기와 정규화로 감싼 블록을 여러 개 쌓은 구조입니다. 지금 쓰는 LLM과 임베딩 모델은 거의 이 구조입니다.

에이전트를 만들 때는 구조 자체보다 구조가 정하는 숫자를 만납니다.

- **모델 크기와 GPU 메모리**: 블록 수와 벡터 길이로 파라미터 수가 정해지고, 그 수가 가중치 메모리입니다.
- **context window와 KV cache**: 길이에 따라 어텐션 비용과 KV cache 메모리가 늘어납니다. → [Prefill, decode](./prefill-decode.md)
- **모델 종류**: 생성용 LLM, 임베딩 모델, 번역 모델이 같은 블록으로 다르게 조립됩니다.

## 왜 필요한가

2017년 이전의 번역 모델은 [순환 신경망](./rnn.md)이나 [장단기 메모리](./lstm.md) 위에 [어텐션](./attention.md)을 붙인 형태였습니다. 순환 구조는 자리를 순서대로 계산해야 해서, 1,000 token짜리 학습 문장 하나에 1,000단계가 직렬로 필요했습니다. 2017년 Vaswani 등의 논문 "Attention Is All You Need"는 순환 구조를 빼고 [셀프 어텐션](./self-attention.md)만으로 번역 모델을 만들었습니다. 셀프 어텐션은 한 층에서 모든 자리를 동시에 계산하므로 GPU를 충분히 쓸 수 있고, 그래서 더 큰 모델을 더 큰 글로 학습할 수 있었습니다.

다만 셀프 어텐션만 쌓아서는 모델이 되지 않습니다. 어텐션은 value를 비율대로 섞는 계산이라, token 하나하나의 정보를 따로 가공하는 단계가 빠져 있습니다. 또 층을 깊게 쌓으면 학습 신호가 앞쪽 층까지 닿지 못하는 일이 생깁니다. → [기울기 소실](../deep-learning/gradient-vanishing.md) 트랜스포머는 섞는 단계(어텐션) 뒤에 가공하는 단계(FFN)를 두고, 더하기와 정규화로 감싸서 깊게 쌓을 수 있게 만든 구조입니다.

학습과 입력 읽기는 병렬이지만, 답을 생성할 때는 token을 하나 만들어야 다음 token의 입력이 생겨서 한 개씩 순서대로 만듭니다. → [Prefill, decode](./prefill-decode.md)

## 블록 하나

블록은 어텐션과 token마다 따로 계산하는 층(FFN, feed-forward network)을 차례로 지납니다. 어텐션이 token 사이를 섞는 곳이고, FFN은 token 벡터 하나씩을 작은 신경망(보통 두 층)에 넣어 가공하는 곳이라 token 사이는 섞지 않습니다. 각 단계의 출력을 입력에 더하는 길을 잔차 연결(residual)이라 하고, 더한 뒤 벡터 하나 안에서 평균을 빼고 표준편차로 나누는 것이 층 정규화입니다.

\[
y = \mathrm{LN}\big(x + \mathrm{Sublayer}(x)\big)
\]

작은 예로 오늘 token \([1,\ 0]\)을 따라갑니다. 앞 문서의 계산에서 어텐션 출력이 \([0.670,\ 0.330]\)이었으니, 입력에 더해 \([1.670,\ 0.330]\)입니다. 평균은 1이고 편차는 \(\pm 0.670\)이라 표준편차 0.670으로 나누면 \([1,\ -1]\)입니다. 이 벡터가 FFN을 지나 같은 방식으로 한 번 더 더해지고 정규화되면 블록 하나가 끝납니다.

블록은 새 벡터를 만들지 않고, 원래 벡터에 더할 변화량을 배웁니다. 더하기는 학습 신호를 그대로 통과시키는 길이라, 층을 깊이 쌓아도 앞 층까지 신호가 전달됩니다.

블록의 입력과 출력은 둘 다 (token 수 × 벡터 길이) 크기의 표입니다. 모양이 같아서 몇 개든 이어 쌓을 수 있습니다. 마지막 블록의 출력에서 생성용 LLM은 [다음 token](./next-token.md)의 점수를 만들고, 임베딩 모델은 벡터 하나로 요약합니다.

## 기억할 것 세 가지

### 모델 크기는 블록 수와 벡터 길이로 정해집니다

벡터 길이를 \(d\)라 하면 블록 하나의 파라미터는 약 \(12d^2\)입니다. \(d = 4096\), 32층이면 \(12 \times 4096^2 \times 32\)로 약 64억 개입니다. 7B급 모델이 이 규모입니다.

가중치 메모리는 파라미터 수에 파라미터 하나가 차지하는 바이트 수를 곱한 값입니다. 70억 개를 bfloat16(2바이트)으로 두면 약 14GB이고, 4비트 양자화(수 하나를 4비트로 줄여 저장)를 하면 약 3.5GB입니다. 서빙에는 여기에 KV cache와 계산용 메모리가 더 필요합니다.

### 문장 길이는 파라미터가 아니라 비용에 들어갑니다

입력이 길어져도 파라미터는 늘지 않습니다. 늘어나는 것은 어텐션 계산과 KV cache 메모리입니다. 같은 모델이어도 context를 길게 쓰면 느려지고 비싸집니다.

### 구조는 세 가지가 있습니다

encoder-only는 앞뒤를 모두 보고 읽는 구조로, 임베딩 모델과 reranker, 분류기가 여기에 속합니다. → [버트](./bert.md)

decoder-only는 앞만 보고 이어 쓰는 구조입니다. GPT 계열이나 Llama 계열 같은 지금의 LLM이 대부분 이쪽입니다. → [LLM](./llm.md)

encoder-decoder는 입력을 읽는 쪽과 출력을 만드는 쪽이 나뉩니다. 번역 모델이 대표적입니다.

<summary>더 깊이: 위치 인코딩, 파라미터 세기, 정규화 위치</summary>

- 위치 인코딩은 자리 번호마다 정해진 벡터를 token 벡터에 더합니다. 2017년 논문은 사인과 코사인으로 만들었고, 요즘 LLM은 query와 key를 위치에 따라 돌리는 방식(RoPE) 등을 많이 씁니다. 방식에 따라 안정적으로 다루는 최대 길이가 달라집니다.
- 파라미터 \(12d^2\)은 어텐션의 \(W_Q, W_K, W_V, W_O\)가 \(4d^2\), FFN이 가운데 칸 수를 \(4d\)로 두었을 때 \(2 \times d \times 4d = 8d^2\)여서 나옵니다. 바이어스와 정규화 파라미터, token 표(임베딩)는 뺀 값입니다.
- 2017년 블록은 더한 뒤에 정규화했고, 지금 LLM은 어텐션과 FFN 앞에서 먼저 정규화하는 구성이 흔합니다.
- 일부 큰 모델은 FFN을 여러 전문가(expert)로 나누고 token마다 몇 개만 쓰는 구조(MoE)입니다. 파라미터 수는 크지만 token당 계산은 그보다 적습니다.
