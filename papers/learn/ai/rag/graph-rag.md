GraphRAG는 색인 단계에서 LLM이 청크마다 개체와 관계를 뽑아 그래프를 만들고, 그래프를 커뮤니티로 묶어 요약을 미리 써 두는 RAG입니다. Microsoft 논문(Edge 외, 2024)이 제안했습니다.

에이전트를 만들 때 "이 문서 모음의 주요 주제는 무엇인가요?"처럼 청크 몇 개로 답할 수 없는 질문이 들어오면 고려합니다. 도입 전에 정할 것은 세 가지입니다.

- **질문 유형**: 사실 하나를 찾는 질문이 대부분인지, 전체를 묻는 질문이 섞여 있는지 봅니다.
- **색인 예산**: 청크마다 LLM을 호출하므로 비용과 시간을 감당할 수 있는지 봅니다.
- **갱신 주기**: 문서가 자주 바뀌는지 봅니다.

## 색인과 질의

벡터 검색은 청크 하나하나가 질문에 가까운지를 잽니다. 전체를 묻는 질문은 가장 닮은 청크가 따로 없고, 청크를 가로지르는 관계는 중간 청크가 질문과 닮지 않아서 놓칩니다. GraphRAG는 이 둘을 색인 때 미리 준비합니다.

```text
청크 → LLM으로 개체·관계 추출 → 그래프 → 커뮤니티 탐지 → 커뮤니티 요약
```

커뮤니티는 그래프에서 서로 촘촘히 이어진 노드 묶음입니다. 아래 그림에서 단계 버튼을 눌러 청크 6개가 그래프와 요약이 되는 모습을 따라가 보세요. 읽은 청크 수를 바꾸면 그래프가 자라는 모습이 보입니다. 이 그림의 코퍼스와 개체는 설명용입니다.

질의 방식은 세 가지입니다.

| 방식 | 하는 일 | 맞는 질문 |
| --- | --- | --- |
| 벡터 검색 | 기존 RAG처럼 닮은 청크 k개를 가져옵니다 | 한 청크에 답이 있는 질문 |
| 로컬 검색 | 질문 속 개체에서 출발해 이웃 개체, 관계, 원문 청크를 모읍니다 | 특정 개체나 청크를 가로지르는 관계 |
| 글로벌 검색 | 커뮤니티 요약을 모아 종합합니다 | 코퍼스 전체를 묻는 질문 |

## 기억할 것 네 가지

### 질문 종류에 따라 이득이 갈립니다

논문은 약 100만 token대 코퍼스 두 개에서 전체를 묻는 질문 125개씩으로 글로벌 검색과 벡터 RAG를 비교했습니다. 논문이 보고한 값으로 포괄성 승률이 72~83%, 다양성 승률이 62~82%였고, 직접성은 벡터 RAG가 모든 비교에서 앞섰습니다. 평가는 LLM 심판이 했고 두 코퍼스뿐이라 다른 도메인의 결과는 모릅니다. 모든 질문에서 낫다는 결과가 아닙니다.

### 색인 비용이 큽니다

벡터 RAG는 청크마다 임베딩만 만들면 되지만 GraphRAG는 청크마다 LLM 추출 호출이 들고 커뮤니티 요약에도 호출이 듭니다. 논문은 약 100만 token 코퍼스의 색인에 gpt-4-turbo로 281분이 걸렸다고 보고합니다. Microsoft 저장소도 색인이 비쌀 수 있다고 경고합니다. 작은 코퍼스로 먼저 비용을 재 보고 전체로 넓힙니다. 문서가 바뀌면 추출, 그래프, 커뮤니티, 요약이 줄줄이 영향을 받아 다시 만들어야 할 수 있습니다. 갱신이 잦다면 새 데이터를 이어 붙이는 증분 갱신을 내세운 LightRAG 같은 후속 연구도 살펴봅니다.

### 커뮤니티 수준이 요약의 깊이를 정합니다

수준은 C0(가장 위)부터 C3(가장 아래)까지 있습니다. 논문 Table 2에서 팟캐스트 코퍼스의 원문 청크는 1,014,611 token이고, 글로벌 검색에 쓸 요약은 C0가 26,657(2.6%), C3가 746,100(73.5%)입니다. 위쪽은 싸고 뭉뚱그려지며 아래쪽은 세부가 많지만 읽을 token도 늘어납니다.

### 개체 이름이 없으면 로컬 검색은 시작하지 못합니다

로컬 검색은 질문 속 개체를 그래프에서 찾아 출발합니다. "주요 주제는 무엇인가요?"처럼 개체 이름이 없는 질문은 시작점이 없어서 글로벌 검색이 필요합니다. 반대로 "지은은 어떤 일을 하나요?"처럼 개체 이름이 있는 질문은 로컬이나 벡터 검색이 더 싸고 직접적입니다.

- 논문의 실험은 청크 600 token, 오버랩 100 token을 씁니다. 긴 청크는 추출 호출이 줄지만 개체를 덜 뽑습니다. 부록에서 GPT-4가 600 token 청크에서 2,400 token 청크의 거의 두 배의 개체 언급을 뽑았다고 보고합니다.
- 추출 뒤에 LLM에게 놓친 개체가 없는지 되묻고 더 뽑게 하는 추가 추출(gleaning)을 씁니다. 같은 문자열일 때만 같은 개체로 합칩니다.
- 커뮤니티 탐지는 Leiden 알고리즘(Traag 외, 2019)을 계층적으로 씁니다. 요약은 아래 수준부터 위로 만듭니다.
- 글로벌 검색은 요약을 묶음으로 나눠 부분 답과 0~100 도움 점수를 만들고, 점수 0을 버린 뒤 모아 최종 답을 만듭니다. 논문은 이 모든 단계에 8k token context window를 썼습니다.
- 로컬 검색은 Microsoft 구현 문서에 있습니다. 로컬에 커뮤니티 정보를 더한 DRIFT 검색도 있습니다.
- LightRAG(Guo 외, 2024)는 그래프와 벡터 표현을 결합하고 증분 갱신을 제안합니다. HippoRAG(Gutiérrez 외, NeurIPS 2024)는 LLM, 지식 그래프, Personalized PageRank를 엮어 다중 홉 질의응답에서 기존 최고 방법보다 최대 20% 앞섰다고 보고합니다.
- Han 외(2025)는 단일 홉과 세부 사실은 RAG가, 다중 홉과 추론은 GraphRAG가 유리했고 둘을 고르거나 합치는 전략이 성능을 높였다고 보고합니다.

개체와 관계를 세 쌍으로 적는 방법은 [지식 그래프](./knowledge-graph.md), 앞 단계는 [검색](./retrieval.md), [RAG](./index.md)입니다. 개체를 뽑는다는 점은 [개체명 인식](../nlp/ner.md)과 닮았지만, NER은 token마다 표지를 맞히는 분류이고 GraphRAG는 prompt로 LLM이 글로 뽑습니다.
