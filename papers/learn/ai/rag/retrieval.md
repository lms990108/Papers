검색은 질문과 가까운 청크 k개를 고르는 단계입니다. 청크마다 임베딩을 미리 만들어 두고, 질문 임베딩과의 [코사인 유사도](../nlp/cosine-similarity.md)가 큰 순서로 k개를 남깁니다.

에이전트를 만들 때 이 단계에서 고르는 설정이 답의 품질을 크게 좌우합니다.

- **임베딩 모델**: 청크와 질문을 벡터로 바꿀 모델을 고릅니다.
- **top-k**: prompt에 몇 개를 붙일지 정합니다.
- **검색 방식**: 임베딩만 쓸지, 키워드 검색을 같이 쓸지 고릅니다.
- **임계값**: 점수가 낮으면 "찾지 못함"으로 처리하는 기준입니다.

## 왜 필요한가

[청킹](./chunking.md)이 끝나면 청크가 수천에서 수백만 개 쌓입니다. 질문 하나에 답하려면 그중 몇 개만 prompt에 붙여야 합니다. 무엇을 기준으로 고를까요?

가장 단순한 방법은 키워드 일치입니다. 질문의 단어가 청크에 글자 그대로 있으면 고릅니다. 사용자가 "휴가 일수가 어떻게 되나요?"라고 묻는데 규정에는 "연차는 15일입니다"라고 적혀 있다면 겹치는 단어가 하나도 없습니다. 사람은 휴가와 연차가 같은 말임을 알지만 글자 비교는 모릅니다. 사용자는 규정 문서의 표현을 모르고 묻는 것이 보통이라 이런 어긋남이 자주 납니다.

[임베딩](../nlp/embedding.md)은 이 한계를 줄입니다. 뜻이 가까운 글은 가까운 벡터가 되므로, "휴가 일수"와 "연차는 15일"은 글자가 달라도 가깝게 나오는 것이 보통입니다. 검색은 질문을 벡터로 바꾸고, 미리 만들어 둔 청크 벡터 중 질문과 가장 가까운 k개를 고르는 일입니다. 가까움은 방향이 얼마나 같은지, 곧 [코사인 유사도](../nlp/cosine-similarity.md)로 잽니다. 글자 일치가 잘하던 일(정확한 오류 번호 찾기)은 임베딩이 오히려 약해서, 아래에서 키워드 검색과의 구분을 다룹니다.

## 계산

코사인은 두 벡터의 방향이 같을수록 1에 가깝고 직각이면 0인 값입니다.

\[
\cos(q, d) = \frac{q \cdot d}{\|q\| \, \|d\|}
\]

\(q\)는 질문 벡터, \(d\)는 청크 벡터입니다. 식이 순위를 어떻게 가르는지 작은 예로 봅니다. 임베딩이 2차원이라고 합시다. 실제 임베딩은 수백~수천 차원입니다. 질문과 청크 세 개의 코사인은 이렇게 나옵니다.

| 대상 | 벡터 | 코사인 |
| --- | --- | --- |
| 질문 | (1, 0) | — |
| 청크 A (연차) | (1, 0) | 1 |
| 청크 B (병가) | (0, 1) | 0 |
| 청크 C (연차와 병가) | (1, 1) | 0.707 |

A는 질문과 같은 방향이라 1, B는 직각이라 0입니다. C는 (1, 1)이라 질문과 45도를 이루고, \(1 / \sqrt{2} = 0.707\)입니다. 그래서 k=1이면 A만, k=2이면 A와 C가 남습니다.

코드로는 이 정도입니다. 벡터를 길이 1로 맞춰 두면 코사인이 내적과 같아져서(아래 details 참고) 행렬 곱 한 번으로 모든 청크의 점수가 나옵니다.

```python
chunk_vecs = ...                 # (청크 수, 차원). 미리 계산해 두고 길이 1로 정규화
q = embed(question)
q = q / np.linalg.norm(q)        # 질문 벡터 하나만 매번 새로 만든다
scores = chunk_vecs @ q          # 청크마다 코사인 점수
top = np.argsort(-scores)[:k]    # 점수가 큰 순서로 k개
```

청크 벡터는 문서가 바뀔 때만 다시 계산하고, 질문마다 새로 만드는 것은 질문 벡터 하나입니다. 청크가 수백만 개일 때 가까운 벡터를 빨리 찾는 방법은 [벡터 인덱스](./vector-index.md)에서 그림으로 봅니다.

## 기억할 것 네 가지

### k는 정답이 들어오는 최소값에서 시작합니다

k가 작으면 정답 청크를 놓치고, 크면 prompt가 길어지며 무관한 청크가 섞입니다. 질문 수십 개에 정답 청크를 표시해 두고, k를 바꿔 가며 정답이 상위 k에 들어오는 비율(recall@k)을 재면 시작점이 나옵니다. 감으로 5나 10을 고르지 않습니다.

### 질문과 청크는 같은 임베딩 모델로 만듭니다

모델마다 벡터 공간이 다릅니다. 차원이 같아도 한 모델의 질문 벡터와 다른 모델의 청크 벡터는 비교할 수 없습니다. 임베딩 모델을 바꾸면 모든 청크를 다시 임베딩하고 색인을 새로 만듭니다.

### 오류 코드나 고유명사에는 키워드 검색이 필요합니다

키워드 검색은 질문의 단어가 청크에 글자 그대로 들어 있는지 보는 방식입니다. 임베딩은 표현이 달라도 뜻이 가까우면 찾습니다. "휴가 일수"를 물어도 "연차는 15일"을 찾는 식입니다. 반대로 `ERR-4021` 같은 오류 번호는 글자가 똑같아야 의미가 있는데 임베딩이 비슷한 번호(`ERR-4012`)를 올릴 수 있습니다. 둘을 함께 쓰는 방법은 [고급 RAG](./advanced-rag.md)의 hybrid search입니다.

### 점수는 확률도 정답 보증도 아닙니다

코사인이 0.9여도 그 청크에 답이 있다는 뜻은 아닙니다. 점수의 절댓값은 임베딩 모델마다 분포가 달라서 "0.7 이상이면 쓴다" 같은 임계값은 내 데이터로 직접 재서 정합니다. 임계값이 없으면 검색 결과가 전부 무관할 때도 상위 k개가 prompt에 들어갑니다.

<summary>더 깊이: 벡터 정규화와 점수 계산</summary>

- 벡터를 길이 1로 정규화해 두면 코사인은 내적과 같아서 내적으로 더 빠르게 계산할 수 있습니다. 쓰는 임베딩 모델이 정규화된 벡터를 내는지 문서에서 확인합니다.
- 코사인 값의 범위는 -1에서 1입니다. 모델에 따라 서로 무관한 문장끼리도 꽤 높은 값이 나옵니다. 정답 청크와 무관한 청크의 점수 분포를 직접 찍어 보면 임계값을 잡을 수 있습니다.
- 키워드 검색(BM25)은 단어 빈도와 희귀도로 점수를 매깁니다. 식과 계산은 [고급 RAG](./advanced-rag.md)에서 다룹니다.
- 고른 청크는 [그라운딩](./grounding.md)에서 질문과 이어 붙입니다.
