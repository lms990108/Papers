질문이 오면 [청킹](./chunking.md)으로 나눠 둔 조각 가운데, 질문과 가까운 것만 고릅니다. 이 고르는 단계가 **검색**(retrieval)입니다. 고른 개수를 \(k\)라고 두면, 점수가 높은 조각 \(k\)개를 남기는 식이 됩니다.

가까운지를 재는 방법은 여러 가지입니다. 단어가 겹치는지를 볼 수도 있고, [임베딩](../nlp/embedding.md)으로 만든 수 목록의 [코사인 유사도](../nlp/cosine-similarity.md)를 볼 수도 있습니다. RAG에서 자주 쓰는 쪽은 후자입니다. 조각마다 수 목록을 미리 만들어 두고, 질문이 오면 같은 방식으로 질문의 수 목록을 만든 뒤 코사인이 큰 조각을 고릅니다.

:::tip[한눈에 보기]
검색은 질문과 가까운 청크 \(k\)개를 고르는 단계입니다.

- 조각마다 수 목록을 만들어 두면, 질문 목록과의 [코사인 유사도](../nlp/cosine-similarity.md)로 순위를 매길 수 있습니다.
- \(k\)가 작으면 근거가 얇고, \(k\)가 크면 생성 입력이 길어집니다.
- 단어 일치 검색은 같은 말이 있을 때 강하고, 임베딩 검색은 말이 달라도 뜻이 가까우면 올라올 수 있습니다.
- 1등 조각이 틀리면 [근거를 붙이기](./grounding.md) 이후의 답도 흔들리기 쉽습니다.

선수 지식은 [청킹](./chunking.md), [임베딩](../nlp/embedding.md), [코사인 유사도](../nlp/cosine-similarity.md)입니다. 다음으로 보면 좋은 글은 [근거를 붙이기](./grounding.md)입니다.
:::

## 동기

조각이 1,000개일 때 전부 생성 입력에 넣을 수는 없습니다. 질문이 “연차는 며칠인가요?”이면 연차 문단만 있으면 됩니다. 검색은 그 1,000개 가운데 위의 \(k\)개를 남기는 체입니다.

## 임베딩으로 가깝기

조각 \(i\)의 수 목록을 \(d_i\), 질문의 수 목록을 \(q\)라고 합시다. 코사인 유사도는 다음과 같습니다.

\[
\cos(q, d_i) = \frac{q \cdot d_i}{\|q\| \, \|d_i\|}
\]

값이 클수록 같은 방향에 가깝습니다. 모든 \(i\)에 대해 이 값을 구한 뒤, 큰 순으로 \(k\)개를 고릅니다. 조각의 \(d_i\)는 문서가 바뀌기 전에는 다시 계산할 필요가 없습니다. 질문이 올 때마다 새로 만드는 것은 \(q\)입니다.

짧은 예입니다. 길이를 2로 둔 목록입니다. 실제 목록은 훨씬 깁니다.

| 대상 | 목록 | \(\cos(q, \cdot)\) |
| --- | --- | --- |
| 질문 \(q\) | 1, 0 | — |
| 조각 A (연차) | 1, 0 | 1 |
| 조각 B (병가) | 0, 1 | 0 |
| 조각 C (연차·병가) | 1, 1 | \(1/\sqrt{2} \approx 0.707\) |

\(k = 1\)이면 A만 남습니다. \(k = 2\)이면 A와 C가 남습니다. B는 질문에 수직이라 아래에 있습니다.

```python
import math

q = [1.0, 0.0]
docs = {"A": [1.0, 0.0], "B": [0.0, 1.0], "C": [1.0, 1.0]}

def cos(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(x * x for x in b))
    return dot / (na * nb)

scores = {name: cos(q, v) for name, v in docs.items()}
print({k: round(v, 3) for k, v in scores.items()})
print(sorted(scores, key=scores.get, reverse=True)[:2])
```

```text
{'A': 1.0, 'B': 0.0, 'C': 0.707}
['A', 'C']
```

## 단어 일치와 비교

“연차”라는 글자가 조각에 있는지만 보면, 동의어·다른 표현은 놓칩니다. 질문이 “휴가 일수”이고 조각이 “연차는 15일”이면 단어가 안 겹칠 수 있습니다. 임베딩이 두 문장을 비슷한 방향으로 두었다면 코사인은 올라갑니다. 반대로, 고유명사·번호처럼 **같은 토큰이 꼭 필요한 질문**에서는 단어 일치가 더 직접적일 때가 있습니다. 둘을 섞어 쓰는 경우도 많지만, 이 글에서는 점수가 코사인인 쪽만 수로 밟습니다.

## top-k

남기는 개수 \(k\)가 **top-k**입니다. \(k = 1\)이면 근거가 한 조각입니다. 그 조각이 틀리면 대안이 없습니다. \(k = 5\)이면 생성 입력에 다섯 조각이 들어가고, 칸과 비용이 늘어납니다. \(k\)는 검색 정확도와 입력 길이 사이의 선택입니다. 손실 식에서 미분되어 나오는 값이 아닙니다.

순위만 쓰고 점수 절대값은 버리는 경우가 많습니다. 위 예에서 A가 1, C가 0.707이어도, \(k = 2\)면 둘 다 붙입니다. 점수가 낮아도 \(k\) 안이면 들어갑니다.

## 헷갈리기 쉬운 점

**검색 점수는 답의 정답이 아닙니다.** 코사인 1에 가까운 조각이어도, 질문의 답이 그 안에 없을 수 있습니다. 가깝기는 방향이 비슷하다는 뜻이지, “15일”이 들어 있다는 보장은 아닙니다.

**임베딩 표는 생성 LLM과 다른 모델일 수 있습니다.** 조각을 수로 바꾸는 망과 답을 잇는 망을 같이 쓸 수도 있고, 따로 둘 수도 있습니다. RAG라는 말 자체가 한 모델을 가리키지는 않습니다.

**\(k\)를 늘린다고 해서 항상 답이 좋아지지는 않습니다.** 무관한 조각이 같이 들어가면, 생성은 그 조각을 읽을 수 있습니다.

## 연습 문제

1. 위 표에서 \(k = 1\)이면 어떤 조각이 남나요? \(k = 3\)이면요?
2. 조각 B의 목록이 \([0,\ 1]\)일 때 질문 \([1,\ 0]\)과의 코사인은 얼마인가요?
3. 문서 조각의 수 목록을 질문마다 다시 계산해야 하나요?

<details>
<summary>정답</summary>

1. \(k = 1\)이면 A, \(k = 3\)이면 A·C·B 모두입니다.
2. 곱의 합이 0이므로 코사인은 0입니다.
3. 아니요. 조각 목록은 문서가 바뀔 때 갱신하면 되고, 질문마다 새로 만드는 것은 질문 목록입니다.

</details>
