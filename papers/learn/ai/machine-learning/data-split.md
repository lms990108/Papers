데이터를 학습(train), 검증(validation), 시험(test)으로 나누는 것은 모델이 새 입력에서 얼마나 맞히는지를 속지 않고 재려는 방법입니다.

에이전트를 만들 때는 모델을 직접 학습하지 않아도 이 구분이 필요합니다.

- **prompt 튜닝**: prompt, temperature, 검색 chunk 크기, top-k는 사람이 고르는 값입니다. 이 값을 평가 세트로 고르면 그 세트는 검증 세트입니다.
- **최종 점수 보고**: 고르는 데 쓰지 않은 세트로 한 번 재야 실제 수준이 나옵니다.
- **fine-tuning**: 평가 질문이 학습 데이터에 섞이면 점수가 거짓이 됩니다.
- **벤치마크 점수 읽기**: 공개 벤치마크가 모델의 학습 데이터에 들어갔을 수 있다는 의심(오염)도 같은 문제입니다.

## 왜 필요한가

모델을 만들었으면 새 입력에서 얼마나 맞히는지 알아야 합니다. 가장 쉬운 방법은 학습에 쓴 데이터로 다시 재는 것입니다. 이 방법은 외운 모델과 제대로 배운 모델을 구별하지 못합니다.

예를 들어(장난감 설정입니다) 학습 리뷰 열 개를 표로 통째로 외우고 표에 없는 리뷰에는 무조건 "긍정"이라고 답하는 모델이 있다고 합시다. 새 리뷰의 절반이 긍정이면 이렇게 됩니다.

```text
                    오류율
학습 데이터로 잼       0
새 리뷰로 잼          0.5   (찍는 것과 같다)
```

점수는 0인데 실제 성능은 동전 던지기입니다. [선형 회귀](./linear-regression.md)에서 학습 오차 0이 목표가 아니라고 한 이유와 같습니다.

그래서 학습에 쓰지 않은 데이터를 따로 떼어 두고 그것으로 잽니다. 그런데 떼어 둔 데이터도 점수를 보고 나면 사람이 움직입니다. prompt나 learning rate를 그 점수에 맞춰 고칩니다. 점수를 보며 고르는 순간 그 데이터는 선택에 쓰인 데이터가 되고, 점수는 새 입력에서보다 높게 나오기 쉽습니다. [회귀](./regression.md)에서 본 "1등은 다시 재면 내려간다"가 이 경우입니다.

이 때문에 값을 고르는 데 쓰는 데이터와 최종 점수를 내는 데이터를 따로 둡니다. 학습, 검증, 시험 세 가지가 여기서 나옵니다.

## 세 집합의 역할

리뷰 열 개를 여섯, 둘, 둘로 나눈다고 합시다.

```text
집합   개수   쓰는 때
학습    6    파라미터(가중치)를 움직일 때
검증    2    learning rate 같은, 사람이 고르는 값을 정할 때
시험    2    모든 선택이 끝난 뒤 딱 한 번
```

학습 6개로만 가중치를 움직입니다. 학습 오류가 0이어도 검증 2개를 모두 틀리면, 모델이 학습 문장을 외운 것으로 볼 수 있습니다. 이때 검증 오류율은 1(둘 다 틀림)이고, 보고할 값은 학습 오류 0이 아니라 이쪽입니다.

학습을 시작하기 전에 사람이 고르는 값이 하이퍼파라미터(hyperparameter)입니다. learning rate(한 번에 가중치를 얼마나 고칠지 정하는 수), 정칙화 계수 \(\lambda\)(가중치가 커지지 않게 누르는 강도), 은닉 유닛(앞 문서 XOR 예의 첫 단계 \(h_1,\ h_2\))의 수가 그 예입니다. → [경사하강법](../deep-learning/gradient-descent.md), [용량과 정칙화](../deep-learning/capacity.md)

에이전트에서는 prompt 문구와 top-k가 여기에 해당합니다. 값을 검증으로 고른 뒤, 시험은 그다음에만 잽니다. 모델을 직접 학습하지 않으면 학습 집합이 없으니, 고르는 용도와 최종 점수용 둘로 나눕니다. 6, 2, 2는 예일 뿐 정해진 비율이 아닙니다. 다만 아래 표준오차에서 보듯 검증과 시험이 너무 작으면 점수가 흔들립니다.

## 후보를 많이 고르면 점수가 부풀려집니다

검증 세트로 값을 고를 때 생기는 문제를 봅니다. 후보는 고르려는 prompt 문구나 하이퍼파라미터 값입니다. 진짜 정확도가 모두 0.5인 후보, 곧 찍는 것과 같은 후보가 20개 있다고 합시다. 문장 20개로 재면 후보마다 점수가 0.5 둘레에서 흔들립니다. 가장 높은 것을 고르면 0.5보다 높게 나옵니다.

1000번 반복해 평균을 내면 이렇습니다. 처음 두 줄은 후보를 고를 때 쓴 세트에서 받은 점수이고, 마지막 줄만 처음 보는 세트의 점수입니다.

```text
같은 세트로 고른 후보의 점수     0.709
검증으로 고른 후보의 검증 점수   0.706
그 후보를 새 시험으로 잰 점수    0.498
```

동전 던지기와 다를 바 없는 후보가 70%를 받았습니다. 후보 수와 문장 수를 바꿔 보면서 부풀림이 어떻게 달라지는지 보세요.

<SelectionBias />

후보가 많을수록, 문장이 적을수록 부풀림이 커집니다. prompt를 스무 번 고쳐 가며 같은 세트로 점수를 확인하는 일은 후보 20개를 같은 세트로 고르는 일과 같습니다.

## 기억할 것 세 가지

### 시험은 한 번만 봅니다

시험 점수를 보고 prompt나 하이퍼파라미터를 바꾸면 그 세트는 검증 세트가 됩니다. 바꿀 때마다 시험 문항의 정보가 선택에 새어 듭니다. 점수를 본 뒤 또 바꿔야 한다면 새 시험 세트를 따로 만들어야 합니다.

### 같은 것이 양쪽에 있으면 시험이 아닙니다

같은 영화의 리뷰가 학습과 시험에 모두 있으면 영화 이름을 외워도 맞힙니다. 에이전트에서는 같은 문서에서 나온 질문이 양쪽에 있거나, 평가 문항을 few-shot 예시로 prompt에 넣은 경우가 같은 누수입니다. 시간순으로 모은 데이터는 나중 것을 시험에 두는 편이 실제 사용에 가깝습니다.

### 작은 평가 세트는 숫자가 흔들립니다

시험 수 \(n\)과 오류 비율 \(p\)에서, 새 세트를 뽑았을 때 오류가 흔들리는 폭(표준오차)은 대략 다음과 같습니다.

\[
\sqrt{p(1-p)/n}
\]

평가 문항 100개에서 정확도 90%이면 표준오차가 \(\sqrt{0.9 \times 0.1 / 100} = 0.03\), 곧 3%p입니다. 90%와 93%의 차이는 방법의 우열로 읽기 어렵습니다. 1000개로 늘려도 약 0.95%p입니다. 문항을 10배로 늘려야 폭이 약 3분의 1로 줄어듭니다.

<summary>더 깊이: 교차 검증과 나누는 기준</summary>

- 데이터가 적으면 검증 몇 개로 값을 고르기가 불안합니다. 교차 검증(cross-validation)은 학습용 데이터를 \(k\)묶음으로 나누고 한 묶음씩 돌아가며 검증으로 씁니다. 나머지 \(k-1\)묶음으로 학습하고 \(k\)번의 검증 오류를 평균합니다. 안정적이지만 학습을 \(k\)번 해야 합니다.
- 열 개에서 시험 둘을 떼면 남은 여덟 개를 4묶음으로 나눌 때 묶음마다 두 문장입니다. 학습 6, 검증 2로 4번 학습하고, 시험 둘은 끝에 한 번 씁니다.
- 레이블 비율이 한쪽으로 치우친 데이터에서는 학습, 검증, 시험의 비율을 같게 맞춰 나눕니다. 같은 문서나 같은 작가가 여러 건이면 묶음 단위로 통째로 나눕니다.
- [MNIST](./mnist.md)는 학습 60,000장과 시험 10,000장이 작가가 겹치지 않게 정해져 있습니다. 10,000장에서 100장을 틀리면 오류 1%이고 표준오차는 약 0.1%p입니다.
- learning rate \(\eta\)를 검증으로 고르는 예는 오차 \((w-3)^2\)에서 \(w = 0\)부터 한 번 갱신하면 \(w = 6\eta\)가 됩니다. \(\eta = 0.1\)이면 오차가 9에서 5.76으로 내려가고, \(\eta = 1\)이면 \(w = 6\)이라 오차가 9로 그대로입니다. 검증에서 오차가 작은 0.1을 고릅니다.
- 정답 하나를 당기는 오차와 정답과 오답의 차이를 줄이는 오차의 비교는 [판별 학습](./discriminative-learning.md)에 있습니다.
