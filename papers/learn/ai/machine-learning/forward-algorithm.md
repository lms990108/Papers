전방 알고리즘은 격자의 모든 경로의 확률을 더한 값을, 경로를 나열하지 않고 노드마다 도착 확률을 합해 가며 구하는 동적 계획법입니다. [비터비](./viterbi.md)의 max를 sum으로 바꾼 것입니다. 지금 에이전트 개발에는 직접 쓰이지 않는 배경 지식이지만, 로그 영역에서 쓰는 logadd는 ML 코드 곳곳에 있는 `logsumexp`와 부호만 다른 계산입니다. 소프트맥스의 분모를 넘치지 않게 계산하는 방법과 같은 원리이고, CTC 손실도 정렬 경로를 이 방식으로 전부 더합니다.

## 왜 필요한가

관측열이 모델에서 얼마나 그럴듯한지, 곧 그 열이 나올 확률 자체가 필요한 곳이 있습니다. 음성 인식에서 단어마다 HMM을 두고 소리가 어느 단어 모델에서 더 그럴듯한지 비교하는 경우, 그리고 정답 레이블이 나올 수 있는 모든 정렬의 확률을 합해 손실로 쓰는 CTC가 그렇습니다. 상태는 보이지 않아서 관측열은 어느 상태열에서든 나올 수 있고, 열의 확률은 그 모든 상태열의 확률을 더한 값입니다.

[은닉 마르코프 모델](./hmm.md)에서는 여덟 상태열을 모두 나열해 더했습니다. 상태열이 \(N^T\)개라 길어지면 불가능합니다. [비터비](./viterbi.md)의 최댓값으로 대신할 수도 있지만 합과 같지 않습니다. 아래 예에서 최댓값 0.01296은 합 0.03564의 약 36%입니다. 모델 둘을 비교할 때 이 차이가 순위를 바꿀 수 있습니다. 장난감 예로 모델 A는 확률 0.02인 경로가 하나이고, 모델 B는 확률 0.008인 경로가 다섯 개라고 합시다. 최댓값은 A(0.02)가 크지만 합은 B(0.04)가 큽니다. 경로가 여럿으로 갈라지는 모델일수록 최댓값은 확률을 낮게 봅니다.

전방 알고리즘은 비터비와 같은 격자를 같은 순서로 채우되 후보 중 최댓값 대신 후보의 합을 남깁니다. 경로를 나열하지 않고도 합이 정확히 나오고 계산량도 \(T N^2\)으로 같습니다. 이 합은 [판별 학습](./discriminative-learning.md)에서 정답과 오답의 비용 차이를 만들 때도 쓰입니다.

## 계산

날씨 격자를 그대로 씁니다. 격자를 왼쪽에서 오른쪽으로 채워서 전방(forward)이라 부릅니다. \(\alpha_t(s)\)는 시각 \(t\)까지의 관측을 내면서 상태 \(s\)에 도착하는 모든 경로의 확률 합입니다.

\[
\alpha_1(s) = \pi_s B_s(o_1)
\qquad
\alpha_t(s) = \Bigl( \sum_{r} \alpha_{t-1}(r) A_{r s} \Bigr) B_s(o_t)
\]

관측 (산책, 쇼핑, 청소)로 계산합니다. 비터비가 후보 중 가장 큰 것만 남기는 자리에서 후보를 모두 더합니다. 노드 하나로 들어오는 경로가 여럿이어도 그 노드에서 끝까지 가는 확률은 같으므로, 도착 확률의 합 하나로 접어 두어도 최종 합이 바뀌지 않습니다.

```text
시각 1   맑음 0.36                      비 0.04
시각 2   맑음 (0.36×0.7 + 0.04×0.4)×0.3 = 0.0804
         비   (0.36×0.3 + 0.04×0.6)×0.4 = 0.0528
시각 3   맑음 (0.0804×0.7 + 0.0528×0.4)×0.1 = 0.00774
         비   (0.0804×0.3 + 0.0528×0.6)×0.5 = 0.0279
```

마지막 두 값을 더한 \(0.00774 + 0.0279 = 0.03564\)가 관측열의 확률입니다. [은닉 마르코프 모델](./hmm.md)에서 여덟 경로를 나열해 더한 값과 같고, 비터비의 최댓값 0.01296은 그 약 36%입니다. 마지막 값을 합으로 나누면 관측을 본 뒤 마지막 날이 맑음일 확률 0.217, 비일 확률 0.783도 얻습니다.

## 비용 영역: logadd

비용(음의 로그 확률)에서는 min 자리에 logadd가 옵니다. 확률은 \(e^{-\text{비용}}\)이므로 확률의 합은 \(e^{-\text{비용}}\)의 합이고, 이를 다시 비용으로 돌리면 \(-\log\)가 붙습니다.

\[
\mathrm{logadd}(x_1, \ldots, x_n) = -\log \sum_i e^{-x_i}
\]

경로 비용이 3과 7이면 \(e^{-3} + e^{-7} \approx 0.0507\)이고 logadd는 약 2.98입니다. 싼 경로가 압도하면 비터비 비용과 거의 같습니다. 비용이 3과 3.2이면 \(0.0498 + 0.0408 = 0.0906\)이고 logadd는 약 2.40으로, 둘 중 작은 3보다 낮습니다. 여러 경로가 같은 결과(같은 레이블)로 읽히면 그 레이블의 총비용이 더 싼 길 하나보다 낮아집니다. 비용 2.7짜리 다른 레이블과 비교하면 경로를 하나씩 볼 때는 다른 레이블이 이기고, 경로를 합치면 3과 3.2의 레이블이 이깁니다.

## 코드에서는

확률 영역의 전방은 [비터비](./viterbi.md) 코드(`pi`, `A`, `B`는 같은 표)에서 `max`를 `sum`으로 바꾼 꼴입니다.

```python
def forward(obs):
    a = {s: pi[s] * B[s][obs[0]] for s in pi}
    for o in obs[1:]:
        a = {s: sum(a[r] * A[r][s] for r in pi) * B[s][o] for s in pi}
    return sum(a.values())

forward(["산책", "쇼핑", "청소"])   # 0.03564
```

비용 영역에서 쓰는 logadd는 PyTorch의 `torch.logsumexp`와 부호만 다릅니다. 비용 텐서 `x`에서 logadd는 `-torch.logsumexp(-x, dim=0)`이고, `logsumexp`는 아래 마지막 항목의 방법으로 넘치지 않게 계산해 줍니다. CTC 손실(`torch.nn.CTCLoss`)은 정렬 경로 전체의 합을 이런 방식으로 구해 손실로 씁니다.

## 기억할 것 세 가지

### 합은 최상의 상태열을 알려 주지 않습니다

전방은 합만 내고 어느 경로가 기여했는지 남기지 않습니다. 상태열이 필요하면 비터비를 씁니다. 위 예에서 전방은 0.03564를, 비터비는 맑음-비-비를 줍니다.

### logadd는 평균도 최솟값도 아닙니다

같은 비용 3인 경로가 둘이면 \(3 - \ln 2 = 2.307\)입니다. 평균 3과도 최솟값 3과도 다르고, 경로 수가 늘수록 계속 낮아집니다. 비용이 같은 경로가 \(k\)개이면 \(\ln k\)를 뺀 값입니다.

### 넘치지 않게 계산합니다

비용이 1000쯤이면 \(e^{-1000}\)은 컴퓨터에서 0이 되어 logadd가 무한대가 됩니다. 가장 작은 비용 \(m\)을 밖으로 빼서 \(m - \log \sum_i e^{-(x_i - m)}\)로 계산하면 지수 안이 0 이하라 문제가 없습니다. \(\mathrm{logadd}(1000, 1001) = 999.687\)입니다. 소프트맥스에서 가장 큰 점수를 빼고 계산하는 것과 같은 방법입니다.

<summary>더 깊이: 학습에서의 역할</summary>

- 정답 레이블과 맞는 경로만 남긴 그래프의 전방 비용에서 제약 없는 그래프의 전방 비용을 빼면 판별 학습 오차입니다. 두 값이 같으면 오차는 0입니다. [판별 학습](./discriminative-learning.md)에서 다룹니다.
- 비터비는 선택된 호만 기울기 1을 받지만, 전방은 모든 호가 받고 값이 큰 경로의 호가 더 크게 받습니다. logadd를 \(x_i\)로 미분하면 \(e^{-x_i} / \sum_j e^{-x_j}\)이고, 비용 3과 7이면 약 0.982와 0.018, 3과 3.2이면 약 0.55와 0.45입니다. 한 경로가 압도하면 비터비의 기울기에 가까워집니다.
- Baum-Welch는 이 전방 값과 끝에서 오는 후방 값으로 각 호가 얼마나 쓰였는지 나눕니다.
- 전방 값 \(\alpha_t(s)\)는 \(o_1, \ldots, o_t\)와 상태 \(s\)의 결합 확률이라 시각이 갈수록 작아집니다. 조건부 확률로 읽으려면 시각마다 합으로 나눕니다.
