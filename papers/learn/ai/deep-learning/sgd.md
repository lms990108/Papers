확률적 경사하강법(SGD)은 학습 데이터 전체의 평균 기울기를 기다리지 않고, 표본 하나나 mini-batch(표본 몇 개를 묶은 것)의 기울기로 파라미터를 바로 고치는 방법입니다.

fine-tuning 설정의 batch size, epochs가 이 방법의 설정값입니다. epoch는 학습 데이터를 한 번씩 다 쓰는 일이고, epochs와 batch size가 정하는 것은 갱신 횟수입니다. 요즘 LLM 학습의 optimizer(파라미터를 고치는 규칙)는 대부분 Adam 계열이지만, mini-batch마다 갱신한다는 점은 같습니다.

## 왜 필요한가

[경사하강법](./gradient-descent.md)은 한 걸음마다 기울기를 구합니다. 그런데 학습의 오차는 학습 쌍 전체의 평균이라서, 한 걸음을 가려면 쌍을 전부 훑어야 합니다. 쌍이 100만 개이면 파라미터를 한 번 고치는 데 순방향과 [역전파](./backpropagation.md)를 100만 번씩 해야 합니다. 걸음이 1,000번 필요하면 10억 번입니다(예).

학습 데이터에는 비슷한 표본도 많습니다. 정답이 거의 같은 쌍 열 개의 기울기를 모두 구해 평균을 내도, 그중 하나만 봤을 때와 가리키는 쪽이 거의 같습니다. 한 걸음을 위해 전부 읽는 것은 낭비입니다.

SGD는 일부만 보고 바로 걸음을 내딛습니다. 표본 하나의 기울기는 전체 평균과 다릅니다. 하지만 표본을 치우침 없이 뽑으면 기울기들의 평균이 전체 평균과 같아서, 걸음 하나는 거칠어도 길게 보면 같은 쪽으로 갑니다. 같은 계산량으로 걸음을 훨씬 많이 옮기는 셈입니다.

## 계산

[경사하강법](./gradient-descent.md)의 오차는 하나였지만, 실제 학습의 오차는 학습 쌍 전체의 평균이라서 한 번 고치려면 쌍을 모두 훑어 평균 기울기를 구해야 합니다. SGD는 이 평균을 기다리지 않고 쌍 하나씩 보며 고칩니다. 학습 쌍이 네 개이고 정답이 3, 3, 1, 3이라고 합시다. 파라미터는 \(w\) 하나, 표본 \(p\)의 오차는 \((w - t_p)^2\)입니다. \(w = 0\), learning rate 0.1에서 시작합니다.

\[
w \leftarrow w - \epsilon\, \frac{\partial E^{p}}{\partial w}
\]

표본 하나의 기울기는 \(2(w - t_p)\)입니다. 네 쌍을 한 쌍씩 보며 갱신하면 다음과 같습니다. 표의 기울기는 그 갱신에 쓴 값이고, 예를 들어 세 번째는 \(2(1.08 - 1) = 0.16\)입니다.

```text
갱신   정답   기울기    갱신 뒤 w
1      3     -6        0.6
2      3     -4.8      1.08
3      1      0.16     1.064
4      3     -3.872    1.4512
```

세 번째 갱신에서 \(w\)가 줄었습니다. 정답이 1인 쌍이 \(w\)를 왼쪽으로 밀었기 때문입니다. 네 쌍을 모아서 평균 기울기 \((-6 - 6 - 2 - 6)/4 = -5\)로 한 번만 고치면 \(w = 0.5\)입니다. 한 epoch 뒤 SGD는 1.4512이고 batch 방식은 0.5입니다. 기울기 계산은 둘 다 네 번이고, 갱신 네 번에 나누었느냐 한 번에 모았느냐가 다릅니다. 네 쌍 전체의 오차를 가장 작게 하는 \(w\)는 정답의 평균 2.5라서, 같은 계산량으로 SGD가 목표에 더 가까워졌습니다.

## 기억할 것 네 가지

### 갱신 횟수는 데이터 수, batch size, epochs로 정해집니다

갱신 횟수는 (데이터 수 ÷ batch size) × epochs입니다. 예시 1,000개, batch size 8, epochs 3이면 \(1000 / 8 \times 3 = 375\)번입니다. batch size를 32로 키우면 약 4분의 1로 줄어듭니다. 같은 epochs라도 batch size가 크면 갱신은 적고 기울기는 평균에 더 가까워 덜 흔들립니다.

### batch는 뜻이 둘입니다

설정 화면의 batch size는 갱신 한 번에 쓰는 표본 수, 곧 mini-batch의 크기입니다. 위 계산에서 "batch 방식"은 학습 쌍 전체를 한 묶음으로 쓰는 방식을 말합니다. batch size가 1이면 표본 하나씩 보는 SGD, 데이터 수와 같으면 batch 방식이고, 실제 학습은 그 사이 값을 씁니다.

### loss가 갱신마다 줄지 않는 것이 정상입니다

표본 하나의 기울기는 전체 평균과 다릅니다. 위 표의 세 번째 갱신처럼 한 표본에는 좋아도 다른 표본에는 나빠질 수 있어서, loss 곡선이 위아래로 흔들리며 내려갑니다. 표본을 치우침 없이 뽑으면 기울기들의 평균이 전체 평균 기울기와 같아서, 길게 보면 내려갑니다. learning rate를 고정하면 최솟값 근처에서도 가만히 서지 않고 흔들립니다. 그 흔들림을 줄이려고 learning rate를 점점 낮추는 스케줄을 씁니다.

### epochs를 늘린다고 계속 좋아지지 않습니다

epochs가 늘수록 학습 loss는 내려갑니다. 같은 데이터를 계속 보면 데이터를 외우기 시작해서, 검증 loss는 어느 시점부터 다시 오릅니다. epochs는 검증 loss를 보고 정합니다. → [용량과 정칙화](./capacity.md)

## 학습 코드에서는

한 바퀴의 내용은 [역전파](./backpropagation.md)의 학습 코드와 같습니다. 바깥에 epoch 반복과 mini-batch 구성이 붙습니다.

```python
loader = DataLoader(dataset, batch_size=8, shuffle=True)
for epoch in range(3):
    for x, t in loader:    # mini-batch 8개씩. 1,000개면 epoch당 125번 갱신
        ...                # 순방향, loss.backward(), optimizer.step()
```

`shuffle=True`는 epoch마다 데이터 순서를 섞어, mini-batch가 치우치지 않게 합니다.

<summary>더 깊이: 중복 샘플, 넓은 최솟값, 축별 보폭</summary>

- 학습 데이터에 비슷한 표본이 많으면 SGD가 batch 방식보다 빠릅니다. 위 네 쌍을 두 번 복사해 여덟 쌍으로 만들면 평균 기울기는 그대로 -5입니다. batch 방식은 계산이 두 배인데 갱신은 한 번이라 \(w = 0.5\)이고, SGD는 갱신 여덟 번에 한 epoch 뒤 \(w = 2.046\)입니다.
- 흔들림은 손해만은 아닙니다. 좁은 최솟값은 파라미터가 조금만 벗어나도 오차가 급히 오릅니다. 갱신마다 방향이 흔들리면 좁은 곳에 머물기 어렵고 넓은 쪽에 남는 일이 많습니다. 넓은 최솟값은 새 입력에서 덜 무너지는 경우가 많다는 관찰이 있습니다.
- 모든 파라미터에 같은 learning rate를 쓰면, 오차가 급한 축에서는 지나치고 평평한 축에서는 느립니다. 축마다 보폭을 따로 정하는 갱신이 있습니다. Adam은 2차 미분을 쓰지 않고 최근 기울기 크기의 통계로 축마다 보폭을 조절합니다.
- SGD라는 이름은 표본 하나씩 쓰는 방법만이 아니라 mini-batch로 고치는 방법도 가리킵니다. 라이브러리마다 쓰임이 다르므로 한 번에 몇 개를 쓰는지는 따로 확인해야 합니다.
- 평균 기울기로 고치는 방식은 [경사하강법](./gradient-descent.md)이고, 표본의 기울기를 만드는 방법은 [역전파](./backpropagation.md)입니다.
