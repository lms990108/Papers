서브샘플링(풀링, pooling)은 이웃한 몇 칸을 수 하나로 요약해서 이미지를 작게 줄이는 층입니다. 시내 지도를 축소 복사하면 골목 하나하나의 위치는 흐려지지만 "역은 이 근처에 있다"는 사실은 남는 것과 같습니다.

에이전트 개발에서 직접 쓸 일은 없는 배경 지식입니다. 다만 일부 멀티모달 모델이 이미지 token 수를 줄이려고 이웃 패치를 합치는 것과 같은 발상이라, 이미지 입력의 비용을 이해할 때 도움이 됩니다([VLM](./vlm.md)의 해상도 처리).

## 왜 필요한가

[합성곱](./cnn.md) 층이 하는 일은 모양을 찾는 것이지 크기를 줄이는 것이 아닙니다. 결과(feature map)는 입력만큼 크고, kernel을 여러 장 쓰면 그만큼 겹쳐서 나옵니다. 그대로 뒤로 넘기면 문제가 둘 있습니다.

### 칸이 너무 많습니다

뒤쪽 층은 앞에서 넘어온 칸을 전부 받아 계산합니다. 칸이 많으면 연결도 계산도 같이 늘어납니다. 앞 문서의 [가중치 공유](./weight-sharing.md)는 서로 다른 가중치의 개수를 줄였지만, 칸 수와 계산량은 줄이지 못했습니다.

이웃한 2×2 네 칸을 한 칸으로 요약하면 가로세로가 절반이 되고 칸 수는 4분의 1이 됩니다.

### 위치가 한두 칸 어긋나도 같은 것으로 읽어야 합니다

손글씨 숫자는 쓸 때마다 획의 위치가 한두 칸씩 달라집니다. 합성곱의 결과는 입력이 움직이면 같이 움직입니다([동변](./cnn.md)). 그런데 뒤쪽 층이 알고 싶은 것은 "획이 대략 이 근처에 있다"이고, 정확한 칸 번호는 필요 없습니다.

아주 작게 한 줄 네 칸으로 보겠습니다. 반응(1)이 한 칸 어긋난 두 입력을 두 칸씩 묶어 큰 값만 남깁니다.

```text
입력 A   1 0 | 0 0   →   1  0
입력 B   0 1 | 0 0   →   1  0
```

반응이 한 칸 움직였지만 같은 묶음 안이라 요약 결과는 똑같습니다.

서브샘플링은 이 두 가지를 한 번에 풉니다. 칸 수가 줄어서 뒤 층의 부담이 줄고 묶음 안에서는 위치 차이가 사라집니다. 대가로 정밀한 좌표는 버립니다.

## 계산

### 4×4를 2×2 덩어리 넷으로 나눕니다

이미지를 겹치지 않는 2×2 덩어리로 나누고 덩어리마다 수 하나를 냅니다. 덩어리를 만드는 창(window)이 2×2이고, 창을 옮기는 stride가 2라서 덩어리가 겹치지 않습니다.

그림의 기본값은 아래 4×4입니다. 숫자는 칸이 얼마나 짙은지입니다(0은 비어 있음, 1은 가장 짙음). 굵은 선이 덩어리 경계입니다.

```text
1    0.35 | 0     0
0    0.55 | 0.25  0
----------+-----------
0    0    | 0.45  0
0.7  1    | 0     0.2
```

왼쪽 위 덩어리의 네 칸은 1, 0.35, 0, 0.55입니다. 이 네 칸을 수 하나로 줄이는 방법이 둘 있습니다.

- **평균(average pooling)**: 네 칸을 더해 4로 나눕니다. 합이 1.90이라 0.475입니다.
- **최댓값(max pooling)**: 네 칸 중 가장 큰 값을 고릅니다. 1.00입니다.

나머지 세 덩어리도 같은 방식입니다.

| 덩어리 | 네 칸 | 평균 | 최댓값 |
| --- | --- | --- | --- |
| 왼쪽 위 | 1, 0.35, 0, 0.55 | 0.475 | 1.00 |
| 오른쪽 위 | 0, 0, 0.25, 0 | 0.0625 | 0.25 |
| 왼쪽 아래 | 0, 0, 0.7, 1 | 0.425 | 1.00 |
| 오른쪽 아래 | 0.45, 0, 0, 0.2 | 0.1625 | 0.45 |

결과는 덩어리 자리 그대로 놓입니다. 4×4가 2×2가 되고, 가로세로는 절반, 칸 수는 4분의 1입니다. 한 변이 7처럼 홀수이면 마지막 한 줄은 덩어리를 못 만들어 버려지고 결과는 3×3입니다.

이렇게 해 보세요.

1. 위쪽 버튼을 '평균'에 두고 입력 칸을 하나 누릅니다. 그 칸이 속한 덩어리의 테두리와, 오른쪽 결과에서 그 덩어리의 칸이 강조됩니다. 아래 문장에 그 덩어리의 네 값과 합, 평균, 최대가 나옵니다. 위 표의 값이 맞는지 보세요.
2. '최대'로 바꾸면 덩어리마다 가장 큰 칸에 밑줄이 그어집니다. 결과가 그 값 하나로 정해진다는 것을 볼 수 있습니다. '합'은 평균에 4를 곱한 값입니다.
3. 덩어리 안에서 값을 서로 바꿔 봅니다. 1행 1열을 누르고 슬라이더를 0.35로 내린 다음, 1행 2열을 1.00으로 올립니다. 1.00이 한 칸 옮겨 갔지만 왼쪽 위 덩어리의 평균(0.475)과 최대(1.00)는 그대로입니다.
4. '본문 예로'를 눌러 되돌린 뒤, 이번에는 덩어리 경계를 넘겨 봅니다. 1행 1열을 0으로 내리고 1행 3열을 1.00으로 올립니다. 1.00이 오른쪽 덩어리로 넘어가서 왼쪽 위와 오른쪽 위의 결과가 둘 다 바뀝니다.

## 코드에서는

PyTorch의 `nn.MaxPool2d(kernel_size=2)`는 stride 기본값이 kernel 크기와 같아서 위처럼 2×2 덩어리를 겹치지 않게 나눕니다. 평균은 `nn.AvgPool2d`입니다. 둘 다 학습되는 파라미터가 없습니다. 같은 일을 `nn.Conv2d(..., stride=2)`로 하면 kernel이 학습되는 파라미터가 됩니다. [합성곱](./cnn.md)의 코드 예에도 `nn.MaxPool2d(2)`가 나옵니다.

## 기억할 것 세 가지

### 완전한 이동 불변을 주지는 않습니다

같은 덩어리 안에서 움직인 것만 가려 줍니다. 위 한 줄 예에서 반응이 0번 칸에서 1번 칸으로 가면 결과가 같지만, 2번 칸으로 가면 둘째 묶음으로 넘어가서 결과가 바뀝니다.

### 평균과 최대는 다른 것을 말합니다

네 명이 한 조일 때 조 평균 점수와 조 최고점이 다른 것과 같습니다. 왼쪽 위 덩어리는 평균 0.475, 최대 1.00입니다. 평균은 덩어리가 전체적으로 얼마나 짙은지, 최대는 센 반응이 하나라도 있는지를 알려 줍니다. 검출기는 특징이 "있는지"만 알면 되는 경우가 많아서 max pooling을 많이 씁니다.

### 줄이는 것은 파라미터가 아니라 칸 수입니다

[르넷-5](./lenet-5.md)(다음 문서)의 서브샘플링 층 둘(S2, S4)이 가진 파라미터는 \(12 + 32 = 44\)개로, 전체 60,000개에 비하면 거의 없습니다. 칸 수가 줄어서 뒤 층의 연결과 계산이 줄어듭니다. 요즘 max pooling과 average pooling에는 파라미터가 없습니다. 같은 역할을 stride가 있는 합성곱이나 패치 임베딩([비전 트랜스포머](./vision-transformer.md))이 하기도 합니다.

- 32×32 입력에 5×5 kernel 6장을 쓰면 합성곱 결과는 28×28 맵 6장이고 모두 \(28 \times 28 \times 6 = 4{,}704\)칸입니다. 이 칸을 84칸 완전 연결층에 이으면 선이 \(4{,}704 \times 84 = 395{,}136\)개입니다. 2×2로 요약하면 14×14 맵 6장, 곧 1,176칸이 되고 선은 \(1{,}176 \times 84 = 98{,}784\)개로 4분의 1입니다.
- 입력 한 변 \(N\), 창 \(K\), stride \(S\)이면 출력 한 변은 아래 식입니다. [합성곱](./cnn.md) 문서의 '더 깊이'에 있는 출력 크기 식에서 padding(\(P\))만 뺀 것입니다. 창 2, stride 2에서 \(N = 7\)이면 \(\lfloor 5 / 2 \rfloor + 1 = 3\)이고 마지막 줄이 버려집니다.

  \[
  \left\lfloor \frac{N - K}{S} \right\rfloor + 1
  \]

- 초기 합성곱망은 덩어리의 합 \(s\)에 학습되는 계수 \(c\)를 곱하고 바이어스 \(b\)를 더해 비선형 \(f\)를 통과시켰습니다. 출력은 \(f(cs + b)\)입니다. 계수가 작으면 평균에 가까운 흐림이고, 계수가 크고 바이어스가 음수이면 덩어리 안에 특징이 있는지를 가르는 문턱이 됩니다.
- \(f = \tanh\)에서 \(c = 3, b = -2\)이면 합이 \(2/3\)보다 클 때 양수입니다. 위 덩어리의 합 1.90은 0.9988, 0.25는 −0.8483입니다.
- LeNet-5의 S2는 28×28 맵 6장을 14×14로 줄여 유닛 1,176개, 파라미터 12개(맵마다 계수와 바이어스), 연결 5,880개입니다. 연결은 유닛마다 입력 4개와 바이어스 1개로 5개입니다. S4는 유닛 400개, 파라미터 32개, 연결 2,000개입니다. 층별 표는 [르넷-5](./lenet-5.md)에 있습니다.
- 언어 모델의 token은 픽셀보다 이미 거친 단위여서, 이 층이 하던 일을 문장을 token으로 나누는 단계가 미리 해 둔 셈입니다.
- 이 페이지는 [합성곱 신경망](./cnn.md)과 [가중치 공유](./weight-sharing.md)를 먼저 보면 읽기 쉽습니다.
