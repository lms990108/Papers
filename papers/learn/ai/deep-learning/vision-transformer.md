비전 트랜스포머(ViT)는 이미지를 같은 크기의 정사각형 조각(패치)으로 잘라 글처럼 읽는 모델입니다. 패치 하나를 단어 하나처럼 다뤄서, 글을 읽는 [트랜스포머](../nlp/transformer.md)에 그대로 넣습니다.

트랜스포머는 token 여러 개가 한 줄로 선 입력을 받아, 어텐션으로 token끼리 정보를 주고받게 하는 모델입니다. token은 수를 한 줄로 늘어놓은 벡터입니다. 글에서는 단어 조각이 token이고, ViT에서는 이미지 패치가 token입니다.

에이전트를 만들 때는 이미지를 받는 LLM을 쓰는 곳에서 만납니다.

- **멀티모달 LLM의 이미지 입력**: CLIP 계열 인코더 등 이미지를 token으로 바꾸는 앞 망으로 ViT가 많이 쓰입니다. → [멀티모달](./multimodal.md)
- **이미지 비용과 지연**: 이미지 한 장이 몇 개의 token이 되는지가 prefill(LLM이 입력 token을 처음에 한꺼번에 읽는 구간)의 비용을 정합니다. 해상도와 패치 크기가 그 수를 결정합니다.
- **스크린샷 에이전트**: 글자가 작은 화면은 해상도를 낮추면 읽히지 않고 높이면 token이 늘어납니다.

## 왜 필요한가

### 이미지를 token으로 바꿔야 합니다

LLM은 token 벡터가 한 줄로 선 입력만 받습니다. 그러니 이미지를 읽히려면 먼저 token 한 줄로 바꿔야 합니다.

가장 단순한 방법은 픽셀(이미지 격자의 칸 하나) 하나를 token 하나로 보는 것입니다. 224×224 이미지는 token이 50,176개가 됩니다. 그런데 어텐션은 모든 token 쌍에 점수를 매겨 점수 표를 만듭니다. token이 n개면 표는 n×n, 곧 n² 칸입니다. 50,176개면 \(50{,}176^2 \approx 25\)억 칸이고, 이것이 한 층의 한 head(어텐션을 따로 한 벌 돌리는 단위) 몫입니다.

게다가 픽셀 하나에는 정보가 거의 없습니다. 의미는 이웃한 픽셀이 모인 모양에 있습니다.

### 이웃을 묶어서 줄입니다

그렇다면 이웃 픽셀을 묶어 token 수를 줄이면 됩니다. [CNN](./cnn.md)의 풀링([서브샘플링](./subsampling.md))이 이웃 칸을 요약해 칸 수를 줄인 것과 같은 발상입니다.

ViT는 이미지를 16×16 픽셀 패치로 잘라 패치 하나를 token 하나로 만듭니다. 224×224는 token 196개가 되고, 표는 25억 칸에서 38,416칸으로 줄어듭니다.

CNN과 비교하면 이렇습니다.

- CNN은 "이웃만 본다"는 규칙을 구조에 넣어 두었습니다. ViT는 그 규칙 없이, 어텐션이 패치 사이의 관계를 데이터에서 배우게 합니다.
- [LeNet-5](./lenet-5.md)는 층마다 크기를 줄여 갔지만, ViT는 처음에 한 번 패치로 줄이고 token 수를 끝까지 유지합니다.

nlp 구역의 [트랜스포머](../nlp/transformer.md)와 [어텐션](../nlp/attention.md)을 아직 읽지 않았다면 여기서는 두 가지만 알면 됩니다. token끼리 어텐션으로 정보를 섞는다는 것, 그리고 그 점수 표가 token 수의 제곱칸이라는 것입니다.

이 문서는 아래 순서로 ViT를 따라갑니다.

```text
이미지 → 패치로 자름 → 패치마다 token 하나 → 어텐션으로 token끼리 섞음 → 분류
```

## 패치와 패치 한 변

이미지는 숫자 격자입니다. 가로 224칸, 세로 224칸이고, 칸(픽셀)마다 빨강, 초록, 파랑 밝기를 나타내는 값(RGB) 세 개가 있습니다. 그래서 이미지 한 장은 \(224 \times 224 \times 3\)개의 수입니다.

패치는 이 격자를 같은 크기의 정사각형 조각으로 자른 것입니다. **패치 한 변**(\(P\))은 패치 하나의 가로(= 세로)를 픽셀 수로 센 값입니다. \(P = 16\)이면 패치 하나는 가로 16픽셀, 세로 16픽셀이고 모두 \(16 \times 16 = 256\)픽셀입니다. 정사각형이라 한 변만 말하면 됩니다.

이미지 한 변이 224픽셀이면 한 줄에 \(224 \div 16 = 14\)개의 패치가 들어갑니다. 가로 14개, 세로 14개이니 패치는 모두 \(14 \times 14 = 196\)개이고, 이 196이 token 수입니다.

이미지는 보통 224처럼 \(P\)로 나누어떨어지는 크기로 맞춰서 넣습니다. ViT-B/16 같은 모델 이름의 /16이 이 패치 한 변입니다.

### 작은 예로 따라가기

흑백 4×4 이미지(칸마다 값 하나)를 \(P = 2\)로 자르면 한 줄에 \(4 \div 2 = 2\)개씩, 패치는 4개입니다. 패치 안의 값을 왼쪽에서 오른쪽, 위에서 아래 순서로 한 줄로 펼칩니다. 아래 그림에서 다음 버튼을 눌러 자르고, 펼치고, token을 만드는 순서를 따라가 보세요.

<PatchSlice />

펼친 수 4개를 token 벡터로 바꾸는 계산이 선형 투영입니다. 펼친 수에 행렬 하나를 곱해 원하는 길이의 벡터를 얻는 것입니다. 여기서는 token 길이를 2로 두고, 계산이 보이게 행렬 \(E\)를 "윗줄 평균, 아랫줄 평균"으로 골랐습니다. 실제 행렬은 학습으로 정해지는 값입니다.

```text
E = [0.5 0.5 0   0  ]     ① [1 2 3 4] → [1.5, 3.5]
    [0   0   0.5 0.5]     ② [5 6 7 8] → [5.5, 7.5]
                          ③ [9 0 1 2] → [4.5, 1.5]
                          ④ [3 4 5 6] → [3.5, 5.5]
```

패치 4개가 모두 같은 행렬 \(E\)를 지납니다. 같은 모양의 패치는 이미지 어디에 있든 같은 token이 됩니다. 한 가지 필터를 여러 자리에 쓰는 [가중치 공유](./weight-sharing.md)와 같은 발상입니다. 패치가 어디에 있었는지는 뒤에서 따로 알려 줍니다.

이렇게 패치를 token으로 바꾸는 입구를 patch embedding이라 부릅니다. 이 입구는 kernel과 stride가 패치 한 변인 합성곱 한 층과 같은 계산입니다. kernel과 stride는 [CNN](./cnn.md)에서 본 것입니다.

### 실제 모델에서는

실제 이미지는 컬러라서 \(P = 16\)이면 패치 하나가 \(16 \times 16 \times 3 = 768\)개의 수입니다. 이를 길이 \(D\)인 token으로 바꾸는 행렬이 \(768 \times D\)입니다.

ViT-Base는 \(D = 768\)이라 두 숫자가 우연히 같을 뿐 뜻은 다릅니다. 앞의 768은 패치 안의 수의 개수(\(P \times P \times 3\))이고, 뒤의 768은 token 벡터의 길이입니다.

token을 만든 뒤에는 두 가지를 더합니다.

- **class token**: 이미지에서 자른 패치가 아니라, 학습되는 빈 token 하나를 맨 앞에 붙입니다. 어텐션을 거치며 모든 패치의 정보를 모아, 이미지 전체를 요약하는 자리가 됩니다.
- **positional embedding(위치 임베딩)**: 어텐션은 token이 몇 번째 자리인지 모릅니다. 그래서 자리마다 정해진 학습 벡터를 token에 더해 자리를 알려 줍니다.

이미지 한 장이 모델 안에서 거치는 모양은 이렇습니다.

```text
단계                          모양 (token 수 × 길이)
이미지                        224×224×3
패치로 자르고 펼침             196 × 768
선형 투영                     196 × 768   (D = 768일 때)
class token 붙임              197 × 768
positional embedding 더함     197 × 768
트랜스포머 블록 12층 통과      197 × 768   (층을 지나도 모양이 같습니다)
```

트랜스포머 블록은 어텐션과 작은 신경망(MLP)을 한 벌로 묶은 한 층입니다. 이 블록을 12층 쌓아도 token의 모양은 그대로입니다.

분류 모델은 마지막에 class token 자리의 출력으로 클래스를 정합니다. 멀티모달 LLM은 패치 자리의 출력을 LLM에 넘깁니다.

## 계산

패치 수는 이미지 넓이를 패치 하나의 넓이로 나눈 값입니다. 이미지의 높이와 너비가 \(H\), \(W\), 패치 한 변이 \(P\)이면 패치 token은 \(N\)개입니다.

\[
N = \frac{H W}{P^2}
\]

224×224, \(P = 16\)이면 \(N = 196\)이고, class token 1개를 앞에 붙이면 시퀀스 길이는 197입니다.

어텐션 표는 token 수의 제곱칸입니다. 아래 그림에서 해상도와 패치 한 변을 바꾸며, token 수와 어텐션 표 크기가 어떻게 달라지는지 보세요.

<PatchGrid />

```text
이미지     패치   패치 token   어텐션 표 칸(class token 제외)
224×224    32     49          2,401
224×224    16     196         38,416
224×224    8      784         614,656
448×448    16     784         614,656
```

패치 한 변을 반으로 줄이면 가로와 세로의 패치 수가 각각 2배가 되어 token이 4배이고, 표는 token 수의 제곱이라 16배입니다. 해상도를 두 배로 키워도 똑같습니다.

### 패치 한 변은 어떻게 고르나

- **\(P\)가 작으면** 패치 하나가 이미지의 좁은 부분만 담아서 작은 글자나 작은 물체의 모양이 token에 남습니다. 대신 token이 늘고 어텐션 표는 그 제곱으로 커집니다.
- **\(P\)가 크면** 싸지만, 한 패치 안에 여러 물체와 글자가 섞여 한 벡터로 뭉개집니다.

224 해상도에서 \(P = 16\)은 이 둘의 절충으로 널리 쓰이는 값입니다. 멀티모달 모델에는 \(P = 14\)도 많이 쓰입니다(336 ÷ 14 = 24, 곧 token 576개).

글자가 작은 스크린샷을 읽히려면 \(P\)를 줄이거나 해상도를 키워야 하고 어느 쪽이든 token이 늘어 비용이 오릅니다.

## 기억할 것 세 가지

### token 수가 곧 비용입니다

이미지 입력의 prefill 비용은 패치 token 수에 따라 커집니다. 그래서 고해상도 이미지는 한 번에 넣지 않고, 인코더가 학습된 해상도(예: 336×336)의 조각으로 나눠 각각 인코딩한 뒤 합치는 방식(AnyRes)을 씁니다.

패치 한 변이 14일 때 672×672를 한 번에 넣으면 token이 2,304개이고 표가 약 530만 칸입니다. 336×336 조각 4개로 나누면 표는 약 33만 칸씩 네 번입니다. 대신 언어 모델이 읽는 token은 늘어납니다. → [멀티모달](./multimodal.md)

### 위치 정보는 따로 더해 줍니다

어텐션은 token이 몇 번째 자리에 있는지 모릅니다. 패치를 어떤 순서로 넣어도 같은 모양의 패치는 같은 token이 되므로, 이미지를 뒤섞은 것과 구별되지 않습니다. 그래서 위에서 본 positional embedding을 더합니다.

앞의 작은 예에서 ①의 token \([1.5, 3.5]\)에 0번 자리의 위치 벡터 \([0.1, -0.2]\)를 더하면 \([1.6, 3.3]\)이 됩니다(값은 설명용입니다). 같은 모양의 패치도 자리가 다르면 다른 벡터가 됩니다.

해상도가 바뀌면 패치 수가 달라져 학습한 위치 임베딩을 그대로 쓸 수 없습니다. 이때는 위치 임베딩을 2차원 격자로 보고 이미지처럼 늘이거나 줄여(보간) 맞춥니다.

### CNN보다 항상 낫다는 뜻은 아닙니다

[CNN](./cnn.md)은 이웃만 본다는 규칙과 같은 검출기를 여러 자리에 쓴다는 규칙이 구조에 들어 있습니다. ViT는 이 규칙이 거의 없어서 데이터가 그 몫을 해야 합니다.

논문(2020)은 이렇게 보고했습니다. 아주 큰 데이터로 미리 학습(대규모 사전학습)하면 합성곱망과 견줄 만하거나 앞섰습니다. 중간 규모 데이터(ImageNet)로만 학습하면 비슷한 크기의 ResNet보다 몇 퍼센트포인트 낮았습니다.

이후 학습 방법(DeiT)과 구조(Swin)로 이 약점이 줄었고, 합성곱망을 현대화한 ConvNeXt가 맞서는 결과도 나왔습니다.

<summary>더 깊이: 구조, 모델 크기, 후속 연구</summary>

- patch embedding 행렬 \(E\)는 768×768이라 589,824개이고, 바이어스까지 \((768 + 1) \times 768 = 590{,}592\)개입니다. [합성곱 신경망](./cnn.md)의 "더 깊이"에 있는 출력 크기 식에 입력 224, kernel 16, stride 16, padding 0을 넣으면 \(\lfloor (224 - 16)/16 \rfloor + 1 = 14\)입니다. 패치 14×14개가 나오는 계산과 같습니다.
- AnyRes 비교의 정확한 수: 672×672를 한 번에 넣으면 \(48 \times 48 = 2{,}304\)개 token이고 표는 \(2{,}304^2 = 5{,}308{,}416\)칸입니다. 336×336 조각 하나는 \(24 \times 24 = 576\)개 token이고 표는 \(576^2 = 331{,}776\)칸이며, 네 조각이면 합쳐 1,327,104칸입니다.
- 인코더는 [트랜스포머](../nlp/transformer.md) 블록과 같습니다. 층 정규화(LN)가 어텐션(MSA)과 MLP 각각의 앞에 있고, MLP는 층 두 개와 GELU입니다.

\[
z'_\ell = \mathrm{MSA}(\mathrm{LN}(z_{\ell-1})) + z_{\ell-1}, \qquad z_\ell = \mathrm{MLP}(\mathrm{LN}(z'_\ell)) + z'_\ell
\]

- 논문의 모델 크기: ViT-Base는 12층, \(D = 768\), 헤드 12개, 86M. ViT-Large는 24층, \(D = 1024\), 307M. ViT-Huge는 32층, \(D = 1280\), 632M입니다. ViT-L/16은 Large에 16×16 패치라는 뜻입니다.
- 위치 임베딩은 1차원 방식으로 충분했습니다. 논문의 ViT-B/16 실험에서 위치 임베딩이 없으면 0.614, 1차원이면 0.642, 2차원이면 0.640이었습니다.
- 사전학습 데이터는 ImageNet(이미지 약 130만 장), ImageNet-21k(약 1,400만 장), JFT-300M(약 3억 300만 장)입니다. 작은 데이터에서는 ViT가 ResNet보다 더 과적합했고, 큰 데이터에서 앞섰습니다. 논문은 이를 합성곱의 귀납 편향이 작은 데이터에서 유용하다는 뜻으로 읽었습니다.
- DeiT(2020)는 구조를 거의 그대로 두고 강한 증강과 정규화, 증류로 ImageNet-1k만으로 DeiT-B(86M) 81.8%(224 입력)를 냈습니다. Swin(2021)은 어텐션을 창 안에서만 계산하고 층마다 창을 밀어, 계산량이 이미지 크기에 선형입니다. ConvNeXt(2022)는 ResNet을 ViT와 Swin 쪽으로 고쳐 맞섰습니다.
- 224 해상도 ViT-Base에서는 어텐션 블록의 곱셈 중 token 수의 제곱에 비례하는 쪽(표 쪽)이 약 11%라 비용의 대부분이 아니고, token이 \(2D = 1{,}536\)개를 넘어서면 표 쪽이 더 커집니다.
- CLIP(2021)은 4억 개의 이미지-글 쌍으로 이미지 인코더와 글 인코더를 함께 학습했고, 이미지 인코더로 ResNet 다섯 가지와 ViT 세 가지를 비교했습니다. LLaVA-1.5는 CLIP-ViT-L-336px를 인코더로 쓰고 연결 모듈을 2층 MLP로 바꿨습니다. 입력 336×336, 패치 14이면 token이 \(24 \times 24 = 576\)개입니다.
- 먼저 읽으면 좋은 페이지는 [가중치 공유](./weight-sharing.md)와 [어텐션](../nlp/attention.md)입니다.
