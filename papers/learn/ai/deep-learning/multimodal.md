멀티모달 모델은 글 말고 이미지나 소리 같은 입력(입력의 종류를 modality라 부릅니다)을 언어 모델이 읽을 수 있는 token 벡터로 바꿔 글 token 옆에 세웁니다. 언어 모델 블록은 벡터를 더하고 곱할 뿐이어서, 벡터가 단어에서 왔는지 픽셀에서 왔는지 구분하지 않습니다.

에이전트를 만들 때는 이런 곳에서 만납니다.

- **이미지 입력을 받는 LLM API**: 이미지 한 장이 몇 개의 token이 되는지가 비용과 지연을 정합니다.
- **스크린샷 기반 에이전트와 문서 읽기**: 화면과 PDF 페이지를 이미지로 넣습니다. 작은 글자를 읽으려면 해상도를 유지해야 합니다.
- **파이프라인 선택**: 이미지를 OCR이나 캡션으로 먼저 글로 바꿔 넘길지, 이미지를 그대로 넣을지 고릅니다.

## 왜 필요한가

언어 모델이 읽는 입력은 token마다 정해진 길이의 수 묶음(벡터)이 한 줄로 선 것뿐입니다. 영수증 사진을 주고 "합계가 얼마인가요?"라고 묻고 싶어도, 사진은 그 줄에 설 수 없는 픽셀 격자입니다.

가장 단순한 방법은 다른 모델로 이미지를 먼저 글로 바꿔 넘기는 것입니다. 캡션 모델이 "영수증 사진"이라고 쓰거나, OCR이 보이는 글자를 모두 뽑습니다. 한계는 질문보다 변환이 먼저라는 점입니다. 변환하는 시점에는 사용자가 합계를 물을지, 품목별 가격을 물을지, 도장이 찍혔는지를 물을지 모릅니다. 글로 옮기지 않은 세부는 언어 모델이 다시 볼 방법이 없습니다. 소리도 같아서, 말을 글자로만 바꾸면 억양은 넘어가지 않습니다.

멀티모달 모델은 변환의 결과를 글이 아니라 벡터로 둡니다. 이미지를 벡터 여러 개로 바꿔 글 token과 같은 줄에 세우면, 질문이 들어온 뒤에도 언어 모델이 [어텐션](../nlp/attention.md)(한 token이 줄의 다른 token을 훑어 필요한 것을 가져오는 계산)으로 이미지 벡터를 직접 읽습니다. 바로 앞 [비전 트랜스포머](./vision-transformer.md)에서 이미지를 patch token으로 바꾸는 부분을 봤습니다. 이 페이지는 그 token을 언어 모델의 줄에 세우는 연결을 다룹니다.

## 전체 그림

이미지가 언어 모델에 들어가는 길은 세 단계입니다.

```text
이미지 → vision encoder → projector → LLM 입력 줄(글 token 옆)
```

- **vision encoder**: 이미지를 patch로 잘라 patch마다 벡터 하나를 만드는 망입니다. 보통 ViT를 씁니다. → [비전 트랜스포머](./vision-transformer.md)
- **projector**: 그 벡터의 길이를 언어 모델의 벡터 길이에 맞추는 행렬(또는 작은 망)입니다. 글 token과 이미지 token은 더하지 않고 한 줄로 나란히 서서 같은 블록의 같은 가중치를 지나갑니다. 가중치는 정해진 길이의 벡터에 맞춰져 있어서 줄에 선 벡터가 모두 같은 길이여야 하는데, encoder가 내는 길이는 보통 다르기 때문에 projector가 필요합니다.
- **LLM**: 이 줄을 prompt처럼 읽습니다. 입력 token을 한꺼번에 읽는 이 첫 구간이 prefill이고, 그다음부터 답을 token 하나씩 이어 씁니다.

이미지를 넣은 요청은 이런 줄이 됩니다. 이미지 token 수 576은 예입니다.

```text
[이미지 token 576개] [글 token: "이 영수증의 합계는 얼마인가요?"]
```

LLM에게는 앞 576개도 그냥 벡터입니다. 답을 쓰는 동안 어텐션이 이 576개를 글 token과 똑같이 훑습니다.

소리도 같은 틀입니다. 파형을 짧은 조각으로 잘라 각각 벡터로 만들고, projector를 거쳐 같은 줄에 세웁니다.

## 계산

이 틀을 가장 작게 줄여 봅니다. vision encoder는 생략하고, 이미지의 픽셀 값에 행렬 하나를 바로 곱해 token 하나를 만듭니다. 글 token이 길이 2인 \([1, 0]\)이라고 하면 이미지 token도 길이 2여야 합니다. 이미지는 2×2 밝기 네 칸 \([1, 0, 1, 0]\)이고, 네 칸을 길이 2로 줄이는 행렬이 projector 역할을 합니다. 줄마다 픽셀과 곱해 더합니다(가중치는 계산이 보이게 고른 수입니다).

```text
줄   가중치             밝기와의 곱         합
1    [0.5, 0, 0, 0]     0.5 × 1, 나머지 0   0.5
2    [0, 0, 0.5, 0]     0.5 × 1, 나머지 0   0.5
```

줄 1의 가중치는 첫째 밝기만 절반으로 가져오고, 줄 2는 셋째 밝기만 절반으로 가져옵니다. 나머지 가중치가 0이라 둘째, 넷째 밝기는 결과에 영향을 주지 않습니다. 이미지 token은 \([0.5, 0.5]\)이고, 글 token \([1, 0]\) 옆에 서서 같은 prefill에서 함께 읽힙니다. 실제로는 vision encoder가 patch마다 벡터를 만들고 projector가 길이를 맞추므로, 이 표의 행렬 하나는 그 둘을 합쳐 줄인 모양입니다.

위 이미지는 token 하나였습니다. 이미지가 커져도 token 하나로 줄이면 어디가 밝았는지가 사라집니다. 4×4 이미지의 사분면 평균 밝기가 1, 0, 0, 0이라고 합시다(왼쪽 위만 밝습니다). 16칸을 통째로 평균 내면 \(1/4 = 0.25\) 한 수가 되어 어느 사분면이 밝았는지 알 수 없습니다. 아래 그림에서 한 칸으로 줄일 때와 조각을 유지할 때의 token 수를 비교해 보세요.

4×4를 2×2 조각 네 개로 나눠 조각마다 같은 projector를 통과시키면 token이 4개가 되어 prefill에 서고, 첫째 조각만 밝습니다. 조각을 유지하면 위치가 token 자리에 남지만, 그만큼 token이 늘어 비용도 오릅니다. 이 2×2 조각은 계산이 보이게 만든 장난감입니다. 실제 모델은 큰 이미지를 인코더의 기본 해상도 크기로 잘라 쓰는데, 이는 [VLM](./vlm.md)에서 봅니다.

## 기억할 것 세 가지

### 이미지 token 수가 비용입니다

token이 1개에서 4개로 늘면 prefill 연산도 그만큼 커집니다. 해상도를 높이거나 조각을 늘리면 품질은 오르고 비용도 오릅니다. 이미지 token은 픽셀 한 칸이 아니라 여러 칸을 곱해 만든 벡터 하나입니다.

### 줄이면 내용이 사라질 수 있습니다

한 칸으로 평균 내면 위치가 사라지고 해상도를 낮추면 작은 글자가 지워집니다. 읽혀야 하는 세부가 있는 이미지는 조각을 유지해야 합니다.

### 글로 바꿔 넘기면 글이 담은 만큼만 남습니다

이미지를 먼저 글로 바꿔 넘기는 경로가 있습니다. 이미지 전용 모델이 "왼쪽이 밝다"라는 문장을 만들고 언어 모델은 그 문장만 읽습니다. 이때 픽셀의 위치는 문장이 담은 만큼만 남습니다. 소리도 같아서, 말을 먼저 글자로 바꾸면 억양과 길이는 글자가 담은 만큼만 남습니다. 위 틀처럼 벡터를 그대로 넘기면 encoder가 벡터에 담은 만큼은 언어 모델에 닿습니다.

<summary>더 깊이: 대조 학습과 CLIP</summary>

- 이미지 벡터와 문장 벡터의 길이가 같으면 [코사인 유사도](../nlp/cosine-similarity.md)를 셀 수 있습니다. 이미지 \([1, 0]\), 맞는 문장 \([1, 0]\)의 코사인은 1이고, 다른 문장 \([0, 1]\)과는 0입니다. 학습은 맞는 쌍의 코사인을 키우고 다른 쌍을 줄입니다. 이 짝 맞추기가 대조 학습(contrastive learning)이고, CLIP과 SigLIP이 이 목적으로 이미지 인코더와 문장 인코더를 함께 학습합니다. 이렇게 학습한 이미지 인코더는 이미지를 글의 의미와 맞는 벡터로 바꿉니다. 이 인코더를 vision encoder로 가져와 projector와 언어 모델을 이어 붙인 것이 VLM(vision-language model)이고, LLaVA가 CLIP 인코더를 씁니다.
- 이미지 token 수 계산, 학습 단계, 문서·GUI 활용과 실패 패턴은 [VLM](./vlm.md)에서 다룹니다.
- 대조 학습이 줄이는 것은 맞는 쌍과 다른 쌍의 코사인 차이이고, 언어 모델의 다음 token 오차와 다릅니다.
- modality별로 처리를 끝낸 뒤 합치는 구성(이미지를 글로 바꿔 넘기는 것이 그 예)을 late fusion이라 부르기도 합니다. 이 말은 원래 출력 단계에서 합친다는 뜻이라 자료마다 가리키는 범위가 달라 혼동되기 쉽습니다. 처음부터 여러 modality를 한 모델에서 함께 학습한 모델은 native multimodal이라 부릅니다.
- token이 늘면 [Prefill, decode](../nlp/prefill-decode.md)의 연산도 token 수에 비례해 늡니다. 블록이 입력에 결과를 더해 다음 블록으로 넘기는 구조(residual)는 [Decoder block](../nlp/block.md)에 있습니다.
- [Diffusion, flow](./generation.md)의 latent도 같은 발상으로 픽셀 벡터를 줄입니다.
