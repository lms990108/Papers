역전파는 오차가 각 파라미터를 얼마나 밀고 있는지(기울기)를, 출력에서 입력 쪽으로 변화율을 곱하며 구하는 절차입니다.

API로 모델을 호출하는 에이전트는 역전파를 직접 쓰지 않습니다. fine-tuning이나 학습 코드(PyTorch의 `loss.backward()`)를 다룰 때 만납니다. 학습이 추론보다 메모리를 훨씬 많이 쓰는 이유도 여기에 있습니다. 역방향에서 쓰려고 순방향의 중간 값을 모두 저장해야 하기 때문입니다.

## 아이디어

칸이 이어진 장치를 떠올립니다. 첫 칸을 1 올리면 둘째 칸이 0.8만큼 오르고, 둘째 칸을 1 올리면 셋째 칸이 2만큼 오른다고 합시다. 그러면 첫 칸을 1 올릴 때 셋째 칸은 \(0.8 \times 2 = 1.6\)만큼 오릅니다. 칸마다 "바로 앞 칸이 1 오를 때 얼마나 오르는가"(변화율)만 알면, 멀리 있는 칸의 영향은 그 변화율을 이어 곱해서 얻습니다. 아래 그림에서 칸 1을 올렸을 때 오차가 얼마나 오르는지 따라가 보고, 같은 곱을 거꾸로 하면 어떻게 되는지 이어서 보세요.

<ChainIntuition />

신경망이 이런 모양입니다. 입력에서 시작해 칸이 이어지고 맨 끝 칸이 오차입니다. 파라미터가 오차에 미치는 영향이 곧 기울기이므로, 파라미터에서 오차까지의 변화율을 곱하면 됩니다. 이 곱을 오차 쪽에서 시작해 거꾸로 계산합니다. 오차에서 출발한 신호 하나를 한 칸씩 앞으로 넘기면, 지나가는 파라미터마다 기울기가 나옵니다. 파라미터가 아무리 많아도 역방향 한 번이면 됩니다. 규칙은 하나입니다.

**새 신호 = 뒤에서 온 신호 × 이 칸의 변화율**

## 계산

목표는 파라미터마다 \(\partial E/\partial w\)(\(w\)를 조금 올릴 때 \(E\)가 변하는 비율, 곧 기울기)를 구하는 것입니다. 먼저 순방향으로 오차를 구하고, 그다음 거꾸로 돌며 기울기를 만듭니다. 입력 \(x = 1\), 가중치 \(w_1 = 0.5\), \(w_2 = 1\), 정답 \(t = 0\)인 두 단계 망입니다.

\[
a = w_1 x, \quad h = \tanh(a), \quad y = w_2 h, \quad E = (y - t)^2
\]

순방향으로 값을 만들고 저장합니다.

```text
a = 0.5     h = tanh(0.5) = 0.4621     y = 0.4621     E = 0.2136
```

역방향은 위 규칙을 출력 쪽에서부터 칸마다 적용하는 일입니다. \(E\)는 \(y\)에, \(y\)는 \(h\)에, \(h\)는 \(a\)에, \(a\)는 \(w_1\)에 이어져 바뀌므로, 칸마다의 변화율을 이어 곱하면 \(w_1\)이 \(E\)에 미치는 영향이 됩니다(연쇄법칙). \(\tanh\)의 변화율은 \(1 - h^2\)입니다.

```text
∂E/∂y  = 2(y - t)        = 0.9242
∂E/∂w₂ = 0.9242 × h      = 0.4271
∂E/∂h  = 0.9242 × w₂     = 0.9242
∂E/∂a  = 0.9242 × (1 - h²) = 0.7269
∂E/∂w₁ = 0.7269 × x      = 0.7269
```

\(h\)에는 정답이 없습니다. 0.9242는 데이터가 준 답이 아니라 출력 오차가 뒤로 보낸 신호입니다. 아래 그림에서 다음 버튼을 눌러, 값이 앞으로 가고 신호가 뒤로 돌아오며 칸마다 변화율이 곱해지는 순서를 따라가 보세요. 파란 테두리는 순방향에서 저장해 둔 값을 다시 쓰는 칸입니다.

<TwoLayerBackprop />

구한 기울기로 [경사하강법](./gradient-descent.md)을 한 번 적용하면 learning rate 0.1에서 \(w_1 = 0.4273\), \(w_2 = 0.9573\)이 되고 오차는 0.2136에서 0.1489로 내려갑니다.

## 기억할 것 세 가지

### 순방향 값을 저장해야 역방향을 계산합니다

위 계산에서 \(\partial E/\partial w_2\)는 \(h\)가, \(\partial E/\partial a\)는 \(1 - h^2\)가 필요합니다. 저장해 두지 않으면 돌아올 때 다시 계산해야 합니다. 학습에서 GPU 메모리를 많이 쓰는 주된 원인이고, 메모리가 모자라면 일부 값을 버렸다가 다시 계산하는 gradient checkpointing을 씁니다. 추론에서는 기울기가 필요 없어서 이 저장을 하지 않습니다(`torch.no_grad()`).

### 중간 층의 학습 신호는 출력 오차에서 옵니다

정답이 붙은 곳은 마지막 출력뿐입니다. 앞쪽 파라미터는 "출력을 이렇게 바꿔라"는 신호를 뒤에서 받아 고쳐집니다. 층 사이의 중간 값이 무엇이어야 하는지는 누구도 정해 주지 않습니다.

### 역전파는 기울기만 구합니다

파라미터를 실제로 고치는 일은 경사하강법이나 Adam 같은 optimizer가 합니다. 순방향 한 번과 역방향 한 번이면 파라미터 전체의 기울기가 나옵니다. 파라미터마다 조금씩 움직여 오차를 재는 방식은 파라미터가 \(N\)개일 때 순방향이 \(2N\)번 필요해서, 수십억 개 모델에는 쓸 수 없습니다.

<details>
<summary>더 깊이: 연쇄법칙과 검산, 갈래가 있을 때</summary>

- 오차가 \(y\), \(h\), \(w_1\)을 차례로 거쳐 바뀌므로 \(\dfrac{\partial E}{\partial w_1} = \dfrac{\partial E}{\partial y}\,\dfrac{\partial y}{\partial h}\,\dfrac{\partial h}{\partial a}\,\dfrac{\partial a}{\partial w_1}\)입니다. 위 계산은 이 곱을 뒤에서부터 하나씩 풀어 쓴 것입니다.
- 검산은 수치 미분으로 합니다. \(w_1\)을 \(\pm 10^{-6}\) 움직여 오차 차이를 \(2 \times 10^{-6}\)으로 나누면 0.72686으로, 역전파 값 0.7269와 같습니다. 근사가 아니라 정확한 기울기이고, 구현이 맞는지 확인할 때 이 방법을 씁니다(gradient check).
- 한 값이 여러 곳에 쓰이면 갈래마다의 기울기를 더합니다. 가중치를 여러 위치에서 공유하는 구조가 그렇고, 트랜스포머의 잔차 연결도 같습니다.
- 변화율이 층마다 1보다 작거나 크면 앞쪽 기울기가 줄거나 커집니다. [기울기 소실](./gradient-vanishing.md)에서 다룹니다. 이 기울기로 학습한 모델이 새 입력에서도 맞히려면 [용량과 정칙화](./capacity.md)도 같이 봐야 합니다.

</details>
