경사하강법은 오차의 기울기를 구해, 오차가 줄어드는 쪽으로 파라미터를 조금씩 옮기는 학습 절차입니다.

모델을 fine-tuning하거나 학습 코드를 돌릴 때 설정 화면에서 만납니다. learning rate, epochs, batch size가 이 절차의 설정값이고, loss(오차를 이렇게도 부릅니다)가 내려가지 않거나 `NaN`이 뜨는 문제에서 가장 먼저 의심할 값이 learning rate입니다. API로 호출만 하는 경우에는 직접 쓰지 않습니다.

## 왜 필요한가

[신경망](./neural-network.md)을 만들면 가중치는 비어 있습니다. 채우는 기준은 [지도 학습](../machine-learning/supervised-learning.md)의 정답입니다. 예측이 정답과 얼마나 다른지를 수 하나로 적은 것이 오차(loss)이고, 가중치를 바꾸면 오차도 바뀝니다. 그러면 학습은 오차가 가장 작아지는 가중치 값을 찾는 문제가 됩니다.

가장 단순한 방법은 값을 이것저것 넣어 보고 오차가 작은 것을 고르는 것입니다. 784 → 100 → 10 망은 가중치가 79,510개입니다. 가중치마다 후보를 10개만 잡아도 조합이 \(10^{79510}\)가지여서 다 확인할 수 없고, 무작위로 찍는 것은 운에 맡기는 일입니다.

경사하강법은 전체를 보지 않고 지금 서 있는 자리만 봅니다. 안개 낀 산에서 발밑이 어느 쪽으로 기울었는지만 보고 내리막으로 한 걸음 가는 것과 같습니다. 가중치를 조금 올렸을 때 오차가 오르는지 내리는지(기울기)만 알면 되고, 이것을 반복합니다. 가중치가 몇 개든 한 걸음에 필요한 것은 가중치마다의 기울기입니다. 이 기울기를 한꺼번에 구하는 방법이 [역전파](./backpropagation.md)입니다.

## 계산

맞는 파라미터가 3이고 오차를 \(E(w) = (w - 3)^2\)으로 둡니다. 3은 이 예에서만 우리가 아는 값이고, 실제 학습에서는 모르는 채 기울기만 보고 찾아갑니다. 시작은 \(w = 0\), 한 번에 옮기는 비율인 learning rate는 \(\epsilon = 0.1\)입니다. 기울기는 \(w\)를 조금 올릴 때 오차가 변하는 비율이고, 여기서는 \(2(w - 3)\)이라 \(w = 0\)에서 \(-6\)입니다. 기울기가 음수이므로 \(w\)를 키워야 오차가 줄고, 그래서 기울기를 뺍니다.

\[
w \leftarrow w - \epsilon\, \frac{\partial E}{\partial w}
\]

```text
단계   w      기울기
0     0.000   -6.0
1     0.600   -4.8     0 - 0.1 × (-6)   = 0.6
2     1.080   -3.84    0.6 - 0.1 × (-4.8) = 1.08
3     1.464   -3.072
```

\(w\)가 3에 다가가지만 한 번에 도착하지는 않습니다. 기울기가 줄어서 걸음도 짧아집니다. 갱신 한 번은 정답까지 남은 거리 \(w - 3\)에 \(1 - 2\epsilon = 0.8\)을 곱하는 일이기도 합니다.

이 과정을 오차 곡선 위에서 보면 이렇습니다. 가로가 \(w\), 세로가 오차 \(E\)이고 곡선의 가장 낮은 곳이 정답 3입니다. 공이 지금 위치이고 초록 직선이 그 자리의 기울기입니다. 기울기가 음수이면 왼쪽이 높고 오른쪽이 낮으니 공은 오른쪽으로 내려갑니다. '다음 걸음'을 눌러 위 표의 값이 그대로 나오는지 따라가 보세요. learning rate 버튼으로 걸음 크기를 바꿔 볼 수도 있고 그 결과는 아래 "기억할 것"에서 정리합니다.

<ParabolaDescent />

파라미터가 여럿이면 \(w\)마다 자기 기울기로 같은 식을 적용합니다. 79,510개이면 기울기도 79,510개이고, 한 걸음에 모두 함께 옮깁니다. 멈추는 시점은 오차가 더 줄지 않을 때나 정해 둔 횟수(epochs)를 채웠을 때입니다.

학습 코드에서 이 식은 `optimizer.step()`입니다. 아래처럼 learning rate를 넘겨 optimizer를 만듭니다.

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)   # lr이 위의 ε
# ... loss.backward()로 기울기를 구한 뒤
optimizer.step()                                         # w ← w − lr × 기울기
```

## 파라미터가 둘이면: 곡선에서 곡면으로

파라미터가 하나일 때 오차는 곡선이었습니다. 둘이면 파라미터 한 쌍 \((w_1, w_2)\)가 평면의 한 점이 되고 그 점 위로 오차가 높이로 서서 곡면이 됩니다. 앞의 포물선 하나가 곡면의 단면이 됩니다.

위의 예를 파라미터 둘로 늘려 \(E(w_1, w_2) = (w_1 - 3)^2 + 10(w_2 - 1)^2\)으로 둡니다. 곡면을 \(w_2 = 1\)에서 자르면 \(E = (w_1 - 3)^2\)이 되어 앞에서 본 바로 그 포물선이 나옵니다. \(w_1 = 3\)에서 자르면 \(E = 10(w_2 - 1)^2\)이고 같은 모양이지만 열 배 가파른 포물선입니다. 곡면은 이런 포물선들이 쌓인 그릇이고 바닥이 \((3, 1)\)입니다. 기울기도 파라미터마다 하나씩 두 개입니다.

\[
\frac{\partial E}{\partial w_1} = 2(w_1 - 3), \quad \frac{\partial E}{\partial w_2} = 20(w_2 - 1)
\]

시작 \((0, 0)\)에서 기울기는 \((-6, -20)\)입니다. \(\epsilon = 0.05\)이면 \(w_1 = 0 - 0.05 \times (-6) = 0.3\), \(w_2 = 0 - 0.05 \times (-20) = 1\)이 됩니다. 두 기울기를 함께 쓰면 그 자리에서 가장 가파른 내리막 쪽으로 갑니다. 그림의 초록 화살표가 그 방향입니다.

아래 그림에서 먼저 검은 단면 곡선을 앞의 포물선과 견주어 보세요. 같은 \(\epsilon\)을 두 파라미터에 쓰고 공을 굴립니다. '위에서 보기'를 누르면 같은 곡면을 내려다본 지도가 되고 검은 선은 오차가 같은 점을 이은 등고선입니다. 지도에서는 초록 화살표가 등고선과 직각입니다.

<LossSurface3D />

같은 \(\epsilon\)인데도 \(w_2\) 쪽이 먼저 흔들립니다. 갱신 한 번마다 정답까지 남은 거리에 곱해지는 값이 파라미터마다 다르기 때문입니다.

| \(\epsilon\) | \(w_1\) 방향 곱 \(1 - 2\epsilon\) | \(w_2\) 방향 곱 \(1 - 20\epsilon\) | 모양 |
| --- | --- | --- | --- |
| 0.02 | 0.96 | 0.6 | 계곡 바닥에 먼저 내려앉고 천천히 걸어갑니다 |
| 0.05 | 0.9 | 0 | \(w_2\)는 한 번에 닿습니다 |
| 0.09 | 0.82 | -0.8 | 계곡 벽을 오가며 지그재그로 나아갑니다 |
| 0.11 | 0.78 | -1.2 | \(w_2\)가 커지며 곡면 밖으로 나갑니다 |

곱의 크기가 1을 넘으면 거리가 줄지 않고 커집니다. 그래서 \(\epsilon\)의 한계는 가장 가파른 방향이 정합니다. \(w_1\)만 보면 1까지 괜찮지만 \(w_2\) 때문에 0.1을 넘을 수 없습니다. 그렇다고 \(\epsilon\)을 \(w_2\)에 맞춰 작게 잡으면 \(w_1\) 방향은 느리게 갑니다. 길쭉한 계곡에서 학습이 느려지는 이유입니다.

## 기억할 것 세 가지

### learning rate가 크면 최솟값을 지나쳐 발산합니다

같은 곡선에서 learning rate를 바꿔 다섯 걸음씩 달려 보면 다음과 같습니다.

| \(\epsilon\) | 5걸음 동안의 \(w\) |
| --- | --- |
| 0.01 | 0.06, 0.119, 0.176, 0.233, 0.288 |
| 0.1 | 0.6, 1.08, 1.464, 1.771, 2.017 |
| 0.5 | 3 (한 번에 도착) |
| 1.0 | 6, 0, 6, 0, 6 (왕복) |
| 1.1 | 6.6, -1.32, 8.184, -3.221, 10.465 (멀어짐) |

기울기 방향은 맞았고 틀린 것은 얼마나 갈지입니다. 아래 그림에서 걸음 수를 늘려 어느 선이 3에 닿고 어느 선이 튀는지 보세요. 실제 학습에서 loss가 오르거나 `NaN`이 되면 이 모양입니다.

<LrRace />

### 작다고 항상 좋은 것은 아닙니다

\(\epsilon = 0.01\)은 안전하지만 다섯 걸음에 0.288밖에 못 갑니다. 한계 안에서는 큰 값이 빠릅니다. 데이터가 많은 학습에서는 느린 만큼 시간과 GPU 비용이 듭니다.

### 학습 오차의 최솟값이 새 입력에서의 최선은 아닙니다

경사하강법은 지금 자리에서 내리막을 따라갈 뿐이어서, 가장 낮은 곳을 찾아 주지도 않고 시작이 다르면 다른 골짜기에 도착합니다. 또 절차는 학습에 넣은 데이터만 봅니다. 넣지 않은 입력에서 얼마나 틀리는지는 [용량과 정칙화](./capacity.md)에서 따로 다룹니다.

<summary>더 깊이: learning rate의 한계와 국소 최솟값</summary>

- \(E = \tfrac{c}{2}(w - w^*)^2\) 꼴이면 갱신마다 거리에 \(1 - \epsilon c\)가 곱해집니다. \(0 < \epsilon < 2/c\)일 때 수렴하고, 이 \(2/c\)가 learning rate의 한계입니다. 곡선이 가파를수록 한계가 작습니다. \((w - 3)^2\)은 \(c = 2\)라 한계가 1입니다. 파라미터가 여럿이면 가장 가파른 방향의 \(c\)가 한계를 정합니다.
- 기울기가 0인 점은 가장 낮은 곳이 아닐 수 있습니다. \(E(w) = w^4 - 3w^2 + w\)는 골짜기가 둘이라, 2.0에서 시작하면 오차 -1.070인 얕은 골짜기(\(w \approx 1.131\))에, -2.0에서 시작하면 -3.514인 깊은 골짜기(\(w \approx -1.301\))에 닿습니다. \(E = w_1^2 - w_2^2\)의 원점은 기울기가 0인 안장점입니다.
- 다층망에서 국소 최솟값이 실무에서 자주 문제가 되지 않는다는 관찰은 있지만, 이론은 아직 열려 있습니다.
- 파라미터가 \(W\)로 여럿이면 \(w\)마다 같은 식을 적용합니다. 층이 여럿일 때 기울기를 구하는 법은 [역전파](./backpropagation.md), 표본 하나나 mini-batch로 고치는 법은 [확률적 경사하강법](./sgd.md)입니다. 오차의 종류는 [지도 학습](../machine-learning/supervised-learning.md)에 있습니다.

</details>
