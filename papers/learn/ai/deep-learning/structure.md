구조는 어떤 수가 어떤 수에 곱해지는지를 적은 연결 방식이고, 학습을 시작하기 전에 사람이 정합니다. 그 연결선 위에 적히는 수가 파라미터이고 학습이 고칩니다.

모델을 고를 때 구조를 고르는 셈입니다. "트랜스포머 디코더, 32층, hidden size 4096"이 구조이고, "7B"는 그 구조가 가진 파라미터 수입니다. fine-tuning은 구조를 그대로 두고 파라미터 값만 바꿉니다. context window(한 번에 읽을 수 있는 token 수의 한도)를 늘려도 구조의 뼈대는 같아서 파라미터 수가 아니라 계산량과 메모리가 늡니다.

## 왜 필요한가

[신경망](./neural-network.md)의 가중치는 학습이 채웁니다. 학습이 정하지 못하는 것은 칸이 몇 개이고 어느 칸의 값이 어느 칸에 곱해지는지입니다. 가중치는 연결선 위의 수라서 선이 없는 곳에는 값을 채울 수 없습니다. 선을 어떻게 그을지는 학습 전에 사람이 정해야 하고, 이것이 구조입니다. [층](./layer.md)을 몇 개 쌓을지, 층마다 칸이 몇 개인지도 구조에 들어갑니다.

가장 단순한 구조는 완전 연결, 곧 한 층의 모든 칸을 다음 층의 모든 칸에 잇는 것입니다. 입력이 작으면 이것으로 충분하지만 커지면 파라미터가 감당이 안 됩니다. 예를 들어 1000×1000 이미지(입력 100만 칸)를 은닉 1,000칸에 완전 연결하면 가중치만 \(10^6 \times 10^3 = 10^9\)개, 10억 개입니다. 게다가 이미지에서는 작은 모양(모서리, 획)이 어느 자리에나 나오는데 완전 연결은 자리마다 같은 모양을 따로 배웁니다.

연결 방식을 바꾸면 이 낭비를 줄입니다. 한 칸이 보는 범위를 작은 창으로 제한하고 그 창의 파라미터를 모든 자리가 돌려 쓰는 식입니다. 아래 계산에서 같은 입력과 출력으로 파라미터가 452,160개에서 26개까지 줄어드는 것을 봅니다.

## 계산

입력 784개에서 점수 10개를 내는 완전 연결 망의 파라미터를 세어 봅니다. 층마다 가중치가 (입력 칸 수) × (출력 칸 수), 바이어스가 출력 칸 수입니다.

```text
784 → 10          784×10 + 10                  =  7,850
784 → 30 → 10     (784×30 + 30) + (30×10 + 10) = 23,860
784 → 100 → 10    (784×100 + 100) + (100×10 + 10) = 79,510
```

가운데 30이나 100은 정답이 붙지 않은 은닉 칸 수이고 데이터가 정해 주지 않아 사람이 고릅니다. 같은 입력과 같은 출력인데 구조가 셋이면 파라미터 수도 셋입니다. 학습이 도중에 30칸을 100칸으로 늘리지는 않습니다. 늘리려면 다른 구조로 처음부터 다시 학습해야 합니다.

연결 방식으로도 파라미터 수가 달라집니다. 28×28 이미지에서 5×5 창을 한 칸씩 옮기면 창이 놓이는 자리가 \(24 \times 24 = 576\)개입니다. 자리마다 출력 칸이 하나입니다.

```text
전부 보기          784×576 + 576   = 452,160
창만 보되 따로      576×(25 + 1)    =  14,976
창만 보고 공유      25 + 1          =      26
```

공유는 모든 자리가 같은 파라미터 한 벌을 돌려 쓰는 것입니다. 출력은 세 경우 모두 576칸인데 파라미터는 26개까지 줄어듭니다. 이미지에서는 이웃한 픽셀이 서로 관련 있고 같은 모양이 어디서나 나옵니다. 이 성질을 구조에 넣은 것이고 입력의 성질에 맞는 연결을 고르는 일이 구조 설계입니다. 이 아이디어가 [가중치 공유](./weight-sharing.md)와 [합성곱 신경망](./cnn.md)입니다.

## 기억할 것 세 가지

### 문장도 같은 방식으로 파라미터를 공유합니다

트랜스포머에서 같은 블록 안의 token 자리들은 같은 파라미터를 씁니다. token 3개든 300개든 한 블록의 파라미터는 그대로입니다. 대신 token이 늘면 계산이 늘고, 어텐션은 모든 token 쌍에 점수를 매기므로 token 수의 제곱에 비례해 늡니다. 긴 context가 비싼 이유입니다. 블록을 쌓는 그림은 [트랜스포머](../nlp/transformer.md), token을 섞는 계산은 [어텐션](../nlp/attention.md)입니다.

### 구조, 하이퍼파라미터, 파라미터는 다릅니다

| | 누가 정하나 | 학습 중 바뀌나 | 예 |
| --- | --- | --- | --- |
| 구조 | 사람, 학습 전 | 바뀌지 않는다 | 784 → 100 → 10, 블록 32개 |
| 하이퍼파라미터 | 사람, 학습 전 | 보통 바뀌지 않는다 | learning rate, 은닉 칸 수 |
| 파라미터 | 학습 | 갱신마다 바뀐다 | 가중치 0.5, \(-0.2\) |
| 입력과 정답 | 데이터 | 바뀌지 않는다 | 숫자 7 이미지와 정답 7 |

fine-tuning 설정 화면의 learning rate, epochs, batch size는 하이퍼파라미터입니다. 어느 값이 좋은지는 학습에 쓰지 않은 검증 데이터로 고릅니다. → [데이터 분리](../machine-learning/data-split.md)

### 파라미터가 많은 구조가 더 좋은 것은 아닙니다

위의 452,160개와 26개 가운데 어느 쪽이 이미지를 잘 맞히는지는 개수로 알 수 없습니다. 같은 일에 적은 파라미터로 충분한 구조가 새 입력에서 덜 틀리는 경우가 많습니다. 이 관계는 [용량과 정칙화](./capacity.md)에서 봅니다.

<summary>더 깊이: 문장 구조의 파라미터 세기</summary>

- 사전 4개, 임베딩 길이 2이면 임베딩 표가 \(4 \times 2 = 8\)개입니다. 블록 하나를 2×2 가중치와 바이어스 2개로 단순화하면 6개이고 블록 둘이면 12개입니다. 마지막 벡터에서 사전의 네 단어 점수를 내는 표가 8개 더 들어 모두 \(8 + 12 + 8 = 28\)개입니다.
- 이 단순한 블록에서도 token이 3개에서 300개로 늘면 곱셈은 100배가 되지만 블록 파라미터는 12개로 같습니다.
- 실제 블록에는 어텐션이 있어 훨씬 크지만 공유하는 방식은 같습니다. 임베딩은 [임베딩](../nlp/embedding.md), token 자르기는 [토큰화](../nlp/tokenization.md), 오차는 [다음 token](../nlp/next-token.md)에서 다룹니다.
- learning rate 같은 값은 연결 방식이 아니라 [경사하강법](./gradient-descent.md)의 보폭이어서 구조가 아니라 하이퍼파라미터로 분류합니다. 은닉 칸 수는 구조이면서 하이퍼파라미터이기도 합니다.
