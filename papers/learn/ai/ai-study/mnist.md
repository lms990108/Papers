방법 둘의 오류를 나란히 적으면, 어느 쪽이 나은지처럼 보인다. 시험에 쓴 그림이 다르면 그 비교는 성립하지 않는다. 한쪽은 쉬운 글씨만 맞고, 다른 쪽은 어려운 글씨에서 틀렸을 수 있다. 같은 학습 집합과 같은 시험 집합이 있어야, 오류 차이를 방법의 차이로 읽을 수 있다. MNIST는 그 공통 집합으로 만든 Modified NIST(Modified National Institute of Standards and Technology)다.

:::tip[한눈에 보기]
MNIST는 필기 숫자 0~9의 학습 60,000장과 시험 10,000장으로 이루어진 비교용 데이터 집합이다.

- 학습과 시험은 작가가 겹치지 않고, 두 출처(직원, 고등학생)의 글씨가 양쪽에 섞여 있다.
- 글자는 20×20 상자에 맞추고 질량 중심을 28×28의 가운데에 둔다. LeNet-5는 이를 32×32로 늘려 쓴다.
- 시험 10,000장의 오류 불확실성은 약 0.1%p라서, 그보다 작은 차이는 방법의 차이로 단정하지 않는다.
- 시험 집합은 마지막에 한 번 쓰고, 설정은 따로 뗀 검증 집합에서 고른다.

이전에 알아야 할 것: [LeNet-5](./lenet-5.md), [데이터 분할](./data-split.md). 다음에 이어지는 것: [부스팅](./boosting.md), [서포트 벡터 머신](./svm.md).
:::

NIST가 처음에 정해 둔 분할은 아래 왼쪽이다. 직원의 깨끗한 글씨로 학습하고, 학생의 어려운 글씨로 시험한다. 오류가 높아도 방법이 나빠서인지 시험이 어려워서인지 알 수 없다. 오른쪽은 작가가 겹치지 않게 두 출처를 양쪽에 섞은 것이다. MNIST 실험이 보고하는 숫자는 오른쪽 분할이다.

NIST Special Database 3과 1의 이진 필기 숫자를 다시 나누었다. 원래 지정은 SD-3으로 학습하고 SD-1로 시험하는 것이었다. SD-3은 인구조사국 직원의 글씨라 비교적 깨끗하고, SD-1은 고등학생의 글씨라 더 어렵다. 학습은 쉽고 시험은 어렵게 고정되어 있어서, 그 오류가 높다고 방법이 나쁘다고 말할 수 없다. 학습과 시험에 글씨를 뽑는 방식이, 전체 글씨에서 뽑는 방식과 같아야 한다.

SD-1은 작가 500명의 영상 58,527장이다. 작가별 블록이 섞여 있어 작가 정보로 다시 풀었다. 앞 250명의 글자는 새 학습 집합으로, 나머지 250명은 시험 쪽으로 넣었다. 각각 약 30,000장이다. 작가가 겹치지 않으므로, 시험의 필체를 학습에서 본 것으로 칠 수 없다. 새 학습 집합은 SD-3의 앞부분으로 채워 60,000장으로 맞췄다. 새 시험 집합도 SD-3으로 채워 60,000장으로 맞출 수 있게 두었고, 실험에서는 그중 10,000장만 썼다. SD-1에서 5,000장, SD-3에서 5,000장이다. 학습은 60,000장 전부다. 시험이 한쪽 출처로만 기울지 않게 반씩 섞은 것이다.

원본은 종횡비를 유지한 채 20×20 상자 안에 들어가도록 크기를 맞췄다. 보간 때문에 회색 단계가 생긴다. 정규 데이터베이스는 픽셀의 질량 중심을 계산해, 그 점이 28×28의 한가운데에 오도록 옮긴 것이다. 필요하면 배경을 채워 32×32까지 늘린다. [LeNet-5](./lenet-5.md)의 입력이 이 32×32다. 중심을 맞추는 이유는, 글자가 칸의 구석에 붙어 있으면 위치 차이만으로 다른 입력이 되기 때문이다.

기울기 보정본은 전경을 1, 배경을 0으로 두고 이차 관성 모멘트를 계산한 다음, 주축이 수직이 되도록 줄을 수평으로 민 뒤 20×20으로 자른 것이다. 초기 실험에는 16×16으로 줄인 버전도 있었다. 논문의 오류를 읽을 때 정규본인지 기울기 보정본인지가 다르면, 그 숫자로 방법을 비교하면 안 된다. 데이터 처리가 이미 다르다.

## 같은 시험에서의 오류

아래는 정규 시험 10,000장에서의 오류다. 기울기 보정이나 변형 학습은 괄호에 적었다. 시험 오류의 불확실성은 약 0.1%로 적혀 있다. 0.1%p 차이는 방법으로 단정할 범위가 아니다.

| 방법 | 시험 오류 |
| --- | --- |
| 선형 분류기 | 12% (기울기 보정 8.4%) |
| 클래스 쌍 45개 | 7.6% |
| 유클리드 K-최근접 이웃 | 5.0% (기울기 보정, \(k=3\)이면 2.4%) |
| 은닉 300, 완전 연결 | 4.7% (1,000개면 4.5%. 기울기 보정과 300개면 1.6%) |
| 가우스 RBF 1,000개 | 3.6% |
| 주성분 40개 + 2차 다항식 | 3.3% |
| 은닉 300-100 | 3.05% (1,000-150이면 2.95%) |
| LeNet-1 | 1.7% |
| LeNet-4 | 1.1% |
| 접선 거리 | 1.1% (16×16) |
| 정규 SVM | 1.4%, 다른 구현 1.1% |
| 축소 집합 SVM | 1.1% |
| LeNet-5 | 0.95% (변형 학습 0.8%) |
| 부스팅 LeNet-4 | 0.7% |

K-최근접 이웃은 학습 시간이 거의 없다. 대신 인식할 때 20×20 영상 60,000장을 들고 있어야 한다. 픽셀당 1바이트면 약 24메가바이트다. 저장해 둔 그림 중에서 가장 가까운 것을 찾는 방법이라, 학습이라고 부를 파라미터 갱신이 없다. LeNet-5를 200MHz R10000 하나에서 학습하면 CPU로 2일에서 3일이 걸렸지만, 인식 때의 곱셈 횟수와 메모리는 최근접 이웃보다 작다. 오류만 놓고 방법을 고르면 이 비용 차이가 빠진다.

LeNet-5가 틀린 시험 예로 논문이 보인 것은 82장이다. 82장은 0.82%라서 0.95%(95장)가 아니라 변형 학습으로 얻은 0.8% 쪽의 오분류다. 일부는 사람도 애매하고, 일부는 읽을 수 있는데 학습 집합에 적게 나온 필체다. 데이터가 더 있으면 더 내려갈 여지가 있다는 뜻으로 적혀 있다.

## 데이터 구성을 숫자로 보기

한 장은 28×28 = 784칸이고 칸마다 0에서 255까지 8비트 회색 단계 하나다. 학습 60,000장은 \(60{,}000 \times 784 = 47{,}040{,}000\)바이트, 시험 10,000장은 7,840,000바이트다. 앞에서 최근접 이웃이 24메가바이트라고 한 것은 20×20으로 줄인 영상 60,000장이기 때문이다. \(60{,}000 \times 400 = 24{,}000{,}000\)이다.

| | 학습 | 시험 |
| --- | --- | --- |
| 장수 | 60,000 | 10,000 |
| 출처 | 직원(SD-3)과 고등학생(SD-1) | 같다. 5,000장씩 |
| 작가 | SD-1은 앞 250명 | SD-1은 나머지 250명 |
| 클래스 | 0~9 열 가지 | 같다 |

클래스별 장수는 고르지 않다. 시험에서 가장 많은 숫자는 1이고, 항상 1이라고 찍으면 시험 오류가 88.65%다. 열 개를 무작위로 찍는 기준선(90%)과 비슷한 이 값이 모든 방법의 바닥이다. 12%인 선형 분류기도 이 바닥보다 훨씬 낫다.

```python
import math

train = [5923, 6742, 5958, 6131, 5842, 5421, 5918, 6265, 5851, 5949]
test = [980, 1135, 1032, 1010, 982, 892, 958, 1028, 974, 1009]
print("장수", sum(train), sum(test))
print("가장 많은 클래스만 찍으면 시험 오류", round(100 * (1 - max(test) / sum(test)), 2), "%")
print("한 장", 28 * 28, "바이트 / 학습", 60000 * 784, "/ 시험", 10000 * 784)
print("20x20 최근접 이웃 저장", 60000 * 20 * 20, "바이트")
for err in [12.0, 3.6, 1.1, 0.95, 0.82]:
    p = err / 100
    se = math.sqrt(p * (1 - p) / 10000)
    print(f"{err:5.2f}% = {round(p * 10000):4d}장 틀림, 표준오차 {100*se:.2f}%p, "
          f"95% 구간 {err - 196*se:.2f} ~ {err + 196*se:.2f}")
se_d = math.sqrt(sum(math.sqrt(p * (1 - p) / 10000) ** 2 for p in (0.011, 0.0095)))
print("LeNet-4 1.1% 대 LeNet-5 0.95%: 차이", 0.15, "%p, 표준오차", round(100 * se_d, 2), "%p")
```

```text
장수 60000 10000
가장 많은 클래스만 찍으면 시험 오류 88.65 %
한 장 784 바이트 / 학습 47040000 / 시험 7840000
20x20 최근접 이웃 저장 24000000 바이트
12.00% = 1200장 틀림, 표준오차 0.32%p, 95% 구간 11.36 ~ 12.64
 3.60% =  360장 틀림, 표준오차 0.19%p, 95% 구간 3.23 ~ 3.97
 1.10% =  110장 틀림, 표준오차 0.10%p, 95% 구간 0.90 ~ 1.30
 0.95% =   95장 틀림, 표준오차 0.10%p, 95% 구간 0.76 ~ 1.14
 0.82% =   82장 틀림, 표준오차 0.09%p, 95% 구간 0.64 ~ 1.00
LeNet-4 1.1% 대 LeNet-5 0.95%: 차이 0.15 %p, 표준오차 0.14 %p
```

코드의 첫 줄은 클래스별 장수의 합이 60,000과 10,000인지 확인한다. 오류율을 틀린 장수로 바꾸면 0.95%가 95장, 0.82%가 82장이다.

## 평가 관행

시험 오류는 시험 10,000장에서 센 비율이라 표본 변동이 있다. 틀릴 확률이 \(p\)인 방법을 \(n\)장에 시험하면 오류율의 표준오차는 \(\sqrt{p(1-p)/n}\)다. \(n = 10{,}000\)이고 \(p = 1\%\)이면 \(\sqrt{0.01 \cdot 0.99 / 10000} \approx 0.1\%\)p다. 위 표에서 0.95%의 95% 구간은 대략 0.76%에서 1.14%이고, 1.1%의 구간 0.90%에서 1.30%와 크게 겹친다. 두 오류가 독립이라고 근사하면 차이 0.15%p의 표준오차가 0.14%p라서, LeNet-4의 1.1%와 LeNet-5의 0.95%의 차이만으로 방법의 우열을 말하기 어렵다. 같은 시험 장에서 두 방법이 틀린 목록이 있으면 이 비교는 더 좁게 할 수 있지만, 표에는 그 목록이 없다.

시험 집합을 설정 고르기에 쓰면 오류가 낮게 나온다. 실력이 똑같은 설정 20개를 시험 10,000장에 돌려 가장 낮은 것을 고르는 모의 실험이다. 설정마다 진짜 오류율은 1.0%다.

```python
import random

random.seed(0)
def err_rate(p, n=10000):              # 진짜 오류율 p인 분류기를 n장에 시험한다
    return sum(random.random() < p for _ in range(n)) / n

p_true, k = 0.01, 20                   # 실력이 똑같은 설정 20개
scores = [err_rate(p_true) for _ in range(k)]
best = min(scores)
print("시험 오류 20개 중 최소:", f"{100*best:.2f}%", " 최대:", f"{100*max(scores):.2f}%")
print("고른 설정을 새 시험 10,000장에 다시:", f"{100*err_rate(p_true):.2f}%")
```

```text
시험 오류 20개 중 최소: 0.86%  최대: 1.15%
고른 설정을 새 시험 10,000장에 다시: 1.03%
```

20개가 모두 같은 실력인데 시험 오류는 0.86%에서 1.15%까지 퍼지고, 최소를 고르면 0.86%라는 낙관적인 값이 나온다. 새 시험에서는 1.03%로 진짜 값 근처로 돌아온다. 그래서 설정은 학습 집합에서 떼어 낸 검증 집합으로 고르고, 시험 오류는 고른 뒤 한 번만 보고한다. 학습 60,000장 가운데 일부를 검증용으로 떼는 것이 흔한 관행이고, 자세한 분할 방법은 [데이터 분할](./data-split.md)에 있다. 논문 안의 표는 이 절차를 지켰는지에 따라 같은 시험 오류도 다른 뜻이 된다.

보고할 때는 어떤 전처리와 어떤 학습 집합을 썼는지도 함께 적어야 한다. 이 페이지의 표처럼 같은 방법이 기울기 보정본에서 8.4%, 정규본에서 12%가 나오기도 한다. 변형으로 학습 집합을 늘린 결과를 변형 없는 결과와 섞어 비교하면 데이터 양의 차이가 방법의 차이로 읽힌다.

지금은 너무 작다. 여기서 오류가 낮다고 시각 모델이나 언어 모델이 잘한다고 말할 수는 없다. 논문에 MNIST 숫자가 나오면, 학습 60,000장과 시험 10,000장인지, 정규본인지부터 확인하면 된다. 방법별 설명은 [부스팅](./boosting.md)과 [서포트 벡터 머신](./svm.md)에 나누어 두었다.

## 자주 헷갈리는 점

MNIST가 학습 60,000장과 시험 10,000장을 임의로 나눈 것이라고 생각하기 쉽지만, 작가 기준으로 나눈 것이다. SD-1의 작가 500명을 앞 250명과 뒤 250명으로 가르고, 시험 필체를 학습에서 보지 않게 했다. 임의로 장을 섞어 나눴다면 같은 작가의 글씨가 양쪽에 들어가 오류가 낮게 나온다.

글자 크기가 28×28이니 LeNet-5의 입력도 28×28이라고 생각하기 쉽지만, 입력은 32×32다. 글자는 20×20 상자에 맞춰졌고 28×28 안의 가운데에 있으며, 32×32는 여백을 더 둔 것이다.

시험 오류가 낮은 방법이 더 좋은 방법이라고 생각하기 쉽지만, 0.1%p 차이는 시험 표본 변동 안에 있다. 인식 때의 메모리나 학습 시간 같은 비용도 방법 선택에 들어간다. 최근접 이웃은 24메가바이트를 들고 있어야 한다.

시험 오류가 낮으면 시각 문제를 풀었다고 생각하기 쉽지만, MNIST는 글자가 가운데 정렬되어 있고 열 클래스뿐이다. 논문 숫자로 모델의 일반 성능을 말하려면 더 어려운 데이터에서도 보아야 한다.

## 직접 풀어 보기

1. 시험 오류 2.4%는 10,000장 중 몇 장을 틀린 것이고, 표준오차는 약 얼마인가? 오류 5.0%와 2.4% 사이의 차이는 시험 표본 변동으로 설명되는가?
2. MNIST 학습 집합 전체를 28×28 8비트 영상으로 저장하는 데 몇 바이트가 필요한가? 20×20으로 줄이면?
3. 항상 숫자 1만 답하는 분류기의 시험 오류는? 시험의 1이 1,135장이라고 할 때 계산하라.

<details>
<summary>정답</summary>

1. 240장이다. 표준오차는 \(\sqrt{0.024 \cdot 0.976 / 10000} \approx 0.15\%\)p다. 5.0%의 표준오차는 약 0.22%p이고 둘의 차이는 2.6%p이므로, 표본 변동으로 설명되지 않는다.
2. \(60{,}000 \times 784 = 47{,}040{,}000\)바이트(약 47메가바이트)다. 20×20이면 \(60{,}000 \times 400 = 24{,}000{,}000\)바이트다.
3. 맞히는 장이 1,135장이므로 오류는 \(1 - 1135/10000 = 88.65\%\)다.

## 정리

MNIST는 학습 60,000장과 시험 10,000장에 작가가 겹치지 않도록 NIST의 두 출처를 섞은 비교용 집합이다. 글자는 20×20 상자에 맞춰 28×28 가운데에 놓고, LeNet-5는 32×32 입력으로 쓴다. 시험 오류는 표준오차가 약 0.1%p라서 작은 차이로 우열을 가리지 않고, 시험 집합은 설정을 고른 뒤 한 번만 쓴다. LeNet-5의 0.95%는 95장, 변형 학습의 0.8%는 오분류 82장이다. 이 집합에서 겨룬 방법들 가운데 [부스팅](./boosting.md)과 [서포트 벡터 머신](./svm.md)은 각 페이지에서 이어진다.
