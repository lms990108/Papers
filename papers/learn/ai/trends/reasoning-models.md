추론 모델은 최종 답을 내기 전에 긴 생각 token(reasoning token, thinking token)을 먼저 만들도록 학습한 LLM입니다. 생각을 길게 할수록 어려운 문제의 정확도가 오르는 성질을 이용해, 모델을 키우는 대신 답할 때 쓰는 계산량(test-time compute)으로 성능을 삽니다. 2026년 11월 기준 정리이고, 모델 이름은 예시입니다.

단계별로 풀게 하는 chain-of-thought prompting(2022)이 먼저 나왔고, 2024년 9월 OpenAI o1이 이를 강화학습으로 모델 안에 넣었습니다. 2025년 1월 DeepSeek-R1은 정답을 검산할 수 있는 보상을 주는 강화학습(GRPO)만으로도 긴 추론이 생긴다는 것을 논문으로 공개했습니다. 이후에는 Claude 3.7 Sonnet(2025년 2월)처럼 한 모델이 일반 응답과 긴 생각을 모두 하고, 생각의 길이를 effort나 budget으로 조절하는 hybrid reasoning이 흔해졌습니다.

에이전트를 만들 때는 이런 곳에서 만납니다.

- **모델 선택과 설정**: 같은 모델에서도 생각을 켜고 끄거나, 생각 길이의 상한을 정하는 설정이 있습니다.
- **비용과 지연**: 보이지 않는 생각 token도 출력 token으로 과금되고 시간을 씁니다. → [Prefill, decode](../nlp/prefill-decode.md)
- **도구 호출 루프**: 도구 결과를 받은 뒤 다시 생각하게 할지 정합니다.
- **eval 비용**: 점수가 같아도 쓴 token이 열 배 다를 수 있습니다. → [Evaluation](../deep-learning/evaluation.md)

## 계산

최종 답이 200 token인데 생각이 4,000 token이면 출력은 4,200 token입니다. 일반 모델은 200 token만 쓰므로 \(4200 / 200 = 21\)배입니다. 가정을 두고 따라가 봅니다. 출력 단가는 100만 token에 10달러(실제 가격이 아니라 계산용 가정), TPOT는 25ms, TTFT는 0.8초입니다.

```text
              출력 token   비용(달러)   응답 시간
일반 모델         200       0.002       0.8 + 200 x 0.025   =   5.8초
추론 모델       4,200       0.042       0.8 + 4,200 x 0.025 = 105.8초
```

비용은 token 수와 같이 21배입니다. 시간은 TTFT가 고정이라 \(105.8 / 5.8 \approx 18\)배입니다. decode는 token을 하나씩 만들기 때문에 지연이 생각 길이에 비례해 늘어납니다. 스트리밍으로 생각을 숨기고 답만 보여 주어도 총 시간은 줄지 않고 사용자는 그 시간 동안 답을 기다립니다.

답을 여러 번 뽑아 다수결로 정하는 self-consistency는 생각을 늘리는 다른 방법입니다. 한 번에 맞힐 확률이 \(p = 0.6\)이고 시도가 서로 독립이라면, 세 번 중 두 번 이상 맞을 확률이 다수결의 정확도입니다.

\[
3 \times 0.6^2 \times 0.4 + 0.6^3 = 0.432 + 0.216 = 0.648
\]

정확도는 0.6에서 0.648이 되고 생성한 token은 세 배입니다. 시도가 독립이 아니고 같은 실수를 되풀이하면 이득이 줄어듭니다. 세 번이 항상 같은 답이면 정확도는 0.6 그대로입니다.

## 기억할 것 네 가지

### 생각은 보상으로 길러지고, 그 값은 token으로 치릅니다

추론 모델 학습의 큰 줄기는 RLVR입니다. 수학은 정답을 비교하고 코드는 테스트를 통과했는지 보는 식으로, 검산할 수 있는 보상을 줍니다. 같은 질문에 답을 여러 개 뽑아 보상이 높은 쪽으로 기울이는 GRPO가 이 학습에 쓰였다고 알려져 있습니다. → [Post-training](../nlp/post-training.md) 보상이 정해지니 모델은 정답에 닿는 데 도움이 되는 긴 풀이를 스스로 만들게 됩니다. 그 풀이가 reasoning token이고, 출력 token과 같은 단가로 과금됩니다.

### 어려운 다단계 문제에 쓰고, 단순한 일에는 쓰지 않습니다

다단계 수학, 코드 수정, 계획 수립, 조건이 얽힌 판단처럼 중간 결과를 쌓아야 풀리는 일은 이득이 큽니다. 추출, 분류, 짧은 질의응답은 생각이 길어도 답이 거의 바뀌지 않아 비용과 시간만 늡니다. 지연에 민감한 화면에서는 생각 길이의 상한을 두거나 일반 모드로 돌립니다. 설정 방식은 모델마다 다르고 일부 모델은 budget 대신 effort 수준으로 조절합니다. 둘 다 우선 낮게 두고 올려 가며 점수를 비교하는 것이 안전합니다.

### 도구를 부르는 에이전트에서는 생각이 도구 결과 사이에 들어갑니다

interleaved thinking은 도구 결과를 받을 때마다 다시 생각하고 다음 행동을 정하게 하는 방식입니다. 첫 요청에서만 생각하고 이후는 기계적으로 도구를 부르는 것보다, 결과가 예상과 다를 때 계획을 고치기 쉽습니다. 대신 단계마다 생각 token이 붙어 루프 전체 비용이 커집니다. 지원 여부와 설정 방법은 모델과 API 버전마다 다르니 문서를 확인합니다.

### 생각 token을 그대로 믿거나 보여 주지 않습니다

생각이 모델의 실제 계산 과정을 충실히 반영하지 않을 수 있다는 연구가 있습니다. Anthropic은 prompt에 넣은 힌트를 모델이 답에 썼는데도 생각에서는 그 사실을 거의 언급하지 않는 경우가 많다고 보고했습니다. 그래서 생각을 감사 기록이나 안전 장치의 유일한 근거로 쓰지 않습니다. 사용자에게 그대로 보여 줄 때도 틀린 풀이나 중간의 헛걸음이 섞여 있다는 전제로 다룹니다. 평가는 생각이 아니라 최종 답과 도구 호출 결과로 합니다.

<summary>더 깊이: 다수결 일반식, 평가에서의 token, 생각 길이와 정확도</summary>

- \(n\)번 시도에서 \(k\)번 이상 맞을 확률은 \(\sum_{i \ge k} \binom{n}{i} p^i (1-p)^{n-i}\)입니다. 다수결은 \(k\)가 과반인 경우입니다. \(p = 0.6\)이면 다섯 번 다수결이 \(10 \times 0.6^3 \times 0.4^2 + 5 \times 0.6^4 \times 0.4 + 0.6^5 = 0.3456 + 0.2592 + 0.07776 \approx 0.683\)입니다. 시도를 두 번 더 늘려 token이 5/3배가 되고 정확도는 0.035 오릅니다. 시도를 늘릴수록 오름폭이 줄어듭니다.
- 다수결은 정답을 몰라도 쓸 수 있고, [pass@k](../deep-learning/evaluation.md)는 맞는지 확인하는 장치가 있어야 합니다. 같은 "여러 번 뽑기"여도 서로 다른 일입니다.
- 추론 모델을 평가할 때는 점수와 함께 문제당 평균 출력 token과 총 비용, 지연을 같이 적습니다. 점수 차이가 작은데 token이 크게 다르면 비용 대비 이득을 따져야 합니다. 생각 길이를 바꾸면 점수도 바뀌므로 비교할 때 설정을 맞춥니다.
- 생각이 길수록 늘 정확해지는 것은 아닙니다. 쉬운 문제에서 생각이 불필요하게 길어지는 현상(overthinking)이 알려져 있어 생각 길이의 상한이 필요합니다.
- 서빙 쪽에서는 생각이 긴 요청이 KV cache를 오래 점유해 동시에 처리할 수 있는 요청 수를 줄입니다. → [Continuous batching](../deep-learning/serving.md)

</details>
