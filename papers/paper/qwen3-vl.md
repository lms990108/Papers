Qwen Team (Shuai Bai 외). *arXiv*, 2025. [원문 PDF](https://arxiv.org/pdf/2511.21631)

## 세 줄 요약

1. 텍스트, 이미지, 영상을 함께 읽는 Qwen 시리즈의 최신 VLM이다. dense 2B/4B/8B/32B와 MoE 30B-A3B, 235B-A22B가 있다.
2. 텍스트와 이미지, 영상이 섞인 입력을 token 256K까지 한 번에 읽는다.
3. 위치 표현, 시각 정보를 LLM에 넣는 방식, 영상 시간 표시 세 가지를 바꿔서 Qwen2.5-VL보다 긴 문맥과 영상을 더 잘 다룬다.

## 내용

### 구조

앞선 Qwen2.5-VL과 같은 세 조각이다. 비전 인코더가 이미지와 영상 frame을 token으로 바꾸고, MLP 연결부가 이를 LLM(Qwen3)이 읽는 형태로 맞춰 넘긴다. → [멀티모달](../learn/ai/deep-learning/multimodal.md)

- **비전 인코더**: SigLIP-2를 이어서 학습한 것이다. 입력 해상도에 맞춰 token 수가 달라지는 동적 해상도를 쓰고, 기본은 SigLIP2-SO-400M이며 2B, 4B 모델은 300M짜리 Large를 쓴다.
- **연결부**: 2층 MLP가 이웃한 2×2 시각 특징을 token 하나로 합친다. token 수를 4분의 1로 줄이는 셈이다.
- **LLM**: 총 6종이다. 플래그십 235B-A22B는 전체 235B 중 token 하나에 22B를 쓴다.

여기서 세 가지가 달라졌다.

### 변경 1: Interleaved MRoPE

위치 정보를 시간(t), 높이(h), 너비(w) 세 축으로 나눠 표현한다. 앞 버전은 임베딩 칸을 t용, h용, w용으로 덩어리째 나눴는데, 그러면 축마다 쓰는 주파수 대역이 한쪽으로 치우쳐서 긴 영상에서 성능이 떨어졌다. Qwen3-VL은 세 축을 칸마다 번갈아 섞어서, 각 축이 낮은 주파수와 높은 주파수를 모두 갖게 한다.

### 변경 2: DeepStack

보통은 비전 인코더의 마지막 층 결과만 LLM 입력으로 넣는다. DeepStack은 비전 인코더의 서로 다른 세 층에서 특징을 꺼내 각각 연결부를 거친 뒤, LLM의 앞쪽 세 층의 hidden state에 더해 준다. 입력 token 수는 늘지 않는다. 깊은 층은 의미를, 얕은 층은 질감과 글자 모양 같은 세부를 담고 있어서, 세부가 중요한 문서와 OCR에 도움이 된다.

### 변경 3: 텍스트 timestamp

영상 frame 묶음마다 `<3.0 seconds>` 같은 시간 문자열을 앞에 붙인다. 초 단위와 시:분:초 두 형식을 섞어 학습한다. 앞 버전은 절대 시간을 위치 인코딩에 넣었는데, 긴 영상에서는 시간 번호가 아주 크고 듬성듬성해졌고 frame을 일정 간격으로 뽑아야 해서 학습 데이터를 만들기가 비쌌다. 문자열 방식은 context 길이가 조금 늘어나는 대가를 치르지만, 모델이 시간을 글자로 읽게 한다.

### 사전학습 4단계

```text
단계                 학습 대상     token 수      입력 길이
S0  정렬             연결부만       67B           8,192
S1  전체 멀티모달    전체          약 1T          8,192
S2  긴 문맥          전체          약 1T          32,768
S3  아주 긴 문맥     전체          100B           262,144
```

S0은 이미지-캡션, 지식, OCR 데이터로 시각 token과 LLM을 맞춘다. S1은 이미지-텍스트가 섞인 문서, 위치 지정(grounding), 질의응답, STEM, 약간의 영상에 텍스트 데이터를 섞고, S2에서는 텍스트 비중을 높이고 영상과 에이전트형 지시 데이터를 늘린다. S3은 긴 영상과 긴 문서를 중심으로 한다. 손실은 샘플 단위 평균이 아니라 token별 제곱근 정규화로 바꿔서 텍스트와 멀티모달 데이터 사이 균형을 맞췄다.

### 데이터 종류

- **OCR**: 사내 데이터 3,000만 개에 합성한 다국어 3,000만 개를 더했고, 지원 언어를 10개에서 39개(29개 추가)로 늘렸다.
- **문서 파싱**: Common Crawl PDF 300만 건(10개 유형, 유형별 30만)과 사내 문서 400만 건. 출력 형식은 HTML 기반과 Markdown 기반 두 가지다.
- **STEM**: 점 위치 지정 100만, 인식 VQA 200만, 도표 캡션 600만, K-12와 대학 수준 문제 6,000만 개 이상, 긴 사고 과정(CoT) 멀티모달 1,200만 개 이상.
- **그 밖의**: 위치 지정과 개수 세기(좌표를 0~1000으로 정규화), 3D 박스, 코드(UI에서 HTML 생성, SVG, 순서도), 영상 캡션과 시공간 위치 지정, 에이전트(GUI 조작 기록, 함수 호출, 이미지·텍스트 검색 기록).

### 후처리

SFT, 강한 모델에서 약한 모델로 증류, 강화학습의 세 단계다. → [post-training](../learn/ai/nlp/post-training.md)

- **SFT**: 약 120만 샘플(3분의 1이 텍스트, 3분의 2가 이미지·영상 텍스트). 32K 길이로 1 에폭, 이어서 256K 길이로 1 에폭. 생각하는 모델(thinking)과 안 하는 모델(instruct)의 데이터 형식이 다르다.
- **증류**: 먼저 교사 모델의 출력을 그대로 따라 학습하고, 다음에 학생이 직접 낸 출력에서 교사와의 로짓 차이(KL)를 줄인다.
- **추론 RL**: 질의 약 3만 개에 질의당 16개 샘플, 통과율이 90%를 넘는 질의는 제거. 보상은 규칙이나 코드 실행으로 검증한다.
- **일반 RL**: 규칙 기반과 모델 기반 보상을 섞는다. 지시 따르기, 선호 정렬, 개수 세기, 시계 읽기, 언어 섞임 방지 같은 항목이다.
- **이미지로 사고하기**: 이미지를 자르고 확대하는 도구를 호출하며 추론하게 하는 학습도 한다.

### 결과

텍스트 평가에서 플래그십 VL 모델이 같은 규모의 텍스트 전용 LLM에 뒤지지 않는다는 점이 눈에 띈다.

| 평가 (instruct) | Qwen3-VL 235B | Qwen3 235B 텍스트 | DeepSeek V3 | Claude Opus 4 |
| --- | --- | --- | --- | --- |
| MMLU-Pro | 81.8 | 83.0 | 81.2 | 86.6 |
| AIME-25 | 74.7 | 70.3 | 46.6 | 33.9 |
| HMMT-25 | 57.4 | 55.4 | 27.5 | 15.9 |
| LiveCodeBench v6 | 54.3 | 51.8 | 45.2 | 44.6 |

멀티모달 쪽은 본문에 나온 몇 가지 수치다. MMStar 78.7(thinking), MuirBench 80.1, 고해상도 V* 93.7(도구 사용), 문서 MMLongBench-Doc 57.0, 환각 평가 HallusionBench에서 Gemini-2.5-Pro보다 3.0점 높다. 영상 needle-in-a-haystack(긴 영상 속 한 장면 찾기)은 30분 길이(256K token)까지 100%, YaRN으로 약 100만 token(약 2시간)까지 확장해도 99.5%다. GUI 에이전트 벤치마크는 32B 모델이 OSWorld 41, AndroidWorld 63.7이다.

### 절제 실험

- **비전 인코더**: SigLIP-2 그대로보다 이 논문의 인코더(Qwen3-ViT)가 1.7B LLM 설정에서 RealWorldQA 58.7에서 66.1로, OCRBench 77.2에서 78.7로 올랐다. 일부 ImageNet 변형 평가는 약간 떨어졌다.
- **DeepStack**: 내부 15B-A2B LLM, 200B token 설정에서 평균이 74.7에서 76.0으로 올랐다. DocVQA 89.5에서 91.1, InfoVQA 71.9에서 74.2.

## 기억할 것

### 모델 이름의 A는 활성 파라미터입니다

`235B-A22B`는 전체 235B 중 token 하나를 처리할 때 22B만 쓰는 MoE라는 뜻이다. 계산량은 22B급이지만 가중치는 235B를 모두 메모리에 올려야 한다. GPU 메모리는 앞의 수, 속도는 뒤의 수를 본다. → [서빙](../learn/ai/deep-learning/serving.md)

### 256K는 입력 한도이지 활용 보장이 아닙니다

긴 문맥을 학습했어도 문맥 중간의 정보를 덜 쓰는 경향은 남아 있을 수 있다. 영상은 frame이 많을수록 token을 크게 쓰고, 논문도 영상 token을 224K, frame을 2,048장으로 제한해서 평가한다. 긴 영상은 필요한 구간만 자를 수 있는지 먼저 본다. → [어텐션](../learn/ai/nlp/attention.md)

### 생성 설정이 모델마다 다릅니다

논문이 권장하는 샘플링 설정이 크기와 모드에 따라 다르다. 큰 모델의 instruct는 temperature 0.7, top-p 0.8, top-k 20, presence penalty 1.5이고, 8B 이하는 1.0, 1.0, 40, 2.0이다. thinking 모드는 MoE에서 0.6, 0.95, 20이다. 쓰는 모델의 권장값을 그대로 가져와야 평가 수치와 비슷한 결과가 나온다.

### 기술 보고서는 자기 보고입니다

수치는 모두 저자들이 직접 잰 값이고 경쟁 모델과 같은 조건이라는 보장이 없다. 논문도 영상 비교에서 frame 수가 모델마다 다르다는 것(Gemini 512, GPT-5 256, Claude 100)을 적고 완전한 공정성은 보장할 수 없다고 말한다. 또한 이 논문에는 독립된 한계 절이 없다.

- 학습은 Megatron-LM에서 텐서, 파이프라인, 컨텍스트, 전문가 병렬과 ZeRO-1을 함께 쓰고, 최대 약 10,000개 GPU를 썼다. 추론은 vLLM이나 SGLang으로 한다.

- 영상 평가는 초당 2 frame(Charades-STA는 4 frame), 최대 2,048 frame과 영상 token 224K로 제한한다.

## 리뷰

오픈 모델 중 가장 최근의 대표적인 VLM 기술 보고서다. 새 알고리즘 하나를 증명하는 논문이 아니라 구조, 데이터, 학습 단계, 후처리를 어떻게 쌓았는지의 기록이다. 에이전트 개발에서는 256K 문맥에서 이미지와 영상을 한꺼번에 넣을 수 있다는 점, GUI 조작과 도구 호출 데이터를 학습에 넣었다는 점, 문서와 OCR 쪽 데이터를 크게 늘렸다는 점이 눈에 띈다.
