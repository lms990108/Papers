## 세 줄 요약

1. 임베딩 벡터를 앞에서부터 잘라 써도 쓸 만하게 학습하는 방법이다. 큰 벡터 안에 작은 벡터가 들어 있어 마트료시카라고 부른다.
2. 앞 8, 16, ..., 2048칸처럼 여러 길이마다 손실을 구해 더해서 학습한다. 모델을 다시 학습하지 않고 벡터만 자르면 된다.
3. 같은 정확도에서 임베딩 크기를 최대 14배 줄이고, 검색은 실제 속도로 최대 14배 빨라진다.

## 내용

### 풀려던 문제

임베딩 모델은 벡터 길이를 정해 놓고 학습한다. 그런데 쓰는 곳마다 사정이 다르다. 저장 공간이 부족하거나 검색을 빠르게 해야 하면 더 짧은 벡터가 필요한데, 그러려면 처음부터 그 길이로 다시 학습해야 하고 길이마다 모델을 따로 만들어야 한다. → [임베딩](../learn/ai/nlp/embedding.md)

### 학습 방식

학습할 때 벡터의 앞 m칸만 떼어 낸 것으로도 분류 손실을 구하고, 여러 m 값의 손실을 모두 더한다. ResNet50(2048칸)에서는 m을 8, 16, ..., 1024, 2048로 두고 손실마다 가중치는 모두 1이다. 앞쪽 칸일수록 더 많은 손실에 관여하므로 중요한 정보가 앞쪽에 모인다.

길이별 분류기를 따로 두지 않고 한 분류기의 앞부분을 나눠 쓰는 변형(MRL-E)은 분류기 메모리를 절반쯤 줄인다. 추론 때 추가 비용은 없다.

### 작은 예

8칸 벡터 둘을 앞 4칸만 잘라서 비교한다. 앞쪽에 정보가 몰려 있다고 가정한 예다.

```text
a = [3, 2, 1, 0.5, 0.2, 0.1, 0.1, 0.1]
b = [2, 3, 1, 0.4, 0.1, 0.2, 0.1, 0.0]

8칸 전체 코사인 유사도 = 0.9285
앞 4칸만 코사인 유사도  = 0.9293
```

뒤쪽 4칸의 값이 작아서 잘라도 유사도가 거의 같다. 마트료시카 학습은 실제 임베딩이 이런 모양이 되도록 만든다. 저장 공간으로는 문서 100만 개를 float32 2048칸으로 저장하면 약 8.2GB이고, 256칸으로 자르면 약 1.0GB다. → [코사인 유사도](../learn/ai/nlp/cosine-similarity.md)

### 결과

| ResNet50, ImageNet-1K 정확도 | 마트료시카 | 길이마다 따로 학습 |
| --- | --- | --- |
| 8칸 | 66.63% | 65.29% |
| 128칸 | 76.30% | 75.29% |
| 2048칸 | 76.80% | 76.87% |

짧을수록 이득이 크고 가장 긴 벡터에서는 거의 같다. 검색에서는 짧은 벡터로 후보를 먼저 고르고 긴 벡터로 다시 고르는 방식으로 계산량이 이론상 128배, 실제 속도로는 14배 줄었다. ResNet50 외에 ViT, ALIGN, BERT에서도 실험했다.

## 기억할 것

### 아무 임베딩이나 자르면 안 됩니다

마트료시카 방식으로 학습한 모델이어야 앞부분이 단독으로 의미를 가진다. 일반 임베딩의 벡터를 그냥 자르면 정보가 뒤쪽에 흩어져 있어서 성능이 크게 떨어질 수 있다. 모델이 이 방식을 지원하는지 먼저 확인한다.

### 자른 뒤에는 길이를 다시 맞춥니다

코사인 유사도나 내적으로 검색한다면, 자른 벡터의 길이(norm)는 더 이상 1이 아니다. 잘라서 저장하거나 질의하기 전에 정규화를 다시 한다. 그리고 저장할 때와 질의할 때 같은 길이를 써야 한다. → [벡터 인덱스](../learn/ai/rag/vector-index.md)

### 짧은 벡터로 거르고 긴 벡터로 고릅니다

후보를 줄이는 1차 검색은 짧은 벡터로, 최종 순위는 긴 벡터로 매기면 속도와 정확도를 같이 챙길 수 있다. 같은 모델이 만든 벡터 하나로 두 단계를 모두 처리하므로 모델을 두 개 둘 필요가 없다.

## 리뷰

벡터 길이를 줄여 받는 임베딩 API 옵션의 바탕이 되는 아이디어다. RAG에서 저장 공간과 검색 시간을 줄이고 싶을 때, 모델을 바꾸지 않고 짧은 벡터로 먼저 후보를 고르고 긴 벡터로 다시 고르는 식으로 쓸 수 있다. 이런 옵션은 해당 방식으로 학습한 모델에서만 의미가 있다.
