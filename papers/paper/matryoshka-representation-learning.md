## 요약

임베딩 벡터 하나를 앞에서부터 잘라 써도 쓸 만하게 학습하는 방법이다. 러시아 마트료시카 인형처럼 작은 벡터가 큰 벡터 안에 들어 있어서 이런 이름이 붙었다. → [임베딩](../learn/ai/nlp/embedding.md)

- **학습**: 벡터의 앞 8, 16, 32, ..., 2048칸처럼 여러 길이를 정해 두고, 길이마다 따로 손실을 계산해서 모두 더한다. 앞쪽 칸일수록 더 많은 손실에 관여하므로 중요한 정보가 앞쪽에 모인다.
- **사용**: 모델을 다시 학습하지 않고, 벡터의 앞부분만 잘라서 쓴다. 추론 비용이 늘지 않는다.
- **MRL-E**: 분류기 가중치를 길이별로 따로 두지 않고 하나를 나눠 쓰는 변형이다. 분류기 메모리가 절반쯤 줄어든다.

### 결과

| 실험 | 결과 |
| --- | --- |
| ImageNet-1K 분류 | 같은 정확도에서 임베딩 크기 최대 14배 작음 |
| 대규모 검색 | 실제 속도 최대 14배 빠름 |
| 롱테일 few-shot 분류 | 정확도 최대 2% 향상 |
| ResNet50, 8칸 | 정확도 66.63%, 통째로 학습한 모델은 65.29% |
| ResNet50, 2048칸 | 76.80%, 통째로 학습한 모델은 76.87% (거의 같음) |

ResNet50(이미지 분류) 외에 ViT, ALIGN, BERT에서도 실험했다.

## 리뷰

벡터 길이를 줄여 받는 임베딩 API 옵션의 바탕이 되는 아이디어다. RAG에서 저장 공간과 검색 시간을 줄이고 싶을 때, 모델을 바꾸지 않고 짧은 벡터로 먼저 후보를 고르고 긴 벡터로 다시 고르는 식으로 쓸 수 있다. 이런 옵션은 해당 방식으로 학습한 모델에서만 의미가 있다. 일반 임베딩 모델의 벡터를 그냥 자르면 성능이 크게 떨어질 수 있다.
