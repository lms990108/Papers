## 세 줄 요약

1. 이미지를 보고 대화하는 모델(LLaVA)을, 사전학습된 비전 인코더(CLIP)와 LLM(Vicuna)을 연결해서 만든다.
2. 이미지 설명을 GPT-4에게 주고 "이미지에 대한 대화"를 만들게 해서, 지시 따르기(instruction following) 데이터 158K개를 얻는다.
3. 두 단계로 학습한다. 먼저 연결부만 맞추고, 다음에 LLM까지 함께 미세조정한다.

## 내용

### 풀려던 문제

LLM은 지시를 따르도록 학습해서(instruction tuning) 대화 도구가 되었다. 하지만 이미지가 들어가는 지시 따르기 데이터는 거의 없었다. 이미지-캡션 쌍은 많아도 "이 그림에서 무엇이 위험해 보이나요?" 같은 질문과 긴 답은 사람이 쓰기에 너무 비싸다. 이 논문은 그 데이터를 GPT-4로 만든다.

### 이미지를 모르는 GPT-4에게 이미지를 설명하는 법

GPT-4와 ChatGPT는 텍스트 전용 모델이라 이미지를 직접 못 본다. 그래서 이미지를 두 가지 텍스트로 바꿔서 준다.

- **캡션**: COCO 이미지에 달린 설명 문장 다섯 개 정도.
- **물체 상자**: 물체 이름과 정규화된 좌표. 예를 들면 `person: [0.681, 0.242, 0.774, 0.694]` 같은 줄이다.

시스템 프롬프트는 "한 장의 이미지를 보고 있는 AI 비주얼 어시스턴트처럼 행동하라, 확실히 답할 수 있는 질문만 하라, 복잡한 질문에는 자세한 추론을 달라"는 취지이고, 사람이 손으로 쓴 예시를 몇 개씩 few-shot으로 끼워 넣는다. 이 소수의 예시가 유일한 사람의 주석이다. 이렇게 세 종류의 응답을 만들었다.

| 종류 | 개수 | 내용 |
| --- | --- | --- |
| 대화 | 58K | 물체 종류, 개수, 동작, 위치, 상대 위치를 묻는 여러 턴의 질문과 답 |
| 상세 설명 | 23K | "Describe the following image in detail" 같은 지시(변형 16종 중 하나) 한 개에 긴 설명 |
| 복잡한 추론 | 77K | 이미지 내용을 근거로 한 단계 더 생각해야 하는 질문과 추론 |
| 합계 | 158K | |

### 구조와 학습

CLIP ViT-L/14가 이미지를 patch별 벡터로 바꾸고, 학습 가능한 선형 변환 하나가 그 벡터를 LLM의 token 임베딩 공간으로 옮긴다. 변환된 이미지 token은 텍스트 token과 함께 Vicuna에 들어간다. 손실은 어시스턴트가 쓴 답 token에만 건다. → [멀티모달](../learn/ai/deep-learning/multimodal.md)

학습은 두 단계다.

```text
단계 1  특징 정렬     CC3M에서 고른 595K 이미지-캡션 쌍 (캡션을 "간단히 설명하라"의 답으로 변환)
                      비전 인코더 고정, LLM 고정, 선형 변환만 학습
                      1 epoch, 학습률 2e-3, 배치 128
단계 2  지시 미세조정  앞의 158K 지시 따르기 데이터
                      비전 인코더 고정, 선형 변환과 LLM을 학습
                      3 epoch, 학습률 2e-5, 배치 32
```

단계 1은 이미지 벡터가 LLM이 읽는 token과 같은 말을 하도록 연결부만 맞추는 일이다. A100 GPU 8개에서 단계 1이 약 4시간, 단계 2가 약 10시간이었다. 큰 모델을 처음부터 만든 것이 아니라 이미 있는 두 모델을 이어 붙이는 일이라서 이만큼 가볍다.

### 결과 1: 대화 품질 비교

저자들은 텍스트 전용 GPT-4가 정답 설명을 보고 낸 답을 기준으로, 모델의 답을 GPT-4가 점수 매겨 그 상대값을 낸다. COCO 이미지 30장, 질문 90개의 LLaVA-Bench(COCO)에서 데이터 종류를 빼 가며 비교했다.

| 학습 데이터 | 대화 | 상세 설명 | 복잡한 추론 | 전체 |
| --- | --- | --- | --- | --- |
| 지시 따르기 데이터 없음 | 22.0 | 24.0 | 18.5 | 21.5 |
| 대화만 | 76.5 | 59.8 | 84.9 | 73.8 |
| 상세 설명 + 복잡한 추론 | 81.5 | 73.3 | 90.8 | 81.9 |
| 전부(158K) | 83.1 | 75.3 | 96.5 | 85.1 |

지시 따르기 데이터가 없으면 21.5점이고, 상세 설명과 복잡한 추론을 소량(5%, 10%)만 더해도 전체 73.8에서 80.5로 오른다. 야외에서 찍은 사진으로 만든 LLaVA-Bench(In-the-Wild, 24장 60문항)에서는 LLaVA 67.3, BLIP-2 38.1, OpenFlamingo 19.1이었다.

### 결과 2: 과학 문제(ScienceQA)

이미지가 있는 과학 객관식(약 21K 문항)이다.

| 방법 | 정확도 |
| --- | --- |
| 사람 | 88.40 |
| GPT-4 (텍스트만, 2-shot) | 82.69 |
| MM-CoT Large (당시 최고) | 91.68 |
| LLaVA | 90.92 |
| LLaVA + GPT-4 보완 | 90.97 |
| LLaVA + GPT-4 심판 | 92.53 |

"보완"은 GPT-4가 답을 못 낼 때 LLaVA의 답을 쓰는 방식이고, "심판"은 둘의 답이 다를 때 GPT-4에게 두 답을 보여 주고 다시 고르게 하는 방식이다. 심판 방식이 당시 최고였다. 같은 실험의 절제: 마지막 층 대신 마지막 직전 층의 CLIP 특징을 쓰면 0.96 더 좋았고(마지막 층은 전체 추상 특징, 앞 층은 국소 세부), 이미지 사전학습 없이 처음부터 하면 5.11 낮았고, 7B 모델은 1.08 낮았다. 답 앞에 추론을 쓰게 하는 순서는 수렴이 빠르지만 최종 성능 기여는 작았다.

## 기억할 것

### 이미지는 token 수백 개를 차지합니다

ViT-L/14가 224×224 이미지를 14×14 patch로 자르면 16×16 = 256개가 나온다. 이미지 한 장이 context window에서 token 256개 정도를 쓴다는 뜻이다. 이미지가 여러 장이면 입력이 빠르게 불어나고, 해상도를 키우면 patch 수와 비용이 늘어난다.

### 합성 데이터의 한계가 그대로 들어옵니다

답을 만든 것이 GPT-4이고 입력이 캡션과 상자뿐이라서, 캡션에 없는 세부는 데이터에 없다. 논문이 보인 실패 사례가 이를 잘 보여 준다. 냉장고 안에 요거트와 딸기가 따로 있을 뿐인데 "딸기 맛 요거트가 있나요?"라는 질문에 "네"라고 답하는데, 논문은 이를 이미지를 "patch 묶음"처럼 받아들이기 때문이라고 설명한다. 부록에서도 환각, CLIP과 LLM에서 물려받은 편향, 평가의 복잡함을 한계로 꼽는다.

### 눈은 고정하고 입만 맞춥니다

비전 인코더는 두 단계 모두 학습하지 않는다. 그래서 인코더의 약점은 모델에도 남는다. CLIP이 세밀한 과제에 약하면 LLaVA도 약하다. 연결부가 선형 변환 하나라는 것도 의도된 단순함이고, 논문은 더 정교한 연결부를 앞으로의 과제로 둔다. → [CLIP](./clip.md)

### 평가자도 LLM입니다

LLaVA-Bench의 점수는 텍스트 전용 GPT-4가 매긴다. 심판의 판단이 얼마나 일관된지는 논문도 이후 과제로 남긴다. 같은 질문에 GPT-4를 세 번 물었더니 LLaVA-Bench(In-the-Wild) 점수가 67.3에서 66.7로 소폭 달라졌다. 평가에 LLM을 쓸 때 반복 측정으로 오차를 함께 보는 습관이 필요하다.

## 리뷰

연결부 하나와 합성 데이터만으로 멀티모달 LLM을 만들 수 있다는 것을 보여 준 레시피 논문이다. 비전 인코더, 연결부, LLM 세 조각을 이어 붙이는 구조는 이후 오픈 VLM의 기본형이 되었다. 학습 데이터를 강한 LLM으로 만든다는 방식은 지금 에이전트용 데이터 만들기에서도 그대로 쓰인다.
